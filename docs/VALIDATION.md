## 复审后的额外核验

第一轮复审未通过后追加的三项核验：

- **逐提交扫描**：对未推送区间的每个提交逐一扫描整棵树的私人标记（实例标识、控制身份、试学地址、课程活动标识、私有项目名、个人选择、实例累计用量），不只扫当前 HEAD；命中数为 0。
- **历史可达性**：含私人内容的旧提交已通过改写历史、删除 `refs/original`、清空 reflog 并回收对象使其不可达；标签按新提交重建，文档中的提交号同步更新。
- **内容存在性**：验收证据目录中的独有设计内容按[审查发现与修复机制汇总](design/evidence-findings.md)补入；[迁移摘要](design/migration-summary.md)中「设计信息已提取迁入」的结论已改为准确口径，提取类内容的完整覆盖未获证明。

## 同类排查后的额外核验（批次 J）

复审追问是否还有同类问题后追加的四项核验，方法与结果见[批次交接说明](design/migration-batches.md)第三节：

- **源侧逐行对照**：私有源文件 13,434 份逐行建索引，与公开侧比对「逐字相同且带个人语义」的候选，人工判定后确认的问题已全部抽象。
- **实例标识普查**：私有证据与运行产物 2,681 份中抽出 2,960 个标识符形态取值逐个回查，公开 Markdown 中已无实例运行标签与实例目录名。
- **用量数字普查**：带用量语境的五位以上数字逐行普查；剩余命中全部属于授权额度与暂停线、调用与门禁计数、发行物文件数、由账本推导的比例、上游公开统计与源码常量。
- **重复变体扫描**：归一化后相同、原文不同的段落对全库比对，命中 4 组逐条核对后均非缺陷（不同任务的路径与验收命令差异、同一文档内两个时点的基线哈希表），未新增重复。

### 复核工具

批次 J 把排查中的形态子集固化为 `tools/check_instance_markers.py`，让复核方能独立复现：

```bash
python -B tools/check_instance_markers.py            # 当前工作区
python -B tools/check_instance_markers.py --commits  # 逐个扫未推送区间的每个提交
python -B -m unittest tools.tests.test_instance_markers
```

判据测试 17 项通过（含改写前真实句子的回归用例）。对私有源原文实测命中 62 处。

**工具第一次逐提交扫描就抓出了它自己那一轮的漏检**：批次 A 与批次 B 的树里，`tools/learning_book/LOCAL_USE.md` 仍写着「首题 1 次／3,653」——同一组数据在另一份文档里已被抽象。先前的普查脚本按「五位以上数字」过滤金额，四位数带千分位被漏掉。已随第三次历史改写清除；未推送区间的 11 个提交现均为 0 命中。

**这个工具不做什么**：它判的是形态不是语义；它只看得见公开仓库自身，迁移当时真正起作用的「私有源逐行对照」那一轮需要私有工作区，无法在本仓库复现；它也扫不到语义等价但措辞完全不同的泄漏。0 命中不等于内容已脱敏。
