# 独立使用与迁移

这个仓库拥有独立 Git 历史，所有日常操作入口均位于本仓库，运行命令从本仓库根目录执行。

## 本地内容

先运行 `python -B tools/init_workspace.py` 创建空目录。需要使用自己的资料时，可在本机将 raw 和 wiki 复制到此工作区；这些目录不会进入版本控制。复制前确认目标文件是否已有内容，避免覆盖。初始化命令不读取或搬运其他知识库。

建议将私人知识库另行备份。新仓库的 Git 历史只保护框架，不能用于恢复未跟踪的私人资料。

## 状态与部署

旧运行数据库、凭据、操作回执、预算和恢复日志不随迁移复制。它们可能绑定旧库根、文件摘要或运行身份；实际服务迁移必须单独核对并通过对应模块的恢复协议进行。

CLI 中的 `--root`、`--state-dir`、部署配置等显式参数应指向新位置。设计文档中的占位路径不是实际部署配置。DeepTutor 补丁应按其 manifest 和固定上游版本使用，不直接作用于未知版本的运行实例。

## 原仓库

独立导出不会删除原库的资料或改写原 Git 历史。原仓库以前已经提交的内容仍存在于其历史中；公开仓库的净化不等于原仓库历史已清理。停用旧框架副本或清理旧版本属于后续独立操作。

## 设计内容的迁移

除仓库拆分外，原工作区的**设计信息**也整体迁入本仓库，作为唯一设计正本维护：维护门禁、知识准备与准入、学习底座与交接、课程与出题、受控扩展、入库改造、上游选型研究与历史演进档案。

- 迁移主题、处理类别、合并规则与未公开范围见[设计迁移摘要](design/migration-summary.md)。
- 全部设计文档的导航入口见[设计入口](design/README.md)。
- 原始证据附件、课程正文、知识页与个人学习记录不进入公开仓库；引用这类结论的位置已标注「证据未公开，无法由本仓库独立复核」。
- 逐项核对记录留在本地，不随仓库发布，因此本仓库不维护第二份设计正本。
