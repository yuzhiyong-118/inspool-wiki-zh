## 3. 第一批：用量接续与日常升级

### 用量接续

- 先只读核对实际运行配置、日常账本、控制库floor、active／metering_unknown、当前额度和所有权；不得输出密钥或整份设置文件。发现未结算调用先对账，不能删除控制状态来启动。
- 精确输入是Q3最终新增调用记录（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-question-q3/run-04/final-usage.json）、传输诊断（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-question-q3/transport-settlement.json）和已知停止点（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-question-q3/run-04/stopped.json）。从明确新增call_id选择五条记录，不把整个153行副本覆盖日常账本。
- 为本机单实例安排受控停服及一致性备份。先在临时账本验证归并：相同call_id且全部审计事实相同为幂等；相同ID却内容冲突必须拒绝。只追加缺失记录，保留started_at、session／turn／source、实报／估算性质及原状态标签；934不能删除或改成实报，历史interrupted不能批量“修正”。
- 优先复用现有计量写入口。若缺少可审计导入操作，先实现窄工具并做临时库正负例；禁止静默INSERT OR REPLACE。不建立长期第二账本。
- 用实际缺失ID计算本次增量；若五条均缺，增量应为账本中该五条之和（见本机账本），若部分已经导入则只加其余。重复执行增量为0。保留原baselineCallIds、floor、有效总额与暂停线；上次为100万／80万，不以导入为理由重设额度，也不回退用户后来合法修改的配置。

### 升级与恢复

- 沿用现有停服备份、安装接入和恢复流程。先核对当前受管进程身份；不按占用端口盲杀进程，不覆盖正在使用的site-packages或现有control目录。
- 使用release-04的完整八模块及当前项目代码，核对wheel／模块／补丁指纹，包括runtime_guard.py。准备独立安装目录和新的控制接入身份，保持同一业务数据、预算历史、floor及未决事实。依赖必须实体化，不能靠缓存硬链接或放宽pathsec检查过关。
- 切换前保存当前内容、进度、已选公开会话、基线和包的对照。切换后核对运行身份、实际模块路径和摘要、原课程／作答／聊天／基线、严格学习状态及I5离线包；做停止／重启和独立恢复检查。日常与恢复观察副本不能同时向同一数据写入。
- 只读检查和本地作答判分不调用模型；检查不能点击原生生成／追问来“顺便测通”。恢复／回退必须携带最新账本及学习数据，不能把旧备份覆盖回来丢掉导入用量或新作答。

本批验收：五个ID逐条对账及冲突负例、幂等重放、归并前后累计与floor、有效补丁身份、原学习数据保持、停启／恢复及回退依据。不能只提交“服务已启动”截图。

## 4. 第二批：W1 操作入口与确定性准备

复用现有应用方法、不可变产物和CLI，不新增通用loop、jobs、队列、插件装载器或第二套状态真值。

- 统一当前路线／能力／最小输入／稳定错误码／产物定位，工作单与CLI参数来自同一份实际契约。纯学习路线不强制登记wiki Runtime任务。
- inspect-task保持只读；describe-input提供可运行模板；prepare-next只白名单串接输入已明确的私有机械步骤。来源、目标、主张和实际payload必须由已有输入提供，程序不编造语义判断。
- 原文正式登记、模型调用、课程POST、admit／apply／approve和预算变更不进入自动串接。已有合法授权可以复用其范围，机械准备完成不能自行签发新权限。
- 缺审、输入变化、规则／范围变化、来源失效时返回定位与下一步并停止对应路径；可回读完整证据，默认回执简短。unknown调用不得换ID或补发。

验收：同输入与既有单步产物语义一致；缺审／stale／越界输入等负例无正式副作用；重复执行及中断续接不重做已确认副作用。报告实际工具调用／纠错／重复读取，宿主回合或tokens不可见时记unknown，不能用JSON变小宣布节省tokens。

## 5. 第三批：E1 受管正文与整书交付

目标是让外部Agent已整理的讲义，通过受管应用操作交付成课，贯穿请求冻结、准备审查、revision、预算身份、unknown对账及首次I4。不是再实现教学Agent。

- 先核对Production、准备步骤白名单、上游BookEngine／路由／状态机的真实接缝，明确本次正文写入和整书完成端点／模型；接口缺口由最小固定补丁补齐，不开放任意HTTP或文件编辑。
- 作者正文不经模型重写，正文与来源／讲义版本可以回读核对。完成操作须根据实际规划内容、块和整书生成状态判定，拒绝缺内容／生成中／错revision，不直接把Book状态写成ready。
- 首次I4认可后需要纠错，创建替代activity/book并说明关系，保留旧题、作答、基线和I5，不原地重绑旧答案。
- 来源、规格、审阅或实际输入在冻结到提交间变化要拒绝；未知响应复用原请求身份核对，禁止换ID重发或用普通GET隐式恢复生成来补齐。

验收必须经真实项目CLI／Production和隔离HTTP，走受管正文写入→明确整书完成→实际I4审查→I5；涵盖响应丢失、重复／并发、旧revision、缺审、运行中、缺内容、已学习／已认可替换、重启及旧包兼容。不能用手动预置ready课件证明E1完成；模型／认证／索引使用替身时逐项标明范围，不把它们写成真实验证。

新增W1/E1产物先在隔离环境验收。是否再次切入日常，按用户交给执行Agent的实际部署范围执行并单列结果，不把代码完成当成已经部署。

## 6. 真实资料与用户试学

已有架构课可以用于后续用户试学，Agent不代做用户的掌握证明。本批确定性开发和升级无需新增模型调用；确需真实教学／索引／生成时，先核对原会话已有资料、供应商、功能和预算授权，原范围仍有效的不要重复索要许可，范围扩大或缺失才补充确认。

Q3“四个对照样本”的授权不自动扩成新质量实验。没有新增调用条件时，保留待执行项并继续不依赖它的离线工作，不能把测试替身或Agent自己答题当用户验收。
