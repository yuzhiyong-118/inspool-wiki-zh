## 3. W1：固定管线与渐进式操作

### 3.1 从“告诉 Agent 下一步”到“执行确定步骤”

`inspect-task` 保持只读，`describe-input` 提供单一契约生成的模板。另增加普通应用方法／CLI `prepare-next`，支持以下限定：

1. 操作者明确给出私有工作根、输入引用、拟执行阶段或有限阶段序列、允许读取范围和预期输入摘要。该根与正式 raw/wiki、运行配置、密钥目录隔离；不接受任意 import、shell、HTTP path 或插件代码。
2. 白名单串接现有 inspect_context、draft_learning_brief、prepare_knowledge、build_learning_projection、preview_wiki_changes 的确定性步骤。只使用已明确的方向、主张、观察和 payload，不靠程序凭空补语义。
3. 只有当前产物、依赖和前置已实际核验才继续。缺用户范围、独立语义审阅、来源、实际 payload 或授权时，返回缺失项、定位和 reviewRequest 并停止。单独填 accepted 不能升格为认证。
4. 产出写入私有工作区，复用不可变版本和原子发布；以现有产物引用推导下一步，不增加 jobs、队列、可写工作流状态或新 loop。
5. 原文正式登记、模型调用、admit／apply／approve、课程 POST 和预算变更不属于自动串接范围。只返回对应受管入口及已有授权要求，不把机械准备的成功变成正式执行许可。

这允许 Agent 一次表达已确定的准备动作，不必手写每份中间 JSON 再逐条复制路径。机器可从已审观察构建包，但不能替代真实 Reviewer。K／L／C1–C3 的相同机械部分共用操作，纯 L 不因管线要求登记 wiki Runtime 业务任务。

### 3.2 中断与复用

每个现有产物绑定实际输入引用／字节、处理方法及版本、规则／配置、作用域。恢复先核对当前依赖，再选可复用的确定性结果。检查不通过时说明失效层级，不覆盖旧产物，不靠修改 timestamp 或重新签 accepted 继续。

时间、临时路径和运行日志尽量作为非语义审计信息，不能每次变化都迫使重做；但实际影响输出／权限的时间窗口和版本必须进入绑定。语料相同不等于目标相同，目标／范围改变仍更新对应约定和映射。

管线不会重放 unknown 模型调用或未知 POST；这些只交原身份对账。最终 G3 与当前依赖检查保留，不通过缓存恢复它们的历史权限。

### 3.3 默认回执

回执只含：操作／结果、artifactRefs、实际覆盖与失效、必要 nextActions、缺失或待审范围、费用观察范围。正文和完整差异默认落盘，显式读取命中段落或完整已选审阅对象。超出回执上限时明确 truncated 与继续读取方法，不把部分内容伪装为完整。

W1 的验收不以“少生成几个文件”为目标，而是比较完成相同准备任务需要的已观察工具调用、输入纠错和重复文档读取。未观察到外部宿主完整工具回合时，区分 observedToolInvocations 与 hostToolTurns=unknown。


## 4. M1：用量与归因的实施任务

### 4.1 指标定义

| 指标 | 定义与取数点 | 限定 |
| --- | --- | --- |
| localIOBytes | 确定性 Reader 实际读取量，包含复验／重试 | 不是模型上下文或 token |
| uniqueDependencyBytes | 按逻辑根类别、locator、版本／byteDigest 去重后的实际依赖字节 | 同字节不同文件不自动当同一依赖；逻辑定位不回显私有绝对根 |
| contextPayloadBytes／artifactBytes | 实际序列化上下文对象和落盘产物体积 | 不代表它们已全部发送模型 |
| modelRequestBytes／agentReplyBytes | 实际 transport 序列化请求、实际对调用者返回的回执字节 | 不据字符比例伪造 tokenizer 结果；没有采集点时 unknown |
| modelCalls／retry／uncertain | 实际调用身份和结果；步骤／语义／机械操作分别计数 | deterministic_module 的 modelCalls=0 仍保留；不能代表宿主全链 0 |
| providerUsage | 供应商实际 input/output/cache/reasoning/total 的可用字段和单位 | 保留来源、实报／估算／缺失及归一化版本；不重复加总包含关系 |
| attribution | invocation/request/activity、session/turn/source、operation/stage 的真实关联 | 缺失保留 unattributed／unknown，不根据文件时间或相邻日志猜配 |
| observedToolInvocations／userClarificationRounds | 项目可观察的工具执行与实际澄清次数 | 外部宿主不可见部分不补 0；不把一条命令认作一次模型调用 |

### 4.2 K 侧

在现有 transport／Invocation 边界增加可信 usage 观察出口，关联原 invocation；不向封闭的模型业务 JSON 塞 usage 字段，也不把 usage 当模型自报授权。只保存计量白名单、实际提供者／模型、调用标识和请求摘要，不记录密钥、私有推理或完整敏感响应。

上层错误、超时或结果 unknown 时，结果状态与费用状态分别记录：有费用不等于业务成功；费用未知不等于零或可以免费重试。没有可信关联时单列未归因调用，不伪造原 Invocation。汇总是现有调用事实的派生观察，不成为第二个扣费／授权账本。

### 4.3 L 侧

沿当前 closeout 补丁的 CallMeasurement／collector → RuntimeGuard.begin／finish → 上游 usage ledger 检查归因。接口已有 session／turn／source，不重复造新的调用入口；重点验证各实际调用者是否填充、哪些领域没有 session，以及 source 标签是否区分编排、题目和教学追问。

上游账本仍是业务 token 正本，控制库只保存监督与关联。一个调用只按 call_id 计一次，缓存和 reasoning 若已被计入 input/output/total 就不再额外累加。供应商未提供细分时记 unknown，不用其他模型的字段含义代推。

### 4.4 验收和预算边界

必须验证：有／无／畸形 usage；缓存子项与总量不双计；未知调用及迟到计量；并发唯一调用；跨重启不清 floor；同 source 不同 session；缺 session 但有领域 stage；外部宿主无计量时仍可读代理指标。

当前实际额度、暂停线和计量未知时的停止规则不因 M1 改变。不能把 K 的次数／字节／时间直接与 L token 相加成硬总额；也不把宿主订阅会话从 unknown 换成 0。没有 provider 实报只能比较代理指标，不发布实际 token 节省比例。


## 5. W3：上下文、缓存与局部失效

### 5.1 上下文和会话生命周期

内部教学端默认按 activity/book/page、当前问题和明确选段取得材料；主题、范围、未决问题和必要最近对话保持可用。历史正文／其他来源／更早会话按定位读取，不把全部资料、I5 原包或全部对话每轮重复发送。

可以形成带来源引用、适用版本和限制的工作摘要，但摘要只辅助续接。原答案、原文、课件基线、授权与原审阅依据不可因裁剪删除；关键事实审阅能回读完整对象。工具请求与结果成对保留，未完成调用、当前任务约束和未处理冲突不能被普通裁剪移除。没有足够依据时重新读取，不用摘要猜原话。

管理范围仅限内部 Agent 可控制的上下文构建器或既有上游受支持配置。先核对真实扩展点；不假设能触发外部 Agent 宿主压缩，不为此重写 DeepTutor 全套会话系统。

### 5.2 缓存友好布局和本地产物复用

在可控制的请求中，将稳定规则／契约／输出约定置于稳定前缀，动态任务、随机标识、当前时间和变化观察置后；实际有效的规则和授权变更仍进入语义绑定，不能为命中缓存继续使用旧 policy。正常工具历史不能为排序强行改角色或次序。

真实请求是否命中及如何计费取决于具体供应商，必须记录冷／暖 usage，不能仅根据前缀相同宣称节省。不要为了缓存命中填充无关规则、整库或旧答案。只有业务请求相同且仍合法时才能做重用；不为实验重复发送有副作用的业务操作。

本地产物缓存先复用现有不可变文件和引用，没有必要先建全局语义缓存服务。检索缓存、抽取缓存与语义审阅有不同失效条件：原件／处理器改变重做抽取；候选选择条件改变重新检索；事实／关系／冲突改变重审；原 G3／权限不能由普通缓存刷新。

### 5.3 模型与结构化输出

纯计算和搬运不调模型；已有讲义通过 E1 交付，普通显示复用上游块和组件；预审题保留当前有界流程，仍核对真实输出，不承诺模板逐字复制。简单交互不逐次生成一个新应用。

如实际需要小模型承担候选标签、检索词或私有分段摘要，须使用固定任务和质量对照；来源支持、冲突判断、授权及正式提交审阅不因便宜自动降级。模型、推理和输出限制由任务明确配置，不预建动态路由器。减少无用解释可以，删掉需要的依据和反例不算优化。


## 6. 同任务对照与质量验收

### 6.1 固定任务组

| 任务 | 固定输入和目的 | 必查质量点 |
| --- | --- | --- |
| F01 新资料整理 | 一份短原文＋固定已有知识页，输出固定主张范围 | 事实、出处、版本、正反条件和反向关系 |
| F02 条件与冲突 | 含否定／例外的原文＋相反旧结论 | 不因短回执丢掉否定条件、例外或未决冲突 |
| F03 来源去重 | 两份共同上游的材料 | 不把转载篇数当独立印证，locator 与原字节可回读 |
| F04 无关变化 | 同任务增加无关页，再增加高排名相关／冲突页 | 前者可复用时少返工，后两者必须重选／重审 |
| F05 已有语料成课 | 同语料、固定学习范围与输出要求 | 复用不重传；新目标不继承旧认可；正文／题目仍经实际审阅 |
| F06 中断后继续 | 相同冻结输入、原请求，包含未知结果 | 恢复不重复生成／写入；不清预算、unknown 或原证据 |

先用合成原文与临时库核对确定性指标、控制流和退化情况；真实模型比较再核对实际资料外发与费用授权。不能用本机替身 token 数当真实模型消耗。

### 6.2 对照方法

冻结当前手动逐步操作作为 A，采用新机械管线／短回执／局部复用作为 B；分别对相同资料、知识基线、目标、深度、质量要求、提供者／模型及已记录的推理／输出配置执行。每次只改变一个优化因素，记录实际请求字节、调用与实报 usage、已观察工具往返、错误修订和人工澄清。

冷缓存和暖缓存分列，运行顺序／样本数明确，不能把 A 的冷缓存与 B 的暖缓存混比。语料复用等有副作用的任务使用隔离环境或原请求的合法历史重读，不复制正式操作来“凑样本”。真实模型有波动，单次样例只报告该次观察，不外推长期比例。

报告实际 token 的变化、缓存计费／延迟的变化、本地 IO／CPU 转移和额外回读成本。未知部分保留覆盖；K／L 分别比较后再解释关联，不能把新增一层调用的成本隐藏在另一个 Agent 中。

### 6.3 放行标准

必须同时满足：关键事实、否定条件、冲突、来源范围和逐字定位不退化；所有适用授权／门禁／恢复仍生效；原件与历史记录未改；至少一项目标指标下降且没有不可接受的调用／返工转移。摘录一致率、locator 可回读率或“主张数量相同”只是必要检查，不能单独证明质量相同。

没有下降就如实报告优化无净收益，撤回该优化选择；有 provider 缺失项只给代理指标结论。预算监控通过只证明限制有效，不等于正常调用更省。未执行的实验标 not_executed，不预填节省百分比。
