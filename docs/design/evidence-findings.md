# 审查发现与修复机制汇总

本文汇总历轮审查与验收中**只存在于验收证据目录、未随仓库发布**的设计信息：问题是什么、为什么会发生、修复机制是什么、哪些失败教训被刻意保留。

原始证据附件（验收快照、探针结果、运行回执）未随本仓库发布，因此这类内容此前只以「问题已关闭」的结论形式出现在方案与交接文档里，**机制与失败教训缺失**。本文补上这一层。

> 文中计数对应原文写作时点的环境。实例标识、本机路径、个人账本与运行状态一律已抽象；原始证据的定位见各节末尾。

## 一、正式知识准入：并发授权被覆盖

来源：正式知识接线的独立复核记录。

### 发现与原因

一项实际并发缺陷：咨询 `review_adopted` 在模型调用期间持有旧 pending；另一 Host 已完成 admit 后，咨询回包**整体保存旧记录**，把 authorization 一并抹掉。而 Runtime 的准入绑定已不可变，结果是该 operation 持久阻断——授权丢了，绑定还在，二者再也对不上。

### 修复机制

咨询回包提交前**短暂取得同一把 OS 接受锁**，重读 pending、核对原不可变输入，**只合并 opinion／status**；**不在模型调用期间长持接受锁**，也不覆盖并发授权。新提交前与最终 acceptance 都重读最新意见，负面意见阻止新 prepare。`validate_binding` 本身不以咨询意见阻止已接受 WAL 的恢复或终态重放。

复现方式：独立审阅者用实际 `review_adopted` 的纯内存探针复现「旧记录丢授权」，并在修订后确认原 authorization ID 保留；`check_current_inputs` 对最新 `request_changes` 抛 `HostError`。

### 主 Agent 补齐的边界

- 知识 WAL 的范围、准入摘要、manifest／candidate／snapshot、steps 路径集与 old／new hash 均对应原候选；重启恢复不接受缩放 scope。
- **最终结果归并核真实 WAL**；终态的核心事实不能改写，只有 errors 展示差异时保留原始终态。`inspect` 不把损坏 WAL 静默降级成 admitted。
- 知识 ingest 不能签发用户 approve 的 `reviewed_at`；raw 正文与 `pending_review` 顺序继续用原门禁，`processed` 迁移不在此入口。
- revoke 在模型前与最终接受时各检查一次；授权、policy、epoch、ownership、财务失效都阻止新 prepare；恢复与原终态不重新要求新授权或模型。
- **admit 也使用现有 OS 接受锁**，避免多个 Host 对同一 pending 的宿主授权互相覆盖；现有修改要求不能靠换次调用争取通过。

### 保留的失败记录

1. 初轮备份测试把导出的 package 根直接当 RuntimeStore 根，**创建了另一个空库**。按真实运行目录布局恢复后 4 项 Runtime 检查通过；没有修改存储实现来迁就夹具。
2. 同一新增用例把 Reviewer 包装器捕获 `OSError` 后返回的 error 意见**误期望为 Invocation unknown**——它实际持久保存了成功返回的 error 意见、不会写库。已把夹具改为真实超时及迟到结果，并加入实际重启核对。原失败不改成全绿。
3. 旧子进程 JSON 在 Windows 缺少 UTF-8 环境，父进程解码失败；明确 `PYTHONUTF8=1` 的单项复跑通过，未改业务检查或旧测试字节。
4. 「无正式变更」盘点原本包含控制目录；新增咨询提交 OS 锁会**首次建立控制面锁文件**，检查现改为排除控制面，继续核所有正式内容，未排除 raw／wiki 业务文件。

原始证据定位：证据目录中正式知识准入的复核记录与验收摘要（未随本仓库发布）。

## 二、E1 作者整书交付：五项复审遗漏

### R1–R5 修订

| 编号 | 问题 | 修订 |
| --- | --- | --- |
| R1 | 严格目录与完整集合 | 内容规划消费 `/content` 已有的 spine、页面枚举与 manifest 信息，拒绝任何严格枚举错误，并核对页数、章节数、唯一页面／章节 ID、章节归属、页面全集及相关引用；提交端改用严格页面列表构造同类内容，不再用尽力而为的列表证明整书完整 |
| R2 | 真实教学内容 | 删除任意 payload 字符串兜底，按块类型检查正文、题目、卡片、代码、视觉内容的实际字段。文本块至少要有非空 body 或 content；`format`、URL 与元数据不能证明正文存在；视觉块只接受实际代码内容或描述，不接受单独的 `language`；未知类型返回专用错误 |
| R3 | 整书生成状态与登记竞态 | 正文写入与完成同时检查 worker 存活、在途与页面生成状态。单页任务与整书 worker 的登记点共用作者协调锁，提交期间的新登记必须等待；完成接口不停止 worker，也不启动生成 |
| R4 | 普通读写屏障 | 在既有发布屏障中协调作者 journal，因此所有普通读取与原生写入都受同一稳定性检查。未显式恢复时返回不稳定错误；恢复仍按原 requestId 与前后模型摘要进行，额外编辑拒绝，不隐式生成 |
| R5 | 首次公开导航 | 首次 inspect 的两个期望摘要改为可选，未提供时返回现读摘要，提供时仍校验；`prepare-next` 继续强制两个摘要，输入变化返回摘要不匹配 |

### 旧发行反例（刻意保留）

在旧发行上重跑审查反例，出现四种失败形态：缺 spine 页仍完成并返回就绪；空白正文加格式声明仍完成；页面保存后、manifest 保存前中断，普通读取返回成功、新正文搭配旧 revision；存活整书 worker 不妨碍完成。首次 inspect 缺摘要退出码错误、占位摘要也不返回实际摘要。

这些反例的作用是保证后续修复不是「让旧用例变绿」，而是真的封住接缝。

### F1–F3 第二轮修订

- **F1 原生概览章计数**：章数表示实际交付 spine 的总章数，包含自动概览章；确认 spine 时同步实际页数，不放宽其余目录完整性检查。
- **F2 真实渲染与逐块门禁**：文本采用与前端相同的空值选择规则，空正文不会被不可见的后备值放行。每个内容块都必须有效，同页有效题目或正文**不能掩盖另一个空块**；只有明确标注的结构块豁免内容字段，且每页仍须至少一个真实内容块。
- **F3 每章必须有页面**：内容规划拒绝任何空页面集合的交付章节，继续拒绝重复归属与页面集合不一致；删除章节须通过目录修订表达，不能把空章当作已交付。

原始证据定位：证据目录中作者交付的修复证据、两轮独立复审与反例记录（未随本仓库发布）。

## 三、I2 真实学习探针：预算门禁与在途停止

### 复审发现

复审发现：暂停线**只返回状态**，缺失用量按 0 放行，模拟没有真正执行 watch；策略还重复计算已观察用量。旧模拟的原始产物保留为历史，不能作为通过依据。

### 修复机制

- 预算守卫：**暂停线即阻止新步骤**；账本缺失、读取失败或用量不合法均停止；只读一次快照作判断；watch 必须配实际停止回调。持续一段时间没有新账本进展时停止，避免长期不可观察。
- 探针控制器：顶层命令启动前检查，独立线程在阻塞请求期间监控。触发后先请求原生 pause，再停止已核验的本次 API，以覆盖独立调度的对话回合；原生 pause 失败仍尝试停止 API；身份不符或停止失败明确报错，**不宣称已取消**。Web、本地模型服务和其他实例不在终止范围。
- HTTP 门禁：写请求发送前检查余额并要求由控制器直接托管；只读请求仍可独立使用。

### 越线后的处置（保留为处置规范）

- 立即停止发起所有新的模型调用；
- **没有**为了凑出「有通过结果」再开第二轮预算；
- **没有**切换普通按量密钥、**没有**购买积分、**没有**声称实现了供应商硬封顶；
- 越线后所有后续步骤均未产生新的模型调用，结束位点与越界时刻的账本逐字相同。

### 保留的限制

离线通过**不构成供应商硬封顶证明**，也不构成真实界面验证；供应商在途调用与入账延迟仍可能造成超额，不能用单条调用给出通用上界。

原始证据定位：证据目录中 I2 探针的执行报告、复审与预算控制回归（未随本仓库发布）。

## 四、I5 学习记录：决定边界的事实

这一节记录的是**观察 → 设计选择**的对应关系，不是结论清单。保留它是因为读方案的人无法从成品接口反推「为什么不能顺便把某项也做了」。

| 观察 | 设计选择 |
| --- | --- |
| 旧整书读取会恢复生成，学习前内容补丁有意不返回学习状态 | 另补最小学习状态读取口；不借旧读取或写入接口获取进度 |
| 缺失、读错与校验失败可折叠为「无」，随后构造空进度对象 | 严格只读状态须区分缺失／无效／不可读／有效但为空；不返回模型自动补出的时间或默认记录 |
| 缺时间可补当前值，进度更新时间也不统一随保存刷新 | 保留原 JSON，变化检测比较实际载荷，不能只比时间戳或数量 |
| 页边映射分属本人页与共享读者覆盖层，旧映射加载器会过滤或字符串化 | 新读取口保留原值与诊断，明确学习者／内容归属，不读取共享作者状态 |
| 事件可能是压缩预览，且有大字段裁剪；详情不等于全量轨迹 | 消息与事件分别描述覆盖；规范事件按实际分页补取，不把详情当全量 |
| 旧会话可返回空事件却标记完成 | 保留历史预览及其覆盖；空分页不证明旧历史完整 |
| 会话列表会尝试回填来源归属 | 不纳入只读导出发现；首期只给当前映射加明确会话 ID，其余历史标记为未知 |
| 原生列表排除导入与已删项，按更新时间偏移遍历可能漂移 | 不默认扫全工作区，不把页边映射或某个列表当全历史；扩大历史发现另立任务 |
| 客户端布尔、自评字符串与空值语义不同，进度已保存后同步可能报错 | 原值与原错误是否可见分开；不重发答案，不用原分数表示掌握，项目键必须含完整作用域 |
| 捕获时间与绑定时间分别存在；候选快照不等于正式绑定 | 每次导出做新检查，逐记录核对两种时间与实际接受绑定；不升级历史证明 |

**取舍与未关闭项**：首期导出范围是「所选公开会话与已存进度」，不是完整聊天备份；书级历史覆盖明确为部分，选定会话内的消息与规范事件另列完整性。这样不必新增全账户发现、删除恢复、归属回填与通用抓取框架，仍能完成交接。

原始证据定位：证据目录中 I5 设计记录与最终验收记录（未随本仓库发布）。

## 五、课程受控扩展：三项未关闭的实现缺口

### CE-R1：原生生成器输出与扩展 schema 不兼容

真实文本生成器输出 `format/body/role`，提示块输出 `variant/label/body`，测验输出 `questions/topic`；扩展校验却只接受文本／提示块的精确 `format/body` 与测验的精确 `questions`，且生成后直接校验原生结果，没有适配。三个类型从真实 HTTP 入口调用均得到内容校验错误——模型替身已成功提供合法原生结果，**这不是供应商质量问题**。

交付版本的测试之所以通过，是因为它替换了整个生成器并直接填写新契约形状，绕开了这个接缝。

**最小修复**：增加显式的原生结果适配，保留有用展示字段与真实来源锚点，继续严格验证最终内容；不要简单删除全部字段校验。再用真实生成器加底层模型替身覆盖文本、提示、测验、建议、整组补充与真实规划链。

### CE-R2：文本 provider 重试绕过每动作调用上限

受管出题路径已在创建前扣减，固定选项、禁用工具与限制修订也已接上；但文本与提示走的是另一条路径——只在助手入口扣一次，**provider 的每次重试没有扣减**。反例：预算设为 1，第一次返回服务错误、第二次成功，实际传输调用 2 次，未在第二次前阻断。

**最小修订**：在每次实际 provider 尝试前统一执行动作预算，明确助手与底层入口的计数关系，避免补扣后同一调用被扣两次；覆盖文本、提示、章节／深挖与受管出题两条路径的成功、传输重试和修复调用。

### CE-R6：深入学习白名单允许重排父页旧区块

追加操作的页面非块字段保护已补齐，深入学习也增加了父页、映射与计数约束。但父页块被转成以 ID 为键的字典后，**只比较集合与逐块内容，丢失了原来的排列顺序**，深挖因此能额外授权旧块重排。反例：先完成建议块与合法深挖，再只反转父页块顺序、按变更重算摘要并传入匹配投影，完整校验链仍通过。

**最小修订**：在字典化之前要求父页块的有序 ID 列表与原页完全一致，并显式拒绝重复 ID；只允许目标建议块增加约定的映射字段。

### 其他关闭状态

- 前端丢失原请求：已有持久化、先查询与关联重试；实际成功确认窗口仍卡住。
- HTTP 没有真正恢复：原 prepared 恢复反例通过；**不等于**候选确认已恢复。
- 后续追加丢失题目关联：原连续追加与实际作答关联反例通过，唯一引入提交接线已补。
- 预算专项数量：已统一为实际执行的项数，独立重跑同数通过。
- 新增的「按原候选显式关联」方向合理：显式关联原候选、使用新提交身份、复用生成字节，不再为 revision 冲突重新付出模型调用。

原始证据定位：证据目录中受控扩展评审及其复审记录（未随本仓库发布）。

## 六、扩展上下文缺失导致内容跑偏

### 用户发现的问题

真实课程第 1 章用「骨架、血液和薄大脑」解释 Flow、数据集与 Agent。插入提示与深入学习后，系统生成了人体骨骼、血液循环与大脑结构，明显偏离课程。同时要求：推荐方向不满意时应能自行指定深入学习方向。

### 根因

提示与深入学习只读取章节标题、摘要与目标，**不读当前页正文或知识库**；当前章摘要又只有比喻。补充讲解会尝试检索，补充题会显式提取页面正文，因此不同扩展块的上下文不一致。后端还要求深入学习主题必须来自推荐卡片，没有自定义方向契约。

### 修复

- 统一从当前页提取文本／提示／章节的有界正文，与书名、章节、页面和学习目标组成生成上下文；**没有有效正文时在模型调用前拒绝**。调用方不能用摘要参数覆盖服务端上下文。
- 提示、文本与深入学习建议经同一上下文对象获取该上下文；深入学习子页的候选章节也携带父页上下文与用户指定方向。检索继续作为补充，不再是页面语义的唯一来源。
- 新增可选的自定义方向：只有显式开启时才允许不在推荐列表中的方向，并限制长度；旧请求继续省略该字段，未知推荐主题仍返回专用错误。
- 请求摘要先按客户端原请求核验，再补默认值；旧候选、原 requestId 重放、revision 冲突后的候选复用与提交链保持兼容。

原始证据定位：证据目录中该轮扩展的修复与反例记录（未随本仓库发布）。

## 七、出题：接口核对与复核发现

### 接口核对得到的边界

| 观察 | 处理 |
| --- | --- |
| 规范摘要拒绝重复键与非有限数字，可直接复用 | 不改变旧摘要规则 |
| 六字段模板、明确 revision、请求与发送阶段冻结；已派发且无完整响应不重发 | 加定稿操作与题目附件；无模型不等于可以绕过请求／授权／并发检查 |
| 显式操作白名单只覆盖三个操作，绑定与步骤审查在真正发送前重验 | 定稿发布加入同一检查链；同活动续接也必须生效 |
| 已有来源／映射留存与有效续接 | 不往封闭旧对象塞未校验字段；独立题目附件必须归档并参与请求身份 |
| 字面检查不替代审校 | 实际题目版本必须进入新附件与接受条件 |
| 旧包结构明确为版本 1 | 新绑定要有明确版本能力；不得改旧包哈希或悄悄丢弃附件 |
| 原生重生成路由先 claim 并保存 revision，再调引擎；失败可能已经推进 revision | 不直接当作原子定稿写接口；真实未知状态必须能查证 |
| 书与页分别原子写，没有跨文件整体提交的证明 | 选定恢复协议后才开放定稿 |
| 通用编辑仅允许文本／笔记／提示，桥接补丁也未提供测验写入 | 不借已有通用更新接口导入测验 |
| 计量与停止、固定文件清单、单 worker 与隔离恢复边界 | 新补丁进入发行清单；追加写入口受原保护；不能把本地核对当原生端已保护 |

### Q2 复核发现与修订

| 发现 | 修订与验证 |
| --- | --- |
| 上游书与页分别保存，revision 提前推进不能证明完整提交 | 窄发布同步持久化「准备 → 页 → 书 → 应用」；实际进程在四个断点退出后核对前后状态，额外编辑保留不确定 |
| 恢复副本自身可能损坏，canonical 摘要又会漏选项顺序 | 写前验证副本与响应摘要；页面与响应信封明列选项顺序。题文、顺序或响应损坏均先拒绝，不把副本写进正式页 |
| 变式原地生成可能留下半成品 | 使用页副本；生成保留持久预留，结构通过才写 journal，格式失败保留旧页，中断不重放模型 |
| 规格绑定不等于最终变式内容版本 | 附件保存实际冻结的请求与发布响应，核对请求摘要、目标、确定性模板与最终题目摘要；保留绑定标记却改解析的反例拒绝 |
| JSON 规范排序丢显示顺序 | 规格、题目、实际请求与 journal 显式绑定顺序；新附件使用保序序列化，旧摘要规则不改 |
| 只拦项目接口，原生入口仍可能覆盖 | 保护实际内容变更 claim 与存储写入／删除边界；受管书不能走旧重生成或省略守卫。未完成 journal 的内容读取返回明确不稳定 |
| 一刀切书写锁会阻止页边对话 | 仅允许聊天映射、会话 ID 与更新时间等非内容变化；题目、正文、revision 与绑定仍保护 |
| 请求丢响应后只改回执，会使重放又变不确定 | 用精确读取核对另存对账证据，不伪装原请求回应；后续本地重放读取该证据，不发第二次请求 |
| 新操作的失败分类可能改变旧口径 | 明确派发前失败只作用于新绑定题目请求，旧操作口径保留 |

**保留的范围限制**：发布后题块不可原地替换，改题先用新活动；本机单 worker 与自有课程的权限解析使用合成夹具，共享编辑、宿主强认证、多进程写入与恶意本机写盘不在证明范围；文件 fsync 与进程退出实验不等价于任意断电或磁盘故障的事务保证，无法辨认状态时保持不确定；规格与最终审校仍由人或外部准备者判断。

原始证据定位：证据目录中出题接口核对与 Q2 复核记录（未随本仓库发布）。

## 八、知识准备 K4：独立复审发现的三项

| 问题 | 修复 |
| --- | --- |
| 返回的 scope 字典同时是扫描策略；调用者修改上次报告可能删掉后续扫描 | 内部固定元组驱动完整扫描与两个规则文件；报告每次创建独立结构 |
| 第二份 brief 使用新深度建课后，不带守卫重读同请求又套用最初的 corpus 头，造成请求冲突 | 保存每次受控创建的实际 manifest；无守卫的已有请求沿用当时的审计包，显式参数仍须一致；新增请求继续需要守卫 |
| 确认／出题审阅仅在发送时读取，没有持久绑定具体观察 | 语义冻结生产审阅引用（ID、观察摘要、审阅请求摘要），完整请求与观察保存在审计中；真正发送前再次匹配。替换观察触发审阅变更错误 |

**保留的失败**：主 Agent 首轮 18 项中发现一个失败——守卫在发送前给出冲突，旧失败记录函数把它转成了不确定。修复为在创建发送标记之前的失败记为失败；若之前已完成知识创建等副作用，外层仍记部分或不确定。**没有修改门禁来消掉失败。** 补充命令行测试的两次夹具失败也保留：一次缺少停止进程，一次绑定到 Windows 虚拟环境启动器而不是实际专属服务进程。

## 九、知识系统修订方案：反例自查

这是作者对自己方案的推演与源码对照，**不是独立审阅**。保留是因为它记录了哪些看起来合理的设计实际上有洞。

| 反例／风险 | 处理 |
| --- | --- |
| 把旧报告的「正式准入关闭」当当前事实，重复建设入口 | 复用既有宿主与执行器路径，新增任务检查只作原准入绑定扩展 |
| 认为运行时任务就是跨候选的用户任务，换 operation 即丢约束 | 区分准备任务 ID 与技术任务／运行，保持关联 |
| 任务与课程互相依赖，导致先有课才能准备、先准备才能有课 | 初始绑定为空；先约定与准备后创建课程，真实回执补学习绑定；候选可提前采纳；放行只依赖已存在的候选与学习证据 |
| 交接包存在就当先学完成，空包也能过 | 完成度保持未知；要求可信用户放行与本任务实际范围的学习观察分别核验包结构、课程绑定与关键覆盖 |
| 假定现有交接结构已有新业务任务字段 | 以任务持有的真实回执与准备映射关联现有结构，不造已有字段 |
| 契约被任意选择、新候选或新任务 JSON 绕开 | 业务契约由可信宿主依据真实委托注册，最终接受锁内检查当前契约与发行物；模型不能自选新任务解除限制 |
| 把认可原话字节变化当目标改变，所有续接都要求再确认 | 任务契约绑定授权范围与语义修订；机械路径或 ID 更新有证据映射，范围与顺序变化则新契约 |
| 删清单校验以减少过期，漏掉新冲突来源 | 新增相关候选、排序／截断、歧义与覆盖必须重核；只复用不受影响快照与审阅，保留保守退回 |
| 附件大就排除它，提高「可扩展」通过数 | 先全量清单与流式哈希，范围不收缩；仍承认线性总字节与协作快照边界，无性能承诺 |
| schema 版本不兼容时换空目录，重复调用或额度清零 | 要求副本迁移、原预算与未知状态与 WAL 保留，未知版本先拒绝 |
| 以减少上下文导致语义审阅漏反例 | 快照与短回执分开，审阅者必须能完整读取被审对象与必要相邻条件；不把摘录一致率当语义正确率 |
| 各条路线都被契约、新任务库或大优化卡住 | 保持现有使用路径可试用，契约只在实施后开放；不增加运行／进度／预算镜像 |

**剩余风险**：真实教学与来源判断仍依赖语义审阅；可信宿主授权不等于强制操作系统隔离；跨上游服务与本地知识库无分布式原子事务；调用归因与增量复用收益需要真实数据。

原始证据定位：证据目录中知识系统修订的设计复核记录（未随本仓库发布）。

## 十、块生命周期与删除边界

- 新增扩展块的删除与重生成操作、请求身份、候选、权威提交、原请求重放与 revision 冲突后的关联重试。
- 只允许操作带扩展身份、标记为 AI 生成且质量审阅未通过的块；原正文、原题与其他非扩展内容继续拒绝。
- 删除只移除目标扩展块。删除深入学习建议块时，**已生成的子页、spine 与父页链接保留**，不误删用户已经打开的学习内容。
- 重生成支持文本、提示与深入学习建议，保持块 ID／类型与既有深挖子页映射，记录取代关系。候选失败不替换正式块，重放已提交请求不会再次生成。
- 扩展测验**暂不允许**通过该入口删除或重生成，避免题目与作答证据错配。
- 个人笔记恢复原生删除；个人内容仍不进入受保护课程内容摘要。
- 受管课程前端隐藏整书重建、整页重生成、块移动、类型转换与原正文编辑等未开放入口，不再让必然失败的按钮反复产生错误。

原始证据定位：证据目录中块生命周期与扩展操作的修复记录（未随本仓库发布）。
