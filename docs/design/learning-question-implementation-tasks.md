## 1. 执行边界与接手顺序

先读根 AGENTS.md、正本 §5–§11、本任务书，再按需要读当前代码，不默认重读所有历史。大量既有脏文件与未跟踪文件属于前序工作，不清理、回退或覆盖。

- 先实施 Q1 并自检，通过后更新检查点；Q2 遇共享接口缺口先修订明确方案，不凭假设宣称可用。
- Q1／Q2 使用临时目录、合成配置和假提供方，不读取或输出密钥，不运行真实模型，不改变正式 wiki／raw、已有课程或预算账本。
- 项目侧模块复用现有应用操作；上游补丁固定源码与补丁集，进入安装和恢复清单。不直接编辑课程存储文件，不借任意 HTTP 绕过应用门禁。
- 不要求新增 SubAgent 或第二个学习状态库。教学策略先用数据／提示表达，不建插件加载框架。
- 不提交／推送，不把历史测试结果当当前通过；本轮只运行与实际修改相关的检查。

## 2. Q1：契约、输入渲染与纯离线验证

### Q1.1 当前接口核对与最小实现落点

核对并记录准确符号、调用方向和内容摘要：

| 落点 | 核对重点 |
| --- | --- |
| tools/learning_book/contracts.py、content.py | canonical/digest、封闭字段、现有投影与结构检查；不得重定义旧摘要 |
| production.py、evidence_store.py、budget.py | 请求语义、幂等、锁、unknown、提交前校验与既有预算身份 |
| knowledge_preparation.py、preparation_provenance.py、preparation_continuation.py | 新 publish-quiz 操作白名单、步骤审阅、附件保存与提交前重验 |
| baseline.py、records.py、I5 打包／校验模块 | 最终题版本、来源与审查绑定；老包与新必需绑定的能力协商 |
| cli.py、local_install.py、现有原生／RuntimeGuard 补丁 | 命令参数、原生生成入口、安装能力与恢复路径 |
| 上游 QuizGenerator、QuestionPipeline、BookEngine、books 路由／请求模型 | 定稿窄写入口、revision／锁／事件、真实提示输入、内容与整书状态 |

输出 `docs/design/evidence/learning-question-q1/interface-check.md`。必须选定：定稿操作具体端点与模型、绑定放在哪个有校验的附件协议、变式上下文是新增受管字段还是确定性编入参考题、如何满足写入与未知恢复边界。禁止仅列候选而把关键选择全部推给实施者。

若局部上游读写不是原子的，或现有恢复无法辨认成功，明确指出并给 Q2 具体修复范围；不把“可调现有接口”视为这些性质已成立。

### Q1.2 规格与可运行的纯函数

建议最小模块 `tools/learning_book/question_spec.py`；如需与内容检查分开，边界由实际职责决定，不为每个字段拆文件。

交付：

1. `learning-question-spec/1` JSON Schema、两种模式的合法样例和错误样例；校验代码与 Schema 的核心规则一致，未知字段不得忽略。
2. 有界读取、引用闭合、规范化摘要、定稿内容提取、目标／来源／条件到变式请求的确定性渲染。
3. 字面与结构 finding；语义未审明确输出 pending_review，不能输出“场景已证正确”。
4. 题目版本与选项内容的比较规则；输入文件变动、缺失、超限明确失败，不静默截断。

Q1 不将新逻辑接入默认生产路径，不改已有旧调用行为。旧 `question-constraint-spec/1` 仅是未实施设计，无需为了它维护运行时迁移层；若发现真实已持久化实例，先记录再决定，不臆造历史数据。

### Q1.3 必须通过的离线用例

| 编号 | 用例 | 必须观察到的结果 |
| --- | --- | --- |
| QN01 | 留存白榆真实失败输出，原字节只读 | 指定编号缺失被检查拦截；不重写样本、不伪称证明了语义错误 |
| QN02 | 编号齐全，但题干说“不存在编号不一致” | 可通过字面检查，仍处于待内容审查；不能机器判为冲突成立 |
| QN03 | 含冲突含义的等价措辞，不含旧触发词 | 不因缺旧关键词一概拒绝；未审状态保留 |
| QN04 | 同一规则对应两个不同误解 | 结构允许，错误理由交内容审查 |
| QN05 | 选项换序／换文／答案换键 | 内容版本变化被识别，旧选项映射不能自动复用 |
| QN06 | 来源或讲义版本变化、同 ID 换内容、引用不存在 | 摘要／引用冲突，不默认为仍有效 |
| QN07 | 两种模式混用、错题型、多答案、重复 ID、空解释 | 明确结构错误 |
| QN08 | 未知字段、重复 JSON 键、超限、多字节边界 | 拒绝或有明确完整输入规则，无静默忽略和截断 |
| QN09 | 相同规格渲染实际变式请求 | 结果稳定、包含必要规则／例外／目标，与所检查规格同源 |
| QN10 | 定稿提取及规范化 | 全部实质字段保持一致，没有模型调用或内容改写 |

Q1 产物：代码／Schema／样例、定向测试、接口核对、实际命令与输出、输入文件摘要、验收结论和下一步。建议证据目录 `docs/design/evidence/learning-question-q1/`。构造夹具只证明所测性质，不是语义判定器效果实验。

## 3. Q2：受管生产与版本／交接接线

前置：Q1 通过。E1 的整书完成与受管编辑共用一套契约，不重复做；若 E1 尚未完成，允许先验收独立就绪课件夹具中的题目能力，但“完整新课交付”必须显式记未通过。

按依赖实施：

1. **窄上游写入能力**：指定草稿 quiz、revision 与并发保护、结构校验、事件、持久化和失败恢复；定稿路径提供模型调用计数为零的依据。
2. **Production＋CLI**：定稿 publish-quiz，变式 prepare-quiz 的规格绑定；复用请求冻结、同 ID 幂等、unknown／reconcile、预算与数据外发门禁。
3. **准备链与原生入口**：新操作必须能生成并核对有效步骤审查；遗漏 binding／关闭策略／旧 regenerate 路径不能让受控活动静默降级。保护实际入口，不只测辅助函数。
4. **I4／I5**：生成最终题摘要，保存必要附件，实际内容审查、采集、接受、当前漂移检查、交接打包、离线校验及恢复都可验证绑定。保持旧快照与旧包字节不变；老包按旧边界读取，新必需附件缺失必须拒绝，未知新版本不能静默接受。
5. **安装与文档**：补丁身份、能力检测、安装与恢复清单、应用操作说明及错误诊断。缺补丁在发送前报错。

### 必须覆盖的集成验收

| 编号 | 验收要求 |
| --- | --- |
| QI01 | 通过真实项目 CLI／Production 及已打补丁的隔离 HTTP 实例发布定稿，回读全文与摘要一致；模型调用为零 |
| QI02 | 相同请求重放、相同 ID 不同内容、旧 revision、并发写入、响应丢失分别有正确结果；unknown 不重复发送 |
| QI03 | 错页／错块／非 quiz、已 I4 绑定或已学习课程的原地替换被拒绝；替代活动保留旧记录 |
| QI04 | 来源／规格／步骤审查在冻结与真正发送之间变化被拒绝；尝试省略规格或走原生重生成不能产生可继续接受的旧绑定 |
| QI05 | 变式请求确实传到 QuestionPipeline 的真实提示构造路径；用确定性假提供方观察，不调用真实模型 |
| QI06 | 模拟目标偏移、格式失败、修复失败均不得被当成合格内容；实际修复上限与记录一致 |
| QI07 | 只有结构通过但未内容审查、块 ready 但整书未就绪，都不能首次 I4 接受 |
| QI08 | 题目／解析／来源变化令旧审查失效；I5 新包绑定闭合、离线能核对；删除必需附件或篡改被拒绝 |
| QI09 | 老快照、老包、无规格旧活动按原边界可读；新版缺能力不得忽略绑定；定向既有测试不回归 |
| QI10 | 停止／重启及独立恢复安装后题目、有效绑定与原作答保持；未经核实的中间失败不假报成功 |

HTTP 验收必须说明使用哪个实际安装／补丁版本及隔离目录。假模型输出只能证明调用链，不得标记为“真实生成质量通过”。优先定向覆盖 I3 生产、准备连接、I4 基线、I5 包与原生／运行时守护，再按实际改动扩大回归；不无差别重跑全部阶段。

建议证据目录 `docs/design/evidence/learning-question-q2/`。Q2 完成后必须区分：题目操作可用、整书交付可用、正式旧课未迁移、真实模型未验证。

## 4. Q3：受控试用与成本对照

前置：Q2 相关路线通过；新编课件需要 E1 与首次 I4；有效模型／资料外发授权与本次预算；调用可归因。不得以历史同供应商或历史“100 万”替代本次范围核对。

- 默认从冻结虚构材料的小批次开始，实际样本数、请求／修复上限和费用停止线先落盘；有授权才发送，未授权时停在实验计划。
- 对照当前参考模板与目标／来源增强输入，固定模型、来源、目标、题量和审查准则。小样本只报告方向，不声称统计普遍性。
- 同时验证定稿不改写、网页答题、重启回读和 I5 交接。定稿路径不调用模型；整个课程创建是否另耗模型要单列，不能混为零消耗。
- 独立于字面检查评价目标命中、场景正确、来源忠实、答案唯一及解释；将所有失败／修复调用计入总 token。
- 以现有账本为唯一累计依据，未知计量标 unknown，不把字节、耗时或请求次数冒充 token。发现来源偏离／答案歧义就退回，不为提高通过率放松审查。
- 如果新方案未改善质量或成本，不自动加量；保留样本和失败，给出下一处具体修改，再决定是否补测。

建议证据目录 `docs/design/evidence/learning-question-q3/`。完成只说明所选材料、模型和样本范围的运行结果，不代表教学成效或掌握认证。
