# 课程受控扩展与适应性学习修复方案

> 公开设计摘编：保留通用契约与方案；历史验收、用户反馈、运行记录及本地素材不随仓库发布。设计条目不代表部署或验收完成。

## 5. 改进原则与推荐方案

采用 **“原生入口＋受控追加＋分级审查”**。原课程和作答保留，学习补充可立即使用；普通内容写入仍受保护。小范围纠错优先追加勘误或局部替代修订，只有目标与目录显著变化时才派生整门课程，不将个人笔记修改套用课程版本规则。

### 5.1 与 DeepTutor 原功能的对应关系

| 原入口 | 继续复用的能力 | 新接线及持久化语义 |
| --- | --- | --- |
| 插入区块→文本、提示 | 原区块生成器、渲染组件 | 根据当前页／选区生成新块，通过扩展提交后直接保留 |
| 插入区块→测验 | 原测验组件、作答与反馈 | 受管生成新题，新块／新题身份，原作答保留 |
| 插入区块→深入学习 | 原推荐主题生成器、主题卡片 | 先生成并保存建议块，点击主题再创建子页面 |
| 点击深入学习主题 | 原子页面模型、父子导航与展示 | 候选生成后统一提交章节、子页、父链接及主题映射 |
| 补充练习 | 原提示＋解释＋较简单测验的组合 | 整组候选生成与提交，题目走扩展出题校验，允许失败恢复 |
| 用户笔记 | 原笔记区块、编辑组件 | 作为用户资料直接保存和编辑，不承担教学审查含义 |
| 保存划选 | 原 learning-captures 链 | 保持独立，不强制转成课程区块，不混入课程发布权限 |
| 时间线、闪卡、图示、交互、动画、代码 | 原各类型生成器与渲染组件 | 按类型逐项验证接入；尚未支持的选项明确禁用并说明原因 |

调用关系固定为：**原按钮 → 经身份校验的受管扩展操作 → 适配原生成器生成候选 → 检查及提交 → 原组件展示**。原 `insert_block()`、`create_deep_dive_subpage()` 等若内部直接写正式内容，应提取／适配生成能力，不直接绕开屏障执行整段旧写入。对未受管课程保持原行为回归，受管课程由服务端依据 Book 的真实状态选择规则，不能由客户端自行声明是否受管。

先恢复截图中的原功能与使用路径。“解释一下”“举个例子”等便捷入口可以后续复用同一操作，不是本轮前置条件，不新建另一套课程、展示或学习状态。

### 操作矩阵

| 操作 | 目标行为 | 历史处理 |
| --- | --- | --- |
| 阅读、作答、进度保存 | 保持现有行为 | 原记录继续有效 |
| 用户笔记／保存划选 | 直接保存个人资料，允许个人编辑 | 原课程正文不变，不伪装成课程审查通过 |
| 插入生成区块 | 检查通过后直接保存为学习扩展 | 标记 AI 生成、未经正式内容审查 |
| 深入学习 | 创建独立子页面 | 父页面及原正文保留 |
| 补充练习 | 新题块、新 question ID | 旧题和旧作答保留 |
| 修改既有正文／答案 | 追加勘误或有替代关系的局部修订 | 保留旧版本及旧作答，正式替代内容重新审查 |
| 打开已有扩展 | 直接读取 | 不重新生成、不重复扣费 |
| 普通未受管原生写入 | 继续拒绝 | 不形成绕过通道 |

### 核心判断

- **追加不等于修改历史。** 新内容必须有独立身份和证据。
- **旧基线不覆盖新增内容。** 首次基线仍描述原课程；扩展有独立身份和质量状态，升级为正式课程材料才需正式内容审查。
- **适应性学习不等于 Agent 自由写。** 用户现场意图仍须经过范围、来源、revision、预算和结构校验。

### 5.2 保存意图与审查等级

| 行为 | 是否保存 | 使用与审查边界 |
| --- | --- | --- |
| 点击插入区块／深入学习／补充练习 | 成功提交即自动保存；刷新和重启后可继续打开 | 先做确定性结构、来源绑定、范围及预算检查；生成内容标记“AI 生成，未经正式内容审查”，可以立即阅读或练习 |
| 普通聊天中的临时解释 | 沿用聊天历史保存；不自动转成课程区块 | 用户明确“保存到课程”时才创建扩展，复用已有回答字节，不为保存再生成一次 |
| 用户笔记／划选 | 沿用原保存入口 | 用户资料，非教学事实、非内容审查 |
| 将扩展纳入正式课程材料 | 记录对固定内容的正式审查 | 准备者／外部 Agent 按原内容审查职责核对来源、教学目标与题目，审查后才声明正式通过 |


在既有学习约定范围内继承约定与来源，系统自动填写工程字段。越出学习方向或引入新来源时才用简短提示确认范围；用户不需要手填 requestId、摘要或 revision。学习扩展和个人资料不自动进入正式 wiki／raw。


## 六、建议契约与实现接缝

以下是设计建议，字段名可在实现前按现有模型做最小调整，但不要绕过现有严格 schema 随意加字段。

### 6.1 受管扩展请求

每次扩展至少需要：

- 稳定 `requestId` 和 `extensionId`；
- 操作类型：插入内容、深入学习、补充练习；
- Book、目标页面／区块及当前 expected revision；
- 用户实际意图、主题或练习目标；
- 当前准备绑定、来源版本及生成／发布模式；
- 与当前学习范围和首次基线的关系；
- 操作者、入口、生成身份和用量证据；正式纳入时另附实际审阅证据，未审扩展不得伪造该字段。

普通页面编辑请求不得仅因携带一个布尔 `allow_extension` 就获得权限。扩展语义必须能校验到具体目标与内容。

复用原认证、Book 归属解析和编辑权限，新增操作仍须服务端授权。请求摘要固定操作、目标、来源／上下文摘要、意图、难度和生成参数；界面刷新、双击和超时保留原请求身份。相同 requestId＋相同摘要返回原状态／结果，改输入返回冲突。

跨请求的已有结果定位使用父页／选区、操作、目标、难度、来源版本等有效条件，不将主题字符串作为永久唯一键。“打开已有”不调用模型；“再生成一份”由用户明确发起新请求，可引用原扩展，产生独立身份并计费。服务端负责查重与并发协调，不能依赖前端按钮禁用。

### 6.2 存储与事务

复用现有文件存储、请求记录和作者 journal 的持久化方法，不新建通用事务平台或独立学习状态库。扩展提交边界从当前 Book／Pages 扩展到实际涉及的 spine、新页面不存在态及响应。

**每次扩展只能有一份权威扩展提交记录**，统一记录本次 Book、spine、全部受影响 Page 和响应的 before／after、requestId、摘要与状态。不得把“新增题块”和“发布新题”分别交给旧作者 journal、旧题目 journal 独立提交，再据各自成功推断整组成功；旧接口和旧 journal 继续服务首次成课，不能覆盖或回滚扩展的更新 revision。

一份权威记录意味着只有一个提交结论，不要求把所有内容塞进一个大 JSON。记录可引用具备摘要、归属与大小边界的不可变附件；只保留本次受影响对象的恢复材料，不为追加一块复制整书。附件、回执等不能各自产生独立提交真值。

普通 GET、原生写入、作者写入和题目写入必须经过同一个扩展稳定性屏障。启动恢复必须纳入扩展 journal，并明确扩展、旧作者和旧题目恢复的执行顺序、统一协调及加锁顺序；任何未决扩展都不能被另一套恢复流程静默忽略。恢复只按原 requestId 和摘要进行，疑似额外编辑拒绝。

唯一协调入口按实际部署／所有者／Book 作用域串行化短提交与恢复，不能按裸 Book ID 混用不同用户目录。新旧提交进入同一协调入口后再调用内部校验／持久化方法，禁止持有旧 journal 锁再反向申请扩展锁。实施前交付实际锁顺序表和调用关系；启动先检查新旧 journal 的终态与前后关系，对同一 Book 多个互相无法解释的未决写入停止恢复，不靠固定先后顺序强行覆盖。

执行分为两步：

1. **候选生成**：在请求专属目录保存意图、进度、完整生成结果和计量引用，该目录必须位于正式 pages 枚举范围之外。生成期间不改正式 spine／父链接、不暴露空题；用户继续阅读原内容、笔记和作答。
2. **短提交**：结果落盘并完成检查后，在协调锁内重新读取最新 Book／spine／受影响 Page，核对来源、目标、expected revision 和权限；候选只表达本次新增内容，将允许的增量应用于最新对象后，才形成权威记录的最终 before／after 并提交。禁止用生成开始时的整页快照覆盖最新 Page。只有这段未稳定提交才使用内容读取屏障，不将整个模型等待时间变成整书不可读时间。

深入学习提交边界至少覆盖：

- spine 的 before／after 与合成章节；
- 子页面，包括提交前不存在态；
- 父页面链接和主题映射；
- Book 页数、章节数与 revision；
- 实际响应。

补充练习的新块、提示、解释、新题及 Book revision 也由同一份权威提交记录判定全有或全无，不能留下可作答的空题或把部分生成当成整组成功。个人学习进度不纳入内容 before／after 回写，恢复不得覆盖生成期间新增作答。

**笔记不能只按 Progress 处理。** user_note 位于 Page.blocks，个人编辑必须与同一 Page 的短提交串行，或返回冲突并保留草稿；learning-captures 则走原独立存储链。生成期间新增／编辑的笔记在短提交重新读取时保留，无法安全应用增量则返回冲突并保留候选，不要求本轮实现通用合并。存在未决整页提交时，不允许新 Page 笔记写入绕过屏障。

只有权威记录进入稳定终态后才能解除相应写屏障。重启跳过已提交历史记录的重复回写，不得因重验旧 afterPage 摘要而覆盖后来合法笔记或较新提交；对未决记录的实际页状态若不能归为已知 before／after，保持 uncertain，不强行恢复。合法笔记变化和受保护正文变化必须按第 6.5 节身份／位置规则区分，不能只凭 type=user_note 忽略差异。

各阶段读写行为固定如下，不能以返回半提交快照换取可用性：

| 阶段 | 阅读原课程 | 保存作答／笔记 | 课程内容写入 |
| --- | --- | --- | --- |
| 候选生成 | 允许读取原稳定内容 | 允许 | 只能写请求专属候选 |
| 短提交 | 受影响 Book 的整书读取不得返回混合快照 | 与提交串行，或返回明确可重试冲突；作答按原 submission_id 重试，笔记保留草稿，不得静默丢失 | 只能由扩展协调器执行 |
| 崩溃恢复 | 受影响 Book 在恢复前不可返回半提交，其他 Book 不受影响 | 已有作答、user_note 和划选不得回滚；未决 Page 的笔记写入受屏障保护，其余记录按同一稳定性规则明确返回，不得假装成功 | 只恢复原请求，不换 ID、不重新生成；不把历史已提交页图像重写到较新页面 |
| revision 冲突 | 继续读取当前稳定内容 | 允许 | 保留候选并返回冲突，不改写原请求语义 |

请求状态至少明确 requested／generating／generated／committed、failed／uncertain。候选与正式提交分别保存：完整候选可用于恢复提交；已发送但生成结果不完整的请求保留 uncertain，不保证所有中断都能自动完成，不自动重发模型请求。

生成结束遇 revision 冲突，保留候选并返回冲突，不静默修改原请求。再次提交用显式关联的新请求，在核对目标和来源仍有效后复用候选字节，不为提交冲突重新生成。

沿用 runtime 异步任务锁及 worker／in_flight／generation 协调；同步线程 RLock 不代替异步任务互斥，不跨模型 await 长期持锁。当前支持单本地服务进程，多标签请求需要验收，跨进程多写者另列范围。半提交恢复期间只阻断受影响 Book 的必要内容读写，不把它误报为预算不足或教学失败。

### 6.3 深入学习

复用上游子页面模型和生成器，不另建 Agent 工作流。需要补充：

- 用户主题和父页面绑定；
- 来源及预算门禁；
- 实际生成身份与用量；
- 生成后结构检查和独立内容审查状态；
- 相同请求可靠幂等，已有主题按实际条件定位并直接打开；
- 新增子页面的独立内容身份、未审／已审状态和增量证据关系。

不得把父页面首次基线描述成已覆盖新增子页面。

菜单“深入学习”生成建议块与点击主题生成子页为两个请求，分别记录用量。子页生成复用原模型、规划器和渲染组件，但规划器允许输出的块类型必须显式限定；其中 quiz 必须走扩展题目链，未知或尚未接入的类型不能借整页编译自动发布。

### 6.4 补充练习

- 新题块和新 question ID 是强制条件；
- 练习目标可来自当前页、用户现场需求或实际作答观察，但不能把客户端分数直接升格为掌握判断；
- 定题／变式复用既有题目规格、来源／讲义绑定和结构检查；正式审查采用第 5.2 节等级，不要求普通现场练习等待全套正式发布；
- 原题作答不迁移、不改写；
- 新题需有独立题目生产检查、质量状态和不可变内容关系；
- 响应未知时只按原请求对账，不重新生成。

新增扩展生产操作，分别接通项目 `Production` 和服务端目标校验。首次成课旧入口继续拒绝基线后发布；扩展入口只允许新增目标，并校验受保护内容未被修改。不清除学习进度、首次基线标记或题目绑定来复用旧接口。

普通现场练习使用有界目标与来源生成规格，复用现有确定性题目校验；未完成人工／外部 Agent 的正式审查时明确记录未审，不伪造现有 preparation-review。模式须在新契约中显式区分，旧正式发布 schema 的 required review 保持不变，禁止“缺审查即自动按未审发布”的隐式降级。

### 6.5 插入区块

恢复用户可见的插入能力，但不开放任意 payload 或任意文件写入。按块类型复用真实生成器或已审正文，明确哪些类型允许直接保存、哪些需要生成、哪些暂不支持。

“保存划选”、笔记、作答和进度与课程内容扩展分别处理，不能共用一个权限结论。

用户笔记即使复用原 user_note 块展示，也要有明确的个人内容身份；个人编辑／隐藏／删除不等于改写原课程正文。原始课程内容及其基线投影不因个人笔记变化而被任意排除，允许变化的类型、位置和归属必须可验证。

未审 AI 扩展块允许通过受管操作删除或重生成，不能再次撞到原生 `question_content_protected`。删除仅移除目标块并保留完整提交证据；删除深入学习建议块时，已生成的子页和父页链接继续保留。重生成保持块身份与既有子页映射，使用候选、原请求重放和关联重试，不在正式页面上直接运行原生生成器。原正文、原题及扩展 quiz 不在本轮删除／重生成白名单内，避免破坏题目和作答证据。

上游整书重建会删除全部 Pages 并重置 Progress，因此受管课程不得原样开放；整页重生成、移动、类型转换和原正文编辑等未开放入口应在界面收敛，服务端仍保留保护。需要替换整门课程时沿用派生新课程流程，不原地清空学习记录。

### 6.6 原基线、扩展及 I5 的关联

现有 I4 按整本内容身份比较，I5 又使用整书一致性判断旧题关联，追加后不能仅靠“旧包字节没变”宣称兼容。必须同时定义并校验：

1. **原受保护内容一致性**：以首次固定快照为依据，旧页／旧块／旧题的内容、选项顺序、来源和身份仍一致；旧块相对顺序保留，不能只检查旧题题干。
2. **完整有序增量链**：从首次基线投影开始，按内容提交序号和前一提交摘要重放全部合法扩展，结果必须与当前受保护内容投影完全一致。每个新块／子页、父链接、主题映射、spine 章节、块位置和计数变化都须对应权威提交及不可变摘要，并记录主线／可选归属和未审／已审状态。扩展记录缺失、重复、分叉、声明的操作顺序错误、内容序号断档、未授权删除或无法解释的差异均须 unknown／拒绝；隐藏／归档不能被解释成内容从未存在，也不能靠忽略所有新增字段通过检查。
3. **分题关联与审查分离**：旧题按首次基线及完整增量链核对，新题按所属扩展的不可变内容、来源和提交核对。新版契约必须分别表达内容关联状态与正式质量审查状态，不能只凭 `baseline_consistent` 把未审新题暗示为首次正式审查通过。新增内容在审查前产生的作答不因事后审查而被追认为当时已审，旧题历史判断也不被新扩展反向改写。

保留完整原始观察，不改写首次绑定、历史 I5 包及历史判断。新 I5 必须携带可离线重放和校验的有序扩展清单、权威提交证据、内容、来源关系、逐题关联与实际审查记录，不能只带新增块的最终快照。无法解释的差异继续 unknown／拒绝，不能简单放宽整书摘要门禁。原 cooperative、submissionContent=unknown 和“非掌握评估”边界保留，不虚构提交时版本证明。

涉及快照／交接包结构变化时显式演进契约及读取能力，保留旧格式读取，不原地改旧包，不让旧读取器静默忽略新字段或降级解释。本节需在实施前形成字段差异、增量重放规则与对应验收样例。

#### Book revision 与内容提交顺序

| 字段语义 | 职责 | 校验要求 |
| --- | --- | --- |
| Book revision／expected revision | 原 Book 的乐观并发令牌及实际操作前后值 | 提交前核对，不假定每个数字都对应一次已成功的内容提交 |
| 内容提交序号 | 首次基线之后合法内容提交的连续顺序 | 在同一权威记录中递增，候选生成／失败／冲突不占已提交内容序号 |
| 前一提交摘要 | 绑定唯一前驱及所属 Book／基线 | 第一条绑定首次基线，后续绑定前一稳定提交，检测缺失、重复和分叉 |
| 前／后受保护内容摘要 | 绑定一次合法增量的输入与输出 | 前后连续且实际差异符合操作白名单，最终与当前受保护内容一致 |

字段名和 schema 在接口准备中冻结，上述语义不可混用。当前上游会在执行部分操作前领取 Book revision；不得仅凭 Book revision 跳号认定扩展链损坏。实施须列明内容提交、个人笔记、作答、划选、暂停／恢复和失败请求各自是否改变该令牌。非内容操作不得改变受保护内容摘要；能分类的令牌变化不作为内容链断档，无法解释的内容变化仍拒绝。

链按声明的序号和前驱关系重建；目录枚举、附件文件名或清单的物理存放顺序不是内容顺序。更换存储顺序但保持同一合法链应可核验，篡改声明的前驱／序号／操作关系必须失败。记录保留实际 Book revision 边界用于诊断，不以它替代内容链。

#### 验证频率与容量

完整重放用于 I4／I5、独立验收，以及启动／恢复中需要证明内容关系的边界；普通 GET 检查本 Book 未决提交和读取窗口稳定性，不强制每次打开页面重放全部历史。该轻量检查不能宣称完成了正式全链内容审查；需要内容关联证明的操作仍必须完整核验。

首轮采用有界全链验证，实施前明确提交条数、附件总字节、导出包大小及重放工作量上限，超过时返回容量诊断，不截断历史再自称通过。无需本轮建设事件数据库、快照平台或全局事务调度器；后续加速缓存只能是可重建、绑定已验证链头的派生数据。证据附件默认不进入模型上下文，不将离线校验材料转成每轮提示词。

### 6.7 进度、勘误与单次预算

- 主线必学与可选扩展分别计数，追加可选子页不改变已完成主线的口径；阅读访问不自动等于掌握。默认保留原 Progress 为学习记录真值，新增可选归属从内容关系派生，不另建一套可写进度。
- 用户可以隐藏／归档扩展；保留原内容、题目和作答，不因界面移除而删除证据。勘误保留原文与被修订目标，新旧题答案不能互相覆盖。
- 单次动作先定义最大块／页／题数、模型调用数、上下文与输出上限及生成轮数。首轮文本一块、单次测验一题、补充练习一组、深挖一个子页；深挖与补充组合的总调用上限须在实现契约中给出并校验，不开放递归深挖和自动连续补题。
- 只发送当前相关页、选区、练习目标和必要来源，默认不重发全书与全部聊天。全部调用及失败估算沿用现有账本，保留 80 万暂停线、100 万累计上限；本方案不产生新的真实调用授权。
- 预算暂停阻止后续模型调用，原有阅读、个人笔记、作答仍可使用。若当前运行守卫会停整个服务，实施时须明确调整生成准入与服务存活的职责并做回归，不能只靠前端隐藏按钮。


## 七、前端与用户体验

- 保留现有插入区块入口，但受管课程调用扩展入口，不再直接撞普通保护屏障。
- 首轮支持文本、提示、测验、深入学习、补充练习和用户笔记；其余菜单类型按实际能力禁用并显示说明，不能点击后才报通用保护错误。保存划选保持原独立入口。
- 深入学习允许从建议主题或用户明确输入的主题发起；已有扩展直接打开。
- 补充练习显示新题与原题的关系，不覆盖旧作答。
- 扩展生成中只锁定相关操作，不把整本课程误报为不可学习。
- 原入口生成成功即保存，下次打开可见，不再弹第二次保存确认；完成后提示查看，默认不自动跳离正在阅读的位置。
- 原渲染组件承载扩展，本轮提供生成来源、未审状态、打开已有和再生成等真实可用能力；隐藏／归档按第 10.2 节边界处理，不引入重复课程列表、第二套播放器或占位按钮。
- 失败时使用中文说明和可操作下一步，错误码放详情；结果未知提供“检查结果”，不得引导新 ID 重试生成。
- 新增内容的审查状态应可见，不能用旧 I4 通过标记遮盖扩展未审事实。
- 前端向系统传递用户意图即可，来源、请求 ID、摘要、revision 和关联由接线负责；不要求用户理解 I4／I5 才能学习。


## 八、验收方案

### 8.1 契约与负例

- 未带扩展绑定、错误 revision、来源变化、超范围操作继续拒绝；
- 普通原生写入仍返回内容保护错误；
- 修改既有正文／旧题不能伪装成追加；
- 空正文、空题、未知块类型和无效引用保持拒绝；
- 当前已有学习进度不能再成为所有扩展的通用阻断条件。
- 原身份、归属与权限校验保持有效；受管状态由服务端读取，客户端不能伪造模式或审查等级绕过规则；
- 相同 ID 相同输入返回同一结果，相同 ID 改输入冲突；刷新、超时、多标签同时提交不重复生成；
- 未审模式必须显式声明并使用对应契约，不能通过缺失正式审查字段隐式降级；
- 原首次成课接口仍拒绝基线后写入，扩展操作不依赖清空进度或旧基线。
- 同一次扩展不得由两套旧 journal 分别提交；人为留下新块／新题分属不同提交、混合 revision、只有一方恢复成功的状态时，普通 GET 不得判稳定，启动恢复不得宣布完成，旧恢复也不得覆盖扩展结果。
- 候选生成期间允许原阅读、作答和笔记；短提交及崩溃点注入期间不得读取混合内容。并发作答只能串行保存或按原 submission_id 安全重试，不能重复、丢失或被恢复覆盖；笔记冲突须保留用户草稿。
- 生成期间新增或编辑 user_note 后提交扩展，必须保留笔记或返回明确冲突并保留候选；短提交期间的笔记写入须串行或保留草稿；扩展成功后修改笔记再重启恢复，不得回写旧笔记。另行验证 learning-captures，不以其通过替代 user_note 检查。
- 从首次基线重放到当前内容时，扩展记录缺失、重复、分叉、声明顺序错误、内容序号断档、未授权删除及伪造隐藏均须失败；仅每个新增块各自有记录但整链不完整，也不能通过。
- 合法非内容操作导致的 Book revision 跳号不应单独导致内容链失败；候选／失败请求不占已提交内容序号；调换附件／记录的物理存储顺序但保持合法前驱关系仍可核验，篡改序号／前驱则失败。
- 普通读取不执行全历史重放；I4／I5 的完整验证不能被轻量屏障检查冒充。超过明确容量上限返回诊断，不截断证据、不误报完整通过。
- 未审题的内容关联与质量审查状态必须分别通过校验，不得仅显示 `baseline_consistent` 就继承首次正式审查结论。

### 8.2 深入学习

- 从真实父页面创建子页面并正确回链；
- 父页面正文和旧题不变；
- 菜单能生成建议块，点击主题能生成子页，已有扩展打开无新生成；
- “再生成一份”使用新身份和实际计量，不被同主题永久查重吞掉；
- 多主题互不误绑；
- 目录编辑不误把合成章节当普通顶层章；
- 生成期间阅读／作答正常；短提交各崩溃点无半提交读取，完整候选恢复不重新调用模型，结果不完整保留 uncertain；
- 父链接、主题映射、spine、page_count／chapter_count、子页和响应恢复一致，不覆盖并行新增作答；
- 启动 `recover_all()` 能发现或恢复扩展未决状态，所有普通读写使用同一稳定性结论；
- 新页面有独立身份与审查状态，首次基线不虚假覆盖，可选子页不增加主线必学负担。

### 8.3 补充练习

- 新题块和新 question ID 成功追加；
- 旧题、旧作答、首次基线和历史交接包不变；
- 选项顺序、答案、解释和来源绑定可回读；
- 同请求幂等、改内容冲突、未知结果只读对账；
- 结构／生产检查与正式审查状态分别完整，未审题可以练习但不冒充正式已审；
- 原组合中的新块、提示、讲解、新题及 Book revision 由一份权威提交记录全组提交，任一步失败不留下半组可作答内容；
- 生成结果成功提交即保存，刷新／重启仍存在，无须第二次保存。

### 8.4 必须先完成的纵向闭环

以真实路由和实际存储完成：**首次基线及旧题作答 → 经原按钮追加讲解／新题 → 阅读和新作答 → 导出新的 I5 → 离线核验 → 重启再读**。模型与来源可先用明确标记的替身，不能手工置 ready、直接 save_page 或伪造审查来替代本轮接线。

分别断言：旧内容仍可关联、完整扩展链可重放到当前内容、新题按自身内容关联、未审身份如实保留、旧包和旧记录未改。额外篡改旧块、添加无扩展记录的链接、删除一条中间扩展或篡改声明的扩展前后关系都必须被发现；事后审查不能重写先前作答的质量状态。只回验旧包或只枚举当前新增块不足以通过。

补充用户路径检查：截图中的原入口可发现且按类型工作；用户笔记可编辑；保存划选不被强制发布；失败不打断继续阅读；超预算阻止新调用但保留现有学习。再核对每个模型调用、失败估算、组合总用量与原累计账本。

### 8.5 回归与真实边界

先整理验收用例，再实现，验证分成三类：

| 类别 | 实现前 | 实现后 |
| --- | --- | --- |
| 旧行为缺口／已知缺陷复现 | 保存真实入口操作及实际失败；能在旧实现合理注入的覆盖／中断问题保存行为证据 | 同场景验证修复，不以换入口或删门禁替代 |
| 新功能与新事务故障注入 | 给出预期、接口样例及故障点；新接口不存在时明确未实现 | 验证正常闭环和跨 journal、半提交、增量链等负例 |
| 原有保护性回归 | 执行现有 E1／Q3／I3／I4／I5 相关检查，保留原本已通过的拒绝行为 | 全部保持通过，不要求旧实现先变红 |

不将新接口 404、ImportError 或字段缺失作为旧混合提交缺陷已复现的证明；不为制造旧实现失败另做临时事务实现。仅在新结构中成立的故障注入于实现后验证。全部新旧检查通过才可交独立复审，既有检查全绿不能替代新增行为验证。模型、认证和索引可用替身做结构测试，但必须逐项标明。

真实验收最多先做一个小型深入学习或补充练习，核对实际内容、用量和重启恢复；不能把合成结果写成真实教学质量或用户掌握证明。

## 十、范围与停止条件

### 10.1 本轮必须完整交付

- 恢复原入口的文本／提示插入和受管新题，完成旧题作答后的追加、继续作答与新 I5 纵向闭环；
- 恢复整组补充练习，以及“生成深入学习建议 → 点击主题生成子页”的两步链，不能把深入学习留成只有设计的后续项；
- 保留旧课程、旧题、旧作答和首次基线，完成统一扩展事务、完整增量链、崩溃恢复、离线核验及原入口用户体验；
- 用户笔记、保存划选、预算暂停和未支持类型的禁用说明按第七、八节回归。

实施可以按“插入与新题闭环 → 整组补充练习 → 深入学习两步链”分阶段验收，但阶段完成不等于整项任务完成，最终部署必须覆盖上述用户明确需要的功能。

### 10.2 本轮只保留数据语义，不扩展成完整新产品

以下能力只需保证新契约不伪造状态、不阻断后续实现，不要求本轮建设完整管理界面或独立工作流：正式审查升级、勘误管理、普通聊天转课程、扩展隐藏／归档、整门课程派生。若本轮提供对应按钮，则必须完成其最小真实行为和证据记录；否则不展示尚未实现的入口，不以占位按钮冒充交付。

本任务不包含：

- 重写 DeepTutor 或重建通用 Agent 工作流平台；
- 让模型自由执行任意工具；
- 自动推断用户掌握程度；
- 将全部课程内容迁移到新存储；
- 无限制真实模型试验。
- 首轮同时开放所有块类型、重建课程播放器或引入另一套学习状态；
- 自动把即时扩展纳入正式知识库、自动给出正式审查通过或掌握结论。

出现以下情况应停止对应写入或生成并保留证据：未确认的来源／范围变化、revision 冲突、扩展身份冲突、额外编辑、事务不确定、未结算调用、预算暂停、真实内容质量未审而试图宣称正式通过。内容未审本身不阻止第 5.2 节规定的现场学习使用；失败不自动升级为整本课程不可学习。
