# 知识准备链方案与实施任务书

> 公开设计摘编：保留通用契约与方案；历史验收、用户反馈、运行记录及本地素材不随仓库发布。设计条目不代表部署或验收完成。

## 2. 架构与职责

```text
用户提供资料／明确整理意图
          ↓
外部 Agent 工作区：原文留存、范围说明、既有知识检索
          ├─ 知识路线：版本绑定 → Claim/Evidence → 比对／冲突 → 核验报告
          └─ 学习路线：背景／学习证据 → 差距分析 → 用户认可学习约定
                             两路在课程准备处汇合
          ┌──────────────────────┴──────────────────┐
学习约定＋已审知识 → 学习投影／出处映射       已审知识 → Wiki 候选预览
          ↓                                          ↓
现有 learning_book → DeepTutor             既有维护审查、授权与 Executor
          ↓                                          ↓
实际课件审校 → 学习前基线 → 用户学习      pending_review → 用户 approve
          ↓
用户要求回顾／约定检查点 → 只读导出 → 外部 Agent 回顾／提出新候选
```

知识准备与学习规划按各自输入推进；针对课程目标的深度研究须等待学习约定，用户另行要求的资料核验可以独立进行。用户如果明确要求“先学完再入库”，将顺序作为本次任务约束记录；不将它升级为所有知识维护的通用前置。

知识准备是可调用的应用能力，不建设常驻通用 Agent、第二套任务循环或新数据库平台。外部 Agent 负责语义提取、检索补证和判断；确定性程序负责字节、引用、版本、覆盖、状态和边界校验。内部模型能力强弱不改变职责。

| 对象 | 唯一负责的状态 | 不得据此推出 |
| --- | --- | --- |
| 原文与正式 wiki | 原文版本、已接受的来源摘要和知识关系 | 已接受知识永远正确 |
| DeepTutor | 课程、原始作答、进度与会话 | 事实已核验、用户独立掌握、可正式归档 |
| 项目 learning_book | 生产回执、内容基线、只读学习证据 | 第二份可编辑课程或进度 |
| 维护 Runtime／Executor | 现有任务、授权、审查和正式文件事务 | 绕过宿主身份限制或用户 approve |

工作区与正式 raw／wiki 分开；同机共享目录是部署便利，不等于跨文件事务。源路径变化不改知识身份，正文变化必须形成新版本。正式页分类目录递归读取，不把完整路径视为语义身份。

### 2.1 贯穿流程与最小状态

| 步骤 | 输入／输出 | 实际推进者与退出条件 |
| --- | --- | --- |
| 暂存与分流 | 用户材料 → 原件、来源记录、整理意图 | 外部 Agent；没有学习意图也可结束于参考／暂缓 |
| 背景与规划 | 相关 wiki／学习证据 → 差距观察、学习约定 | 外部 Agent 引导用户；仅成课路线要求范围获得认可 |
| 知识核验 | 原件、旧知识 → 知识包与核验观察 | 外部 Agent 和确定性校验；缺证留 needs_evidence，缺审留 needs_review |
| 投影与编排 | 已审范围＋有效约定 → 学习文本、出处与目标覆盖 | 外部准备者；优先复用已有正文，不无条件重复自动生成 |
| 生产与发布 | 资料包 → Book、实际内容审查、I4 基线、入口 | learning_book 与 DeepTutor；生成 READY、审校及基线分别记录 |
| 学习与局部补讲 | 固定版本课程 → 阅读、作答、追问原始记录 | DeepTutor；不要求外部 Agent 常驻，不自动宣称完成 |
| 回顾与反馈 | 用户回顾请求／约定检查点 → 导出包、表现观察及未解决问题 | 外部 Agent 显式执行现有导出与校验；未结束也可导出 |
| 两类后续更新 | 表现观察／事实纠错 → 下次规划依据／知识修订候选 | 用户背景变化只影响规划；新事实须核验，不能因聊天回答自动入库 |
| 正式知识接受 | 受审候选 → pending_review → 用户 approve | 既有维护入口；学习结束不自动授权接受或归档 |

不设“系统整体通过”这一混合状态。分别保存学习约定状态、知识审校观察、课程发布证据、原始学习记录和正式维护状态，通过身份与摘要关联。needs_evidence／needs_review／rejected／reviewed_for_scope 是条件观察，允许退回补证或修订后产生新记录，不是必须依次走完的单线阶段。

K0 固定一个最小交付封装：关联学习约定（纯知识任务可无）、知识包、原文定位、核验报告、输入投影及目标覆盖；课程发布后追加独立生产／内容审查／基线回执引用。封装引用既有原件，不复制权威状态；来源、目标、投影分别变化时分别重验依赖。学习约定初次确认时尚可没有知识包；已审知识包也无需提前绑定某门课，避免循环依赖。


## 3. 最小知识准备流程

### 3.1 收资料与范围确认

收到链接或文件只暂存，不自动成课。明确整理意图后，外部 Agent 将材料分为重复、参考、待补充、知识候选和学习输入；同一材料可兼有用途。首个实现只接完整可追溯 UTF-8 文本，网络获取由宿主现有能力提供。

保留原件、来源规范地址、作者／发布方、获得时间、事件／发布／版本时间、可读范围、获取方式及失败信息。不能用搜索摘要代替全文；partial 材料只能支持可见范围，缺失部分不能成为确定答案。PDF／OCR 的真实输入身份不能通过改扩展名消失。

### 3.1.1 结合知识库制定学习约定

课程准备须先识别用户想解决的问题，再决定材料中哪些值得学。允许在约定前做有界的资料预览和相关知识检索，帮助用户发现方向；初始默认最多预览 3 份材料、读取 5 篇相关知识页，并明确本次时间／调用上限。预览不代替 ingest 所需的原文全文阅读或正式核验；超出后先收窄方向，不无限研究再让用户选择。未明确目标时，不展开面向该课程的深度研究、完整讲义编写或模型成课。纯资料暂存、事实核验及无需学习的知识维护不受此门禁阻塞。


| 可用依据 | 可用于课程规划的判断 | 边界 |
| --- | --- | --- |
| raw、来源摘要、Agent 生成或导入的知识页 | 相关资料可用、可能接触过 | 不证明用户读过或理解 |
| 用户自己的解释、实践记录、明确表示了解 | 可提议略讲或快速回顾 | 保留作者、时间、适用版本与判断理由，不自动成为独立掌握凭据 |
| 原始作答、独立实践等实际学习证据 | 在证据覆盖的目标和条件内调整难度与重复量 | 区分提示辅助、自评和独立表现；不能把选择题答对推广为整个领域掌握 |
| 用户当前明确表示遗忘、不会或希望重学 | 安排补讲或重新学习 | 当前意图优先于旧推测，原历史证据仍保留 |
| 无记录、记录不可读或版本过旧 | 熟悉程度 unknown，针对关键前置询问 | 无记录不等于不会，不强制从零开始 |

事实证据与学习者证据分别引用：论文／源码支持知识主张，用户作答／实践支持特定能力观察。一份材料可承担多种用途，但每个判断必须明确它实际证明什么。已有 raw／wiki 和 DeepTutor 原始记录仍是各自正本，熟悉程度只是绑定证据的规划观察，不另建一套可编辑掌握度库。

外部 Agent 先从 wiki/index 和局部相关页出发，结合用户同意使用的学习记录，记录查阅范围、页面／记录身份、摘要或版本、时间与未知项。没有可用学习记录时仍可规划，不能通过补造历史绕过不确定性。检索不要求全库扫描，也不默认将整个知识库、历史对话或作答发送给模型；实际使用遵守现有读取范围、隐私门禁和具体发送授权。

建议学习约定包含以下内容，字段契约由 K0 固定：

| 内容 | 必需说明 |
| --- | --- |
| 目标与方向 | 学完能解释、判断或完成什么；多个方向时说明差别并帮助选择 |
| 已有背景与依据 | 哪些可复用、哪些只是可能熟悉、哪些未知；引用相关知识和学习证据 |
| 本轮差距 | 新概念、变化、冲突和需要补齐的前置；为什么值得学 |
| 范围与排除项 | 必讲、略讲、选读、不讲；不可把所有检索结果塞进正文 |
| 时间与深度 | 单次学习时长及本轮总量的期望或上限、讲解深度；未知项明确列出 |
| 检验方式 | 与目标相符的练习或实践交付，不把访问进度当掌握证明 |
| 认可与版本 | 用户原始意图／确认依据、适用范围、版本及摘要；不得由 Agent 自报已确认 |


### 3.1.2 学习约定门禁、覆盖与变更


放行条件为目标、范围及量级可执行，关键前置已知或有明确补讲安排，确认／授权依据有效。未满足时只保留探索与草案。确认学习方向不等于同意新的外部数据发送、费用或正式知识写入。

课程准备和发布审查引用同一约定版本：从目标到所选主张、章节、练习／实践任务建立覆盖映射，记录未覆盖项、跳过依据及选读内容。事实核验门禁独立保留；用户想学某个方向不能使争议主张自动变为正确答案。知识包中未选入课程的内容不因此丢失或变成已学习。

DeepTutor 的提案／目录可展示这份约定的落地结果，不要求用户重复确认相同范围。现有 confirm-proposal／confirm-spine 操作回执不是用户认可的自动证明：若由外部 Agent 提交，必须回指真实用户意图或委托范围。结构字段齐全由程序检查，方向是否贴合、内容是否过量由准备者与实际用户反馈检验。


来源变化只使相关证据／投影失效，不自动撤销仍适用的学习意图；学习目标变更也不抹除已有事实核验。分别重验受影响绑定，不让整条链每次从头运行。

### 3.2 先查已有知识，再形成主张

检索从 wiki/index、相关来源页、关系字段及局部关联开始，必要时扩大。机械检索只产生候选；语义重复、支持或矛盾由外部 Agent 结合条件和版本判断。没有搜索命中不等于库中不存在。

记录实际查询、覆盖的目录／页面、选中与排除理由、读取版本及摘要。旧知识也必须回到可读证据；不能因已在 wiki 中就压过新的一手材料。结果至少区分 exact_duplicate、related、new、conflicting、insufficient，名称在实现契约中固定。

Claim 保留归属、适用条件与 evidence_status。Evidence 绑定原文版本、摘要、实际定位与摘录；程序核对定位及摘录是否匹配，语义审查核对它是否支持该主张。合法 JSON、有效 hash 和真实引用分别证明结构、字节与引用事实，均不单独证明结论正确。

### 3.3 来源依据与独立性

沿用原设计的三条独立维度：工具 T 说明获取机制的适用性；来源 S 说明对特定主张的证据角色；主张 I 说明核验强度。它们不合成一个网站信用分，也不以模型置信概率放行。

首个实现仅需来源目录的最小记录及每次核验观察：稳定来源标识、规范定位、来源类型、主题范围、时间／版本、获取状态、发现依据、状态及理由。新增来源可作有界调查线索；常规启用、主题扩展和关键裁决用途仍需留下独立复核依据。完整生命周期自动化与排序优化后置。

同一文章的转载、聚合摘要和 AI 改写不能计作多份独立佐证。记录引用／转载关系及可确认的共同上游；无法确认独立性就标 unknown，不能默认独立。两份独立资料若版本、对象或实验条件不同，也不能简单投票裁决。

### 3.4 冲突与核验输出

先判断是否为同条件互斥，再区分版本变化、定义差异、适用条件差异与真正未决冲突。每次解决必须保存依据、范围与判断者，不覆盖旧观察；新证据推翻旧结论产生新包版本及候选修订。

未决冲突不强行选赢家：受影响主张不能作为无条件教学结论或唯一标准答案；可明确呈现为争议。无关且证据充分的主张允许单独交付，必须显式分包并列出排除项，不能整包假装通过。

知识准备输出为按实际条件记录的观察：needs_evidence、needs_review、rejected、reviewed_for_scope。最后一项表示指定判断者在指定证据与范围下的审校，不是权威事实认证、维护 G3 凭据或用户学习证明。任何资料包内自报 pass 都不能赋予正式写权限。

### 3.5 两个独立消费者

学习投影：从已确认学习约定与审校范围挑选目标和主张，形成既有 prepare.json、完整文本及旁路映射。映射至少绑定学习约定版本／摘要、KnowledgePackage 的 package_id/version/digest、所选 Claim、Evidence、输入 artifact/hash、实际 intent、目标覆盖及排除项。单独封装学习约定、知识审校和投影审校，不把旧 prepare 会忽略的未知字段当作已校验，也不复制一套 Claim 事实库。来源映射精确覆盖实际上传来源，允许直接来源和外部编写讲义；知识包未选来源不强制上传，既有知识比较另有已读页字节依赖。

投影摘要必须与实际上传字节一致。改写若引入新事实、扩大条件或补充判分依据，要回到知识准备形成新主张／版本并重审；不能在生成正文时绕过核验。外部编写正文和 DeepTutor 自动生成都须对实际产物做内容审校，输入通过不保证输出忠实。

Wiki 候选：复用 compile_candidate／coverage 校验形成 preview，并对新旧页双向关系给出预览。正式接受继续走现有维护审查、授权和 Executor；归档仍需用户 approve。新原文如需进入 raw，使用现有 capture/import 能力及适用授权，不在 ingest 中私自登记或混入原批次。

学习并非所有知识入库的前置条件。哪些内容需要学习由用户意图决定；本轮不启用旧“独立理解验收后才可入库”的 L2 门禁。旧 required_objective 等协议如被复用，只保留 preview 语义，不用 DeepTutor quiz 代造 UnderstandingRecord、Assessment 或 Readiness。

### 3.6 学习回顾与纠错如何闭环

现有结果导出是显式调用，不是课程完成事件自动触发。当前产品无须常驻外部 Agent：用户说“回顾本课／今天所学”时，由外部 Agent 选择实际活动及允许读取的公开会话，调用 export-results、verify-handoff 并消费结果。学习约定可约定回顾时点，但没有触发器运行时不能声称已自动执行。未来增加网页按钮或 MCP 时仍调用同一应用操作，不先建设后台调度平台。


用户发现题目／知识错误时，先记录受影响的 book、page／question、约定与内容基线、来源及用户陈述。在未核清前不将相关题目结果用于新的能力判断；当前若只有人工工作单能提醒，就明确为工作约定，不能声称原生评分已被技术阻断。外部 Agent 回原文核验；确有错误形成知识包／课件新版本和必要候选，不让聊天中的新回答自动成为正式知识。

课程或资料被撤回／替换后保留旧记录及失效说明，避免用户继续依赖过时题目得出能力结论；原有内容基线和导出历史仍按原事实保存。重新发布复用有效来源和约定，重新核对变化内容，不复制造假学习历史。


## 4. 运行、预算与恢复

知识准备核心先作为普通应用模块，支持文件输入、显式操作和私有产物；不要求先建成常驻 Agent。需要持久维护调度、模型调用或正式写入时，复用 S1 的 Task／Step／Invocation 和既有 Executor，不新建 loop。私有解析、检索和导出不以严格 Native 认证为前置；正式操作只用当前已接入且满足其身份、审查与授权要求的入口。严格 Native 未通过的边界继续保持关闭，不能把私有分析通过当作它已通过，也不能把当前上下文自审变成可信 G3。

DeepTutor API 的模型调用仍由现有受管实例、usage.sqlite3 和累计预算控制。外部 Agent 的模型调用若由维护 Runtime 发起，走其已有 Invocation；若使用宿主自身模型且无可信用量，就记录 unknown。不能把外部 Agent 费用漏计成零，也不能让两套账本重复结算同一次真实调用；任何跨服务总额汇总仅是只读展示，不引入第二权威预算。

默认研究限额须在任务创建时明确：最多 3 份初始文本、10 个核心主张、每个关键缺口最多 2 次定向补查、最多 2 轮修订。数量只是初次实现的可配置保守默认，执行前冻结实际参数；达到限额仍有缺口则留待确认，不靠删主张掩盖失败。真实模型额度与发送范围沿用各自已明确授权，本课程的发送授权不自动覆盖其他新资料。

复用原文、核验结果和课程正文的有效版本，确定性步骤不调模型。主张粒度优先覆盖学习目标、关键条件、数字、冲突和判分依据；稳定背景归并表达，不为每个连接句单建审查任务。正文仍须完整审读，不能以“非核心”名义夹带新事实。时间与费用分别记录预览、研究、编写、审查、DeepTutor 生成和回顾阶段，unknown 用量照实保留；未经实测不报节省比例。

每一步持久保存输入摘要、实际结果和下一动作；外部调用未知先查回执，不自动重发或换 ID。重启可重放确定性校验，不能重置预算／修订次数。包版本不可覆盖；发布前重新核对源字节、旧知识依赖及审校绑定，变化则标 stale，并只使受影响的主张／投影失效。


## 6. 验收矩阵

在临时库执行以下样例，逐条记录 actual／expected、产物摘要和执行命令。确定性测试不调用模型；语义能力另用真实独立审查或人工复核，不以替身测试冒充效果证明。

| 编号 | 样例 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 完整新文本与库内相关知识 | 生成有定位的包、比对覆盖、学习投影与候选 preview，正式库不变 |
| A02 | 同一原文重复提交／移动分类路径 | 复用相同身份；不重复来源，不因路径变化捏造新知识 |
| A03 | 同 source/version 的正文变化 | 拒绝原版本覆盖；新版本经重新核验 |
| A04 | 新文与旧 wiki 同条件冲突 | 同时保留两边证据，不能凭旧页地位或多数票判胜 |
| A05 | 新版本修复旧行为 | 记录适用版本，历史结论保留条件，不能误判全部旧知识错误 |
| A06 | 三篇转载同一报道 | 记录共同上游，不计为三份独立佐证 |
| A07 | partial／不可读／截图中关键信息未提取 | 核心结论与标准答案阻断，缺口保留 |
| A08 | 摘录真实但不支持主张 | 结构检查可能通过，语义审查必须拒绝；记录两者区别 |
| A09 | 未决冲突加无关正常主张 | 正常部分显式分包，争议项不进入确定答案 |
| A10 | 审校后原文、旧知识或投影变化 | 旧审校绑定失效，不复用到新 payload |
| A11 | 合法包内自报 pass／伪造 reviewer 字段 | 不生成可信审查凭据，不授予正式写权限 |
| A12 | 投影／生成课文夹带新事实 | 新事实返回知识准备，不因课程 READY 放行 |
| A13 | 无需学习的正式知识候选 | 不伪造学习记录；走既有适用维护规则 |
| A14 | 外部调用超时、落盘前崩溃与重复执行 | 保留 unknown／原回执，重启不自动重发或清零次数 |
| A15 | 来源降级／证据被替换 | 标记受影响依赖，不删除原件或篡改旧学习证据 |
| A16 | 宿主无真实独立角色／用量不可见 | 保留 needs_review／unknown，真实验收不宣称通过 |
| A17 | 补证采集已完成但候选失败 | 保留合法采集及失败记录，不混批归档或删除原件 |
| A18 | 候选创建新来源与知识页 | frontmatter、正文双向边及索引／日志变更均在预览中，接受时仍受现有门禁 |
| A19 | 方向模糊、资料很多 | 先有限预览并提出方向，未认可范围前不深入成课；不阻塞暂存和非学习整理 |
| A21 | 库中只有 Agent 摘要／导入资料 | 可用于背景连接，不默认已掌握，不据此跳过关键前置 |
| A22 | 有旧作答或实践，当前版本变化／用户表示遗忘 | 限定旧证据作用，优先处理变化与当前需求，不改写历史记录 |
| A23 | 生成目录偏题、内容超量或缺少目标 | 覆盖审查指出具体缺口并退回修订；合法字段和 READY 不替代课程适切性 |
| A24 | 原生提案由 Agent 点击确认／包内自报用户同意 | 没有真实用户要求或有效委托依据时，不通过学习约定门禁 |
| A25 | 范围内补讲与新增专题两种变化 | 前者沿用约定，后者更新约定并取得认可；改已发布内容另走版本与基线流程 |
| A26 | 查不到学习记录／历史对话不可读 | 熟悉程度保持 unknown，可继续澄清规划，不推断不会、不上传整库来补足 |
| A27 | 学习目标或证据单侧变化 | 分别使相关绑定失效，保留仍有效的学习意图或事实核验，不全量重跑 |
| A28 | 仅整理知识、仅学习、明确要求先学后入库 | 三种路线均可执行，仅最后一种携带本次用户顺序约束，不形成循环依赖 |
| A29 | 无常驻外部 Agent／未完成课程 | 用户请求后可显式导出回顾，不假称自动完成或无记录即已掌握 |
| A30 | 学习聊天产生新结论／用户指出错题 | 新事实进入核验与纠错；受影响学习观察单独处理，原答案与旧基线不被覆盖 |
| A31 | 一个包被两门课复用、一个约定改选资料 | 原包与约定不循环绑定，投影分别记录依赖，无重复权威知识状态 |
| A32 | 私有离线操作可用、严格 Native 未认证 | 私有解析／候选可验收，正式应用按入口实际要求独立阻断，不伪造整体通过 |
| A33 | 已有正文却再次触发整章自动生成 | 工作单能选择直接写入已审正文；生成实际开销单独记录，不保证模型输出等于输入 |

K4 放行需同时具备：实际可运行操作、以上确定性负向样例、真实语义审查证据、受影响回归、独立审查后的问题关闭、明确未覆盖项。本地、外发和正式应用的验收分列；涉及真实外发或正式应用却缺少对应条件时，该项保持未验收，不为了阶段通过强制新增付费模型调用或绕过门禁。
