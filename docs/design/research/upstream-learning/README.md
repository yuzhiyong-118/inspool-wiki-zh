# 上游学习应用研究：方法、产物与未公开范围

> 本目录是上游学习应用选型与源码研究的公开部分。上游源码副本与研究过程记录未随本仓库发布；本目录保留的是研究方法、结论正文与证据定位口径，使读者能判断每条结论的来源、强度与复核条件。

## 一、这套研究要回答什么

对六个（后扩展到十个）上游学习应用做**只读源码审查**，回答四个决策相关问题：

1. 资料与课件是怎么生产出来的；
2. 教学交互（对话、追问、判定、举例）的真实链路；
3. 学习状态（进度、掌握、证据）存在哪里、由谁拥有；
4. 上下文与 token 怎么控制，MCP／API／模块边界怎么切。

研究结论是**源码口径**，不是运行口径——没有安装依赖、没有启动应用、没有执行上游测试。

## 二、证据方法与口径

这是本研究最值得保留的部分：结论必须能被别人独立复核，因此每条证据都被约束成可定位的结构。

### 2.1 证据定位只有三种合法形态

| 形态 | 含义 | 复核方式 |
| --- | --- | --- |
| `code` | 单个或多个真实源码文件，每个带自己的行号区间 | 打开文件读对应行 |
| `search` | 一次实际执行过的检索，带命令、范围与命中数 | 重跑该命令 |
| `directory` | 一个目录路径及其下被点名的条目 | 列目录 |

任何一条落不到这三种形态之一，就算「不可独立复核」。这比「文件 + 行号塞进一个字符串」的早期写法严格得多：多文件观察必须拆成各自带行号的定位，检索型证据必须记录实际命令，目录型证据必须给出条目清单。

### 2.2 关键修订与理由

研究过程中对证据结构做过一轮系统性修订，修的是口径而不是结论：

1. **仓库归属由文件路径决定**，不再由证据 ID 前缀推断。早期版本把 open-notebook 的后端文件归到了 open-notebook-mcp 名下——ID 前缀暗示的项目与文件实际所在仓库不一致。归属必须由路径判定，ID 只作校验提示。
2. **多文件观察拆成多个定位**，每个定位带自己的行号区间，不再混在一格里。
3. **检索型证据升级为结构化检索记录**（命令 + 范围 + 命中），不只写「搜过」。
4. **目录型证据独立成形态**，记录路径与条目数。
5. **「同上」在解析时展开**，指向同一条证据的同一文件，避免隐式引用。
6. **行号越界按实读源码改正**（7 条）。写错行号会让整条证据失效。
7. **ID 冲突改名**：open-notebook-mcp 侧的 `ONMCP-xxx` 与主执行者记录里的同名不同义，前者改为 `ONMCPL-xxx`（适配器本地源码），后者保持 `ONMCP-xxx`（跨仓契约）。

### 2.3 三层校验

| 校验 | 检查什么 | 结论 |
| --- | --- | --- |
| 定位审计 | `file` 字段是否为可直接打开的真实单文件路径；行号是否越界；仓库归属是否与文件实际所在仓库一致 | 不可独立复核的条目必须修正后才能采信 |
| 观测与定位一致性抽查 | 对带 `symbol` 的 `code` 型证据，符号名应在其所引行附近出现（同文件 ±25 行窗口） | 不一致的列为「观测与定位可能不符」，交人工复核 |
| 交付文档表格一致性 | 三份交付文档的 Markdown 表格列数一致（代码块内与表头行不计） | 避免表格在渲染层错位而无人察觉 |

三条校验都**只读**，不修改任何上游仓库。

## 四、研究纪律

- **区分 README、接口声明、实现与主应用接线**。声明存在不等于实现存在，实现存在不等于主应用用得上——多轮评审中的多数更正来自这三者的混淆。
- **首轮对照只作线索**，关键判断需要独立核实，允许并要求指出首轮错误。
- **不自动 pull、checkout 或回滚**；记录实际 HEAD 与固定提交是否一致，有差异就说明版本。
- **不安装依赖、不启动服务、不调用产品模型 API、不跑完整流程、不改正式系统**；运行未知不阻塞研究任务，也不允许编造实测结果。
- **下载不是采用决定**。
