## 1. 整体选择

**知识与原始来源长期独立，外部成熟 Agent 负责开放式收集、核验、整理和候选，DeepTutor Book 负责面向用户的学习消费，本项目以稳定操作和证据交接衔接两边。**

首个主体验是可反复打开的交互书：章节阅读、页边追问、选择题练习和恢复。已生成内容不因打开网页重新生成；临时原文问题也不被永久强制先成课。DeepTutor Reading 为以后围绕来源阅读提供实际扩展入口，本期不同时交付它的完整结果映射。

选 DeepTutor 是因为当前重心是自主学习/追问/练习与可读结果，尚未要求讲台播放和角色演出。OpenMAIC 是合理的固定课堂替代路线；短答原文与模型批改若成为首期必需，也应重评它，而非默认扩建 Book。完整比较、代价和重评条件见 [D1](design-convergence/D1-learning-backend-decision.md)。

不复刻通用 Agent loop，不把学习记录塞进维护 Runtime，不机械拼接两套学习应用。课程目录、SQLite、自建 UI、三方独立部署均不是长期架构约束；当前本地 SQLite/文件是所选产品的实际能力，不是对未来后端的规定。

## 2. 用户流程与责任

| 阶段 | 负责方 | 输出与边界 |
| --- | --- | --- |
| 平时收集 | 外部 Agent + 资料工作区 | 原文/版本/来源；先暂存，不把每个链接自动成书 |
| 明确整理 | 外部 Agent | 查询现有 wiki，区分重复、冲突、参考、暂缓、学习输入和知识候选 |
| 学习规划（涉及成课时） | 外部 Agent + 用户 | 结合相关知识和实际学习证据分析差距，明确目标、范围、量级及检验方式；复用已有意图，不因入库默认掌握 |
| 知识准备（待实现业务） | 外部 Agent + 知识准备应用操作 | 原文与版本绑定、主张／证据、独立性与冲突核验；可独立于成课形成知识候选 |
| 学习准备 | 外部 Agent + 项目应用操作 + DT Book | 将已审知识与有效学习约定形成有出处和目标覆盖的投影，导入、编排或生成；保存请求与生产回执，不自动入库 |
| 学习交付 | 项目证据操作 + 准备者 | 完成内容检查和学习前基线，给出上游网页入口 |
| 阅读/追问/答题/恢复 | DT 网页和实际领域入口 | 书/页、Progress、chat 保存实际状态，外部 Agent 不需常驻 |
| 导出/回顾 | 项目只读适配 + 外部 Agent | 用户要求或约定检查点由 Agent 显式导出，原始记录、快照、覆盖/失败/未知分列；当前不自动后台触发 |
| 反馈/纠错 | 外部 Agent + 用户 | 表现观察用于下次规划；错题和新事实回原文核验、形成修订，不自动写回课程或知识 |
| 知识候选/正式归档 | 外部 Agent + 现有维护流程 | 沿用 ingest→pending_review→用户 approve，不让内部学习产品代批 |

**学习结束、自评理解、模型估计、独立掌握和正式知识接受是不同结论。** 本期不自动计算权威掌握度或复习队列，不以 Book READY、访问比例或 quiz 结果代替它们。

## 3. 实际架构与部署边界

```text
用户 → 外部成熟 Agent ←读→ 现有 wiki / 独立原始来源
             │ 明确整理
             ↓
       本地资料工作区
             ├─ 原文 / 既有知识 → 主张与证据 / 核验 / 候选预览
             └─ 用户目标 / 知识背景 / 学习证据 → 学习约定
             │ 两者形成学习投影与覆盖（知识准备业务待实现）
             │ 生产回执 / 上传 / 编排或生成
             ↓
       DeepTutor HTTP 后端 + Web
       ├─ BookEngine/Compiler → 书/页文件
       ├─ Progress → 本地 JSON
       ├─ Chat 应用服务 → SQLite
       └─ Knowledge → 学习输入副本/解析/索引
             │ 只读
             ↓
       项目快照与学习结果交接包
             ↓
       外部 Agent → 知识候选 → 既有维护入口 → raw / wiki
```

首个组合：core、server、Web、books、knowledge、parsing、questions、visualize、mastery；这是 manifest 的实际闭包，不是只装 core 就有网页。源码 Web 与打包 Web 二选一，固定同一版本族。采用 Python 引擎、单后端 worker、默认 memory coordination、本地文件/SQLite；选 llamaindex 学习检索需配置 embedding，并承担其安装/索引成本。

不默认启用 PocketBase、Redis 多 worker、额外桌面前端、Reading、Partners、Memory、视频/动画/OCR/沙箱。单 worker 形态有默认配置和源码依据，但尚未安装验证；默认 compose 实际包含额外服务，不能根据旧注释称为最小配置。精确启动方式在实施前的定点验证中确认。

资料工作区、项目证据和 DT runtime/workspace 是存储职责，不要求三个常驻服务。它们可以同机同盘，但 DT workspace 不指向正式 raw/wiki，也不把正式仓库整树作为内部模型的可写工具目标。外部 Agent 仍按既有授权维护知识库。

## 4. 自有工程的职责范围

学习适配继续保留原有四个边界。新增知识准备复用既有 evidence／persistence 协议与维护能力，核心作为普通应用操作，不放进 DeepTutor 补丁，也不新建通用 Agent harness。学习约定是课程准备记录，知识核验是事实依据，两者不能互相代替。

| 边界 | 负责 |
| --- | --- |
| 契约与校验 | stable ID、来源版本、内容证据、学习事实与判断、覆盖/错误语义 |
| DT 适配 | 同一服务的身份/工作区、HTTP 入口、分页、错误和字段映射 |
| 应用操作 | 收资料生产回执、创建交付、学习前基线、读取/导出；未来界面/MCP 调同一操作 |
| 证据与索引 | 只读快照/响应/交接包、可重建目录，不提供另一套答案/进度编辑入口 |
| 知识准备（待实施） | 既有知识比对、主张／证据与冲突、来源依据、审校范围及知识候选，不接管学习状态 |
| 学习规划与覆盖（待实施） | 基于背景和学习证据形成学习约定，将目标对应到所选知识、章节和任务；不从库中存在推断掌握 |

“薄适配”表示不接管教学 harness 和领域状态，**不是几行导出脚本**；这部分是中等工作量。先用普通模块、一个后端实现和本地 CLI，按消费者需要再接网页或 MCP。不建动态插件系统、消息总线、通用任务/预算平台。

用户网页与外部生产方通过同一个 DT HTTP 服务写业务状态，不再开独立 CLI/SDK BookEngine 进程并行写同一文件树。CLI/SDK 是有价值的真实入口，但共享业务语义不等于任意并发/权限都安全。

知识准备的私有解析、检索与候选不要求先获得严格 Native 认证；需要持久维护调度或正式应用时，复用现有 Runtime／Executor，并满足对应入口实际身份、审查与授权要求。不能凭私有分析通过解锁关闭中的 Native，亦不把完整工具隔离变为所有私有准备的新增前置。

## 5. 真值、来源与版本

- 原始来源由项目/外部生产方独立保存，sourceId/sourceVersionId/hash 不依赖可移动路径或上游 KB/file/bookId。原文与清洗提取物各自标识，上传副本绑定实际输入 artifact/hash。
- accepted 来源摘要沿用 wiki/sources；待整理提取物、摘要、目标保留在工作区。DT KB 是学习投影和索引，按冻结小批语料集隔离、可跨活动复用；全库检索不冒充文件过滤，不另建正式知识图谱。
- 可编辑书与页的真值在 DT；Progress/chat/assessment 分别由真实上游入口写入。项目保存其只读证据，不做第二套可写学习库。单个应用也不意味着这些存储具有全局事务。
- 生产回执保存 requestId/digest、来源与上传映射、生成配置/身份和 bookId。缺回执/历史资料标 unknown，不靠模型回忆补造。
- 学前快照保存完整内容投影、题目/答案键和资源身份，contentDigest 校验实际证据字节；schemaVersion、Book.revision、KB fingerprint 和内容版本是不同东西。
- 学习期间采用协作冻结，改版另建 book/activity。导出复核内容与记录，变化/缺基线就标 unknown。**attempt 未保存提交时内容 hash，所以首期只有协作级 baseline_consistent，不声称严格历史绑定。** 改后回退、未受控客户端所见版本不能从导出摘要证明。
- 读取跨文件/SQLite，不宣称原子快照；记录逐资源时间、digest/位点，变化时有限重读或 partial。现有证据不能因“理论可重建”而丢弃。

完整所有权、真实操作、字段对照、JSON 契约和正常/失败/版本变化三个例子见 [D2](design-convergence/D2-data-and-handoff-contract.md)。

## 6. 学习证据的实际边界

| 观察 | 可保留的结论 | 不能推导 |
| --- | --- | --- |
| 选择题答案 + 请求中的 is_correct | 原客户端判分；对固定基线可另作确定性复核 | 服务器权威判分、提交时版本已证明、独立掌握 |
| 书面题 self:correct/self:incorrect | 用户自评；揭示未评为 ungraded | 用户实际解题原文、模型 verdict |
| Progress 已保存但 assessment 同步报错 | 部分成功，原始尝试可能已存在，先读再同 ID 恢复 | 整笔未写入、重发新 ID 一定安全 |
| 有页边教学对话 | 有辅助迹象，附出处/范围 | 缺日志就是独立作答、每条提示一定影响某个答案 |
| Book READY/页面访问 | 生成/导航事实 | 学习结束或理解率 |
| 用户明确说结束/懂了 | 带作者/时间/scope 的声明 | 自动接受知识候选或权威掌握 |

BookEngine 平行于 ChatOrchestrator，自行管理生成队列与恢复；不能将聊天 durable turn 的保证整体套给 create/compile。原生 Book Markdown 导出只含书内容，项目结果包必须另读 Progress 和可读公开 chat。QuizGenerator 的来源锚点不完整，部分生成路径的可选检索失败仍可继续，READY 不证明来源已用；准备者须对照原文核验关键内容。选定 KB 也不证明逐题精确来源，缺定位就用活动级/partial。

OM 的短答基础分 fallback、PBL 独立状态、RuntimeStore 等已审查事实保留为候选依据，不套用到 DT。严格学习门禁/内容提交证书需要另改真实领域入口，首期不隐藏这部分成本。

## 7. 首个闭环覆盖

支持明确整理后的 Markdown/纯文本投影、小型 Book、文字/提示/题目、页边追问、单答案 choice、当前页与已存尝试/会话恢复、只读结果交接。未知题型、无效答案键和部分生成不得列为完整覆盖。

书面/填空/代码题允许按上游实际内容展示，但导出明确自评/未评/缺原答案，不承诺模型批改。Reading、PBL、执行环境、音视频、复杂应用、跨课程画像/复习、严格独立评估后置。不做所有模式的统一学习库。

首期直接用上游书库/reader，项目 CLI 请求导出即可；自有门户/导出按钮不是首个闭环前置条件。详细范围、配置/SOP/适配/可能补丁成本与未来验收观察见 [D3](design-convergence/D3-first-learning-scope.md)。

## 8. 预算、恢复与工程管理

复用 Book 的页队列/in-flight 合并、块并发配置、provider 故障暂停、pause/resume 和重开恢复；chat 复用自己的 admission/cancel/recovery/context/loop 限制。Book 创建超时可能未得到 bookId，不具有已证明的 exactly-once，先核对回执/状态，不盲目重新生成。

一次交互可能含多次模型/工具调用。生成提案/大纲/块/问题、embedding、追问分别计入；关非必要媒体并从小单元、单本生成开始。LLM metrics/usage_ledger 可保存供应商用量与 estimated 标记，但不证明所有路径完整归属活动，也不是价格账单或硬预算。首期不建新账本；货币硬限额需供应商支持或另做完整配额设计。

固定上游提交/发行物、模块族/Web 版本、配置及 exporter schema；运行质量、费用、内存和模型兼容尚未知。备份包含 runtime-home data、外部 workspace 的隐藏状态、SQLite/WAL 的一致副本、学习资料与项目证据，不只复制书。升级先在副本验证迁移/读侧/恢复，程序和数据配套回退；凭据不装入学习交接包。

保留复用许可与必要通知。正式库写入及 approve 权限不因共用接口而合并，不把提示词当物理工具隔离。旧维护 Runtime 的 S0/S1 历史结论保留，其后阶段必须按当前职责重新规划。

## 9. 吸收的上游原则和扩展触发

| 来源 | 实际吸收 | 何时扩展 |
| --- | --- | --- |
| DeepTutor | 成熟教学/会话服务、typed blocks、模块闭包与按需激活 | 原文阅读重要时加 Reading；个人连续性需求明确时评估 memory/mastery |
| OpenMAIC | 可检查的内容与运行状态分开、持续生成/恢复、课堂播放 | 固定课堂/角色/短答模型批改成为核心时重评后端 |
| Lattice | 人与 Agent 共用状态/操作，按打断成本分工，路标+按需内容、结构化呈现 | 上游 UI 不足时局部替换；支线回传事实/引用，不合并整段历史 |
| Open Notebook | Source/Insight/Note 分离，来源跨活动复用，chat/search/transformation 按任务取舍 | 研究整理成为独立产品需求时再评估完整系统，不现在叠加部署 |
| Kotaemon | 可替换索引/推理和证据呈现 | 有真实召回/引用问题才替换流水线，不因能接就引整栈 |
| MCP adapter | 传输薄、短输出、错误/身份明确 | 外部客户端确需 MCP 再包装已有操作；工具发现不等于 schema 自动延迟 |

来源所有权、证据诚实、共享业务语义和可替换边界是稳定原则；当前选 Book、单 worker、协作冻结是可重评选择。没有为了可扩展而先建设多用户、微服务或插件市场。

## 10. 设计完成与下一步

D1 的推荐经 D2 的真实字段/接口核对后仍成立，但仅适用于本文件明确的有限辅助学习闭环，不代表严格测评平台已经成立。D3 已列出配置、主要适配工作和后续验收观察，三个专题不再待执行。

后续实施任务书已编写，精确模块/源码 Web 的 I0/I1 无模型启动与空库重启读取已通过。I2 的 MD 导入/生成/choice/追问/真实记录恢复，待明确模型、embedding 和预算后执行；不要求先完成适配器或运行六套产品。验证失败应回 D1，而不是靠增加另一套学习状态或通用 Agent 平台掩盖缺口。前面的设计推断不因 I1 通过而自动成为真实教学验证结论。
