# D3：首个可用学习闭环与工程边界

> 本文为上游选型与原始研究记录。上游源码副本与研究过程记录未随本仓库发布；引用上游源码时绑定[上游来源清单](../../../upstream-sources.md)的固定提交与文件路径，结论与分析随正文发布。文中状态与结论对应原文写作时点，不代表当前部署或验收完成。

日期：2026-11-10。状态：设计范围已收敛，未实施/部署。依赖 [D1 选择](D1-learning-backend-decision.md) 与 [D2 契约](D2-data-and-handoff-contract.md)。后续另写实施任务书，不自动继续旧 S2/S3。

## 1. 首个闭环

**外部 Agent 明确整理资料 → DeepTutor 生成一个短交互书 → 用户网页阅读、页边追问和选择题练习 → 重开恢复 → 项目导出真实学习记录 → 外部 Agent 结合原文整理知识候选。**

暂存与正式知识库按已有职责独立存在。首个学习入口直接使用上游书库/reader，不先做自己的门户。用户仍能掌控本地数据、模型配置和后续界面改造；这不要求现在拥有全部上游前端代码的维护责任。

建议初始使用规模：一次整理 1–3 份文本资料，一个小目标、1–2 个内容章节及上游概览；同一时间只生成一本书。它们是减少初次运维与生成面的方法，不是已经生效的系统限额，也不是未来吞吐上限。资料被上游截断时须显式缩小/拆分单元，不能只标成功。

### 可见用户步骤

1. 平时把链接/文件交给外部 Agent，先保存原文、来源身份、抓取信息；不自动生成书。
2. 明确要求“整理今天资料”时，Agent 查询 wiki，输出材料分流与短学习目标。重复、参考、暂缓和直接候选不必成书。
3. 准备资料包与生产回执，导入该小批资料集的专用学习 KB；等待所选文件可读/索引就绪，固定语料清单。原文与清洗文本分别留存；相同冻结资料集可供不同活动复用，不在学习期间向同一 KB 追加无关文件。
4. 使用上游 Book 的 proposal/spine 确认和编译流程。限定文字/提示/题目块，检查实际产物。生成可能多次调用模型，不能将“确认”描述为免费转换。
5. 内容生成完成、题目可识别后，由项目操作保存基线，再交付书的打开入口。学习中只读内容，更新另建活动；不边学边 regenerate/supplement。
6. 用户阅读页面、追问和作答，上游维护 progress/chat。已存在内容开页无需重新生成；未完成编译的书可能在打开时恢复，应先完成发布检查再作为学习交付。
7. 随时可导出，包括没有做完的情况。需要“结束学习”时保存用户声明；导出操作等待当前回合结束并标示读取边界，形成可搬运的只读结果包。
8. 外部 Agent 读取结果与原始来源，汇总疑问、表现、自评及未确认项，必要时产生知识候选。正式 ingest/pending_review/approve 沿用既有流程，不由内部应用代批。

准备者可以是外部 Agent，消费时不需要它常驻；结果交接可由外部 Agent 稍后请求本地项目 CLI，无需先开发网页导出按钮或 MCP Server。

## 2. 支持范围

| 项 | 首个闭环承诺 | 明确限制 |
| --- | --- | --- |
| 输入 | 已整理 Markdown/纯文本的可读文本投影及独立原始来源 | 网页先由生产方提取；扫描 PDF/OCR、视频、复杂排版不作为首期验收输入 |
| 内容 | 小型 Book，text/section/callout/quiz 等文本学习内容，概览按实际上游产物保留 | 使用现有 block_types 和产物检查；不以允许块配置代替对真实输出的验证 |
| 追问 | BookChatPanel，当前页引用、公开会话与恢复 | 聊天历史可有裁剪/删除，提问不是受控独立测验；不承诺始终逐段引用原文 |
| 练习 | 可确定为 choice、选项键唯一且有效的单答案题；保存用户选择与原判分 | 不是多选集合评分；未知类型、错误答案键不能进入 supported 评估。生成题质量由准备者检查 |
| 书面/填空/代码题 | 可看上游内容；自评/揭示按实际值导出 | 不承诺书面答案原文输入、模型批改、代码运行。自评不能伪装成短答评分 |
| 阅读恢复 | 当前页、visited/bookmarked、已保存尝试、关联 chat | 不承诺精确滚动、离线浏览器崩溃前未保存的点击或输入 |
| 内容证据 | 生成完成后的基线、来源集合、原始响应 | 提交时 hash 缺失；协作级绑定，严格历史证明 unsupported |
| 结果 | 原始尝试、导航、可读公开会话、用户声明、部分/未知说明 | 不自动宣称独立掌握，不把访问比率当理解率 |
| 知识输出 | 外部 Agent 形成可审阅候选 | 不自动写正式 wiki、不改变 raw 正文/审批规则 |
| 其他模式 | 不纳入本期闭环 | Reading、Mastery 自动门禁/复习、PBL、HTML 应用、动画/音视频、跨活动记忆后置 |

题目生成类型可通过目标/已有 params 控制，但模型输出不保证符合要求。若出现书面题：按现有 regenerate-block + params_override 在学习前调整并检查，或将该题记 unsupported；不能为通过验收强行将它解释成 choice。这个准备步骤是配置/SOP 成本，不隐藏成“应用原生保证全部单选”。

## 3. 组件、目录与单写入方

```text
外部成熟 Agent ──读── wiki / 原始资料
       │ 明确整理
       ↓
资料工作区（原文、提取物、prepare manifest）
       │ 项目操作：生产回执、上传/创建
       ↓
DeepTutor HTTP 服务 + Web
  ├─ BookEngine / Compiler → 书与页文件
  ├─ Progress 业务入口 → progress.json
  ├─ Chat 应用服务 → SQLite sessions / turns / events
  └─ Knowledge → 学习输入副本、解析缓存与索引
       │ 只读结果
       ↓
项目证据层（receipts / snapshots / exports）
       ↓
外部 Agent → 知识候选 → 现有维护入口 → raw / wiki
```

实际采用 D1 列出的九个模块，同一版本族；Python 引擎、单 worker、默认本地 SQLite/文件，Next Web 作为其客户端。源码与打包 Web 二选一，实施时按固定提交/兼容发行物确定可重现交付。不额外部署 Open Notebook、Kotaemon、Lattice、PG、PocketBase 或 Redis 来拼接本期能力；默认 compose 含额外依赖，需针对单 worker 安装形态编写启动配置，尚未验证。

资料工作区、项目证据目录与 DT runtime-home/选定 workspace 是三个**存储职责**，不是要求三个进程。可以放同一物理磁盘；运行目录与 DT workspace 不指向正式 raw/wiki，也不把正式仓库整树挂给带写工具的内部模型。外部 Agent 仍可按既有授权维护 wiki。未来目录名可变，manifest 的稳定 ID 不变；本轮不创建这些产品目录。

自有代码保持四个普通边界：契约/校验；DT 后端访问与错误映射；准备/基线/导出应用操作；只读证据和可重建索引。先设一个后端实现，不动态加载插件、不引入新 Task/Run 平台。CLI 首先调用这些操作；未来网页/MCP 复用它们。已有维护 Runtime 只承担正式接受与恢复。

写入规则：用户和外部准备方都通过同一个 DT HTTP 服务写 Book/Progress/chat；不从独立 CLI/SDK 进程并行操作同一个 BookStorage。项目只写自己的证据与回执，原始结果不能在项目端另行“修正后回灌”。内部工具仅启用本次学习需要的读取/教学能力，正式库不作为工具写入目标；是否启用更多工具属于配置与权限核对，不靠提示词保证隔离。

## 4. 生产、冻结、直接编辑和导出

| 时点 | 责任与处理 |
| --- | --- |
| 收集 | 外部 Agent 保存原文及来源版本；可重复使用提取物，摘要不能替代核验 |
| 创建前 | 项目先保存 requestId/digest，再调用 API；记录所选 source/KB/file、目标、上游配置版本和已知截断 |
| 创建/编译 | 保存 bookId 和响应；复用 proposal/spine 确认、逐页合并、失败暂停和 resume；未知成功不盲目重发 create |
| 学习前 | 项目采集 D2 的一致性基线；准备者对照原文检查目标、事实、题目类型/答案键、缺资源和来源精度。可选检索失败时仍可能生成 READY，不能只看状态通过；发布回执后才交付 |
| 学习期间 | 上游是状态真值；用户可用原生 UI，但编辑、深挖补块和补练习会改变内容。首期 SOP 禁止原地改已交付活动，并无物理封锁 |
| 直接改动后 | 导出检查新旧内容，改动记录 binding=unknown，保留旧快照；不能静默重新固定基线给旧答案。新内容另建活动 |
| 交接 | 项目读原始响应、位点与错误；不补问模型、不把自评升格为评估；导出包不可变 |
| 回库 | 外部 Agent 对照原文整理候选；正式审查与用户 approve 照常，capture approved 不替代它 |

题目内容绑定仅具协作强度，是公开限制。首期不增设“提交证书”或承诺全局原子快照。若实际需要持续编辑同一本书并保留历史测评，必须补上游提交内容版本/快照引用，而不是让 exporter 根据当前题干猜历史。

## 5. 预算、重试、并发与取消

| 路径 | 可复用能力 | 首期处理及缺口 |
| --- | --- | --- |
| Book 生成 | 每书 page queue、页级 in-flight 合并；CompilerOptions.block_concurrency 默认 1；两次连续 provider 级整页失败触发暂停 | 一次只准备一本书，先小纲目。SourceExplorer 另有检索并发 6/调用上限 48，单块顺序不等于全链低并发；没有据此声称统一硬预算 |
| Book 恢复 | pause_book 先持久 PAUSED 再取消；未完成页保留/复位；打开未暂停书可恢复 | 断连不等于取消，主动停止走 pause；暂停是边界控制，已经发出的供应商调用可能仍计费 |
| chat | 共享 turn 的 admission、提交身份、cancel/recovery，loop 有上下文与探索轮次限制 | 轮次限制仍可能有收尾/工具/子调用；不将一回合视为一次请求或全部费用上限 |
| quiz | choice 客户端判分与记录；可用 submission_id 去重 | 默认 Book 不需要每题另调评分模型；失败后先读实际记录，assessment 同步可能部分失败 |
| 导入/检索 | 现有解析与索引任务、可读进度/取消路径 | llamaindex 路径检查 embedding 联通，索引本身有成本；不是“上传文本零模型/零依赖”保证 |
| 用量 | LLM metrics/usage_ledger 保存 call_id、provider、token、estimated、session/turn/source，持久于 usage.sqlite3 | 用量比按聊天次数估算更可靠；仍有估计/缺项/日志失败，未证明所有 Book/embedding/媒体调用都完整归属 activity |

模型调用静态组成：来源导入可能有解析/embedding；Book 有提案、来源探索、结构综合、页面规划及块/题生成；页边聊天是 agent loop；内容已生成后的常规阅读和选择题判分通常不需要为同一内容再调用生成模型。题目、摘要、修订和补练习也可能新增调用，不能报一个未实测的 token 节省百分比。

首期模型设置包含文本生成/聊天与兼容的 embedding；重用现有 provider 配置，不强制某供应商。媒体、额外 OCR、浏览器、动画、沙箱和自动补练习不纳入默认流程。**不额外建立通用预算账本。** 项目只保存已读的 usage 与覆盖；若用户要求货币硬限额，应使用供应商账号硬限额，或另做覆盖所有调用入口的配额设计。当前本地 scope/轮次/并发是软控制，不是财务门禁。

重试规则：可恢复已知 book/page，不重复创建整个活动；在请求不确定时先核对回执/当前状态；同 submission_id 相同内容可恢复，不同内容拒绝。错误、超时、取消、部分状态分开显示，不能把未知降成空结果。没有必要为了导出再增加一个 always-on Agent。

## 6. 复用与工作量清单

| 类别 | 实际工作 | 粗粒度成本/风险 |
| --- | --- | --- |
| 直接复用 | DT Book 引擎、Web、页边 chat、Progress、导入/索引、已有模型与 usage 机制 | 降低自研范围；上游版本复杂度与实际资源需求仍由本地使用承担 |
| 配置与 SOP | 固定版本、模块闭包、模型/embedding、单 worker、隔离工作区、准备检查、学习冻结、备份 | 小到中等；使用约定不能算强制保护，未验证打包组合 |
| 薄适配中的主要工作 | 来源/请求回执、stable ID 映射、内容投影与快照、HTTP 读侧、逐题语义/位点/失败分类、可搬运结果包 | 中等；这是完整的数据适配职责，不按“几行 JSON”估算 |
| 可能需要的部署调整 | 精确模块组合、可用 Web 发行形态、单 worker 启动/数据挂载 | 中等不确定性；不预先 fork 核心。定点安装失败会触发 D1 重评 |
| 首期不要求的上游补丁 | 提交时内容 hash、服务端权威评分、跨 Progress/assessment 事务或状态化补偿、完整错误溯源 | 若升级为硬要求，成本中到高且要做上游协议；不能悄悄挤入“薄适配” |
| 后置 | 自建门户/组件、MCP、Reading、复习画像、PBL、复杂生成应用、多用户/多 worker | 当前没有闭环必要性，先保留数据/操作接口，不实现平台 |

## 7. 运行、备份和升级最低要求

- 固定 Git commit/可重现发行物、模块家族版本、Web 对应版本和模型/解析/索引配置；不把未来 latest 的行为当成本次设计依据。Apache-2.0 的 DT 复用保留所需许可/NOTICE；未来分发额外资产另核对。
- 默认 runtime-home 的 data、外部选定 workspace 及其隐藏 `.deeptutor`、项目原文/回执/快照/导出一起备份；不能只复制书文件或只复制一个 SQLite 主文件。停止应用/相关写进程后备份，或使用上游明确支持的一致备份方式；包含凭据的备份由用户本地保管，不装进给外部 Agent 的普通学习交接包。
- 升级先在备份副本验证包版本、迁移、book/progress/chat 读侧、旧交接包校验；回退恢复应用与数据同一备份组，不能在迁移后仅回退程序。保留 fixture/旧包用于以后契约兼容，不要求本轮建立测试平台。
- 本地服务默认同机访问，必要身份/工作区按上游配置；暂不建设公网、多租户或远程授权。不向导出包塞运行凭据、模型私有历史或整个正式 wiki。

## 8. 后续扩展的位置和触发

| 实际触发 | 扩展位置 | 避免的额外负担 |
| --- | --- | --- |
| 主要学习变成读原文、保留位置 | 同一 DT reading + notebook，新增活动 kind 和位置/证据映射 | 不先生成 Book，不强塞进 Book Progress |
| 上游界面不满足操作/呈现 | 自有 Web 客户端/组件调用既有业务 API；保留 book/chat 身份 | 不重写整个 Agent harness，也不增加独立进度存储 |
| 检索/引用效果不足 | 所选 DT pipeline/检索配置与证据定位，先使用真实问题定位 | 不默认再加完整 Open Notebook/Kotaemon |
| 多活动需个体连续性 | 声明/表现/导师估计的 scoped 记录；再评估现成 memory/mastery | 不将自评分直接当掌握度，不合并全部聊天 |
| 严格学习门禁/历史评估 | 上游提交入口绑定版本、真实答案和评估；重评 OM 选择 | 不以导出侧推断假装权威证书 |
| 外部消费者确需 MCP | 包装现有项目操作和上游 API，独立权限 | 不为了协议形式先开发工具平台 |
| PBL/运行代码成为需求 | 单独的 activity/evidence/执行环境专题；比较现有上游路径 | 不把执行环境藏在普通题目适配里 |
| 用户主要需要课堂播放/短答批改 | 用 D1 的 OM 路线替换学习后端，重写对应映射 | 不强求运行两套产品或保持旧实现投入 |

## 9. 后续实现的验收观察（本轮不执行）

1. 用一份自有 MD，从原文版本、准备包、KB 上传到 bookId 可追溯；没有显式整理时不生成内容、不改正式库。
2. 在隔离目录运行精确模块组合，生成一个小单元；有实际 choice 题、有效答案键，页边追问确实引用当前页。若定点运行不成立，先回 D1，不能先做全部适配。
3. 保存基线后，回答一题并追问；关闭网页、重启服务再开，页面/保存答案/已关联会话能从上游重新读取。未保存的 UI 草稿不混入成功条件。
4. 导出包能原样定位答案与公开记录，区分 client_reported、自评、ungraded、missing；明确内容提交时绑定 unknown、来源粒度、聊天覆盖。已有事实不触发模型补写。
5. 模拟同步失败或取不到会话时保留真实已存答案和 partial；重复 submission_id 不凭项目另造答案去“修复”。
6. 直接改动题目、缺原文、读取中继续写入、身份不符时，分别得到 unknown/partial/拒绝聚合；不能默默用新题干解释旧答案。
7. 外部 Agent 在不连接学习内部 DB 写入的情况下，用交接包+原文+wiki 形成候选；没有发生正式自动 approve。
8. 能暂停/恢复已知生成任务，观察 token/estimated 和缺失项，能够备份并在副本恢复完整状态；实际费用/质量单独记录，不宣称本轮已经通过。
