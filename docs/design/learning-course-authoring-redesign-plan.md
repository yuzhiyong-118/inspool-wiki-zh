# 能力目标驱动的课程内容重构方案

> 公开设计摘编：保留通用契约与方案；历史验收、用户反馈、运行记录及本地素材不随仓库发布。设计条目不代表部署或验收完成。

## 2. 目标与非目标

### 2.1 最终学习目标

课程完成后，用户应能面对一个未展示答案的新场景，独立产出一份最小但完整的 Flow／Agent 设计，包括：

1. 识别贯穿任务的领域对象、输入、产物和事实状态；
2. 划分确定性 Flow 与受限 Agent 的职责；
3. 设计 Capability 契约、参数 Schema、产物和错误；
4. 接出合法的生产者—消费者关系；
5. 判断确认闸、执行、重试、幂等和恢复规则；
7. 给出可检查的验收证据，并解释主要取舍。

“读完章节”“答对术语题”“Agent 认为不错”均不能单独证明达到目标。

### 2.2 本方案范围

- 建立能力目标、知识覆盖和课程目录之间的关系；
- 扩大与学习目标有关的本地源码和外部资料阅读；
- 设计完整示例、失败示例、迁移练习与最终考核；
- 规定内容生产、证据核查、试学和修订流程；
- 比较未来内容交付方式，但不预设立即开发。

### 2.3 非目标

- 不按固定字数、章数、图数制造内容；
- 不重写现有课程或直接覆盖原 Book；
- 不为了课程改版部署 OpenMAIC 或另一套学习系统；
- 不恢复未经保护的整书重建；
- 不自动继承旧课作答为新课掌握证明。

## 3. 核心生产原则

### 3.1 摘要用于导航，不承担完整教学

来源摘要用于发现主题、定位证据和形成候选概念。关键机制必须回到原始文档、源码、配置或测试核对。课程正文不是摘要的扩写，而是根据学习目标重新组织的教学产物。

### 3.2 从最终作品反推课程内容

先定义用户最后要独立完成的作品，再反推概念、示例和练习。每个章节必须回答它支持哪项最终能力；不能只是因为资料里出现了某个术语就生成一章。

### 3.3 项目事实、通用知识与迁移推演分层

- **项目事实**：来自固定提交中的文档、源码、配置和测试；
- **通用知识**：来自外部课程、官方文档或其他可靠资料；
- **迁移推演**：为本课程构造的非 GIS 示例和练习，明确标注，不冒充上游实现。

三类内容可以相邻出现，但来源和确定性不能混淆。

### 3.4 示例先于抽象堆叠

重要机制至少考虑一种能展示输入、处理、输出和判断的完整示例。理论用于解释示例为什么这样运行，而不是脱离示例重复定义。

### 3.5 示例与练习承担不同职责

- 完整正例展示正常路径；
- 失败示例展示边界、错误和修复；
- 对照示例展示不同设计选择；
- 变式练习减少机械模仿；
- 最终新任务检查独立迁移，不提供答案。


## 4. 先建立课程覆盖矩阵

正式写作前形成一份覆盖矩阵。每一行是一项可观察能力，而不是一个资料标题。

| 能力域 | 可观察产出 | 必需内容 | 证据与练习要求 |
| --- | --- | --- | --- |
| 确定性执行 | 说明真实动作由谁触发和执行 | Engine、Capability、REST、确认闸 | 完整调用链＋直接执行反例 |
| Capability 设计 | 写出最小能力契约 | ID、参数 Schema、产物、错误、幂等、状态副作用 | 正例＋缺字段／越界失败例 |
| Flow 编排 | 接出多步骤数据流 | 环、步骤、输入引用、生产者—消费者 | 可检查 Flow＋断线修复 |
| 失败与恢复 | 设计不重复写入的恢复路径 | 状态、重试、幂等、段级恢复、超时未知 | 故障时序＋恢复设计 |
| 验证与目标 | 区分执行、验收和豁免 | Probe、GoalContract、执行证据 | 证据表＋“成功但未达标”反例 |
| 独立设计 | 交付自己的最小 Flow／Agent | 上述能力的组合与取舍 | 未展示答案的新任务＋人工标准 |

矩阵还需记录：先备能力、达成标准、预计阅读／练习／反馈时间、现有章节、支持来源、证据验证方式、已有示例、缺失内容、练习覆盖和未决问题。没有来源或无法观察的能力先标记缺口，不用生成文字掩盖；“有章节、有来源、有练习”本身不等于达成。


## 5. 资料扩展策略


run-01 只使用三个直接来源，不足以支撑上述目标；本地来源目录实际还保存了 Advisor、Validator、Flow Contract 和 Flow 模板等副本。先盘点这些文件的来源、固定提交和适用范围，再按能力域定点扩展，不无差别复制全仓：

1. **对象与目标**：`Document/constitution.md`、领域模型、需求与验收文档；
2. **Capability 与 Registry**：真实能力定义、参数 Schema、产物 spec 和注册实现；
3. **Flow 实例**：选择少量有代表性的 Flow 模板，展示真实参数和产物接线；
4. **Agent 链**：模板选择、参数提取、确定性实例化、AgentAdvice、确认和 Escalation 的实际接口；
5. **执行与恢复**：Engine、状态迁移、Run 快照、重试和恢复测试；
6. **验证与证据**：Probe、GoalContract、环级决策和相关测试。

每个资料包记录固定提交、路径、支持论断、验证方式、适用边界和对应能力域。研究以具体缺口为单位；证据足以支持目标论断和案例后即可停止，不要求读完整个仓库或列出的外部课程。

### 5.2 外部教学与知识参考

外部资料分两种用途，不混为项目事实：

- [Hugging Face AI Agents Course](https://huggingface.co/learn/agents-course/unit0/introduction)：参考理论、实践、用例作业和最终挑战的组织；
- [DeepLearning.AI Agentic AI](https://www.deeplearning.ai/courses/agentic-ai)：参考设计模式、错误分析和系统评价的知识覆盖；
- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：参考文字、代码、视频和扩展资料的组合；
- [Datawhale Agentic AI 中文教程](https://github.com/datawhalechina/agentic-ai)：参考中文概念讲解与代码解读；
- [Anthropic Claude Code 101](https://anthropic.skilljar.com/claude-code-101)：作为上下文、权限、Skills、MCP 与 Hooks 的补充阅读。

只读取与具体缺口相关的章节。借鉴课程结构不等于复制其框架、工具或结论。原始课程、中文整理和同一来源的转述必须保留来源关系，不能作为多个独立证据重复计数。

### 5.3 资料不足时的处理

若项目资料无法支持某个必要论断，可：

1. 找到更直接的项目证据；
2. 引入可靠外部资料并标为通用知识；
3. 明确写为迁移推演或设计建议；
4. 仍不足时保留开放问题。

不得用模型常识补成确定的项目事实。


## 7. 单元内容设计

每个核心机制根据需要选择以下组成，不机械设置数量：

1. **学习目标**：能解释或完成什么；
2. **问题情境**：为什么现在需要这个机制；
3. **项目真实实现**：源码或文档怎样工作；
4. **完整正例**：输入、草案、校验、执行、产物和证据；
5. **失败示例**：具体错误、阻断原因和修复；
6. **设计取舍**：替代方案及选择条件；
7. **迁移应用**：非 GIS 场景怎样复用原则；
8. **独立练习**：产物、评价标准、反馈和复验；
9. **参考资料**：直接证据、辅助阅读和迁移推演分别标注。

可以使用 DeepTutor 原生规划中的 `core / example / derivation / application / comparison` 作为内容用途参考，但不继承固定字数或块数指标。


## 8. 示例与练习标准

### 8.1 完整示例最低要求

一个被称为“完整”的示例，应让读者看到：

- 用户或上游系统的真实输入；
- 相关对象或建议物及其产生者；
- 至少一个关键校验或决策；
- 实际执行者与执行入口；
- 输出、状态和可核查证据；
- 与当前学习目标的对应关系。

只展示 JSON 片段、架构图或能力名称，不自动算完整示例。每个示例还必须标明验证级别：

| 级别 | 允许声称的内容 | 必要证据 |
| --- | --- | --- |
| 源码追踪 | 按代码路径，预期会怎样处理 | 固定提交、文件、函数和推理链 |
| 离线校验 | 某份实际输入通过了校验或得到某个错误 | 实际输入、校验器、输出和错误记录 |
| 真实运行 | 某次执行产生了真实结果 | 实际产物、状态、日志或外部证据 |

三者都能服务教学，但不能互相冒充。非 GIS 示例可以完整讲清设计过程，不需要为它额外开发系统；编写的示意输出不得写成真实运行结果。

### 8.2 练习产物与反馈

样课阶段使用聊天或本地 Markdown 承载设计物，不新增提交平台。每项练习明确：

- 要提交的产物；
- 可人工检查的标准；
- 用户自评、Agent 建议和正式审查的区别；
- 常见错误对应的补学位置；
- 使用变式任务复验的方式。

### 8.3 最终考核

最终任务必须与贯穿示例不同，且未展示答案。写作前先形成简短评价表，区分四个层级：

| 层级 | 所需证据 |
| --- | --- |
| 能解释 | 用自己的话说明对象、角色、权限和因果链 |
| 能设计 | 交付完整设计说明、Capability 契约和 Flow 配置，经人工标准审查 |
| 经校验 | 设计配置通过适用的确定性离线校验；不代表真实执行 |
| 实际运行 | 真实运行并保留产物与证据；不属于当前默认必需目标 |

当前目标是“能设计”，按需增加“经校验”，不要求安装 GIS 软件或实现完整 GeoFlow。允许查课程、官方文档和接口参考；可以使用 Agent 获取概念解释或错误提示，但不得由 Agent 代做核心设计。记录无提示、概念提示、结构提示或部分答案等辅助程度，辅助结果不与完全独立作答混写。

评价者另备参考解和可接受的替代设计，不向学习者提前展示。对象遗漏、Agent 直接执行、产物断线、外部写入缺确认、超时盲目重试等关键错误必须修正；满足相同约束的不同对象命名、模块划分和能力拆分可以接受。


## 9. 内容生产工作流

### 9.1 多角色生产管线

课程生产采用主 Agent 统筹、多角色分工、确定性门禁和独立审查。角色代表职责，不要求每个角色常驻一个 Agent；小幅修订只启动受影响职责，独立 Reviewer 不参与被审内容创作。不能再退回主 Agent 单独完成全部资料研究、正文、练习和阅读体验设计后直接交付。

| 角色 | 核心责任 | 交付物与边界 |
| --- | --- | --- |
| 主 Agent／Coordinator | 拆任务、管理依赖与预算、集成候选、维护交接 | 不自行宣布独立审查通过；预算或证据不足即暂停 |
| 课程设计者 | 学习目标、先备关系、统一术语、贯穿案例、难度与学习负担 | 持续对整门课连贯性负责，不只拼接各章 |
| 资料研究者 | 核查原始来源、追踪代码、提供案例和未知项 | 区分文档声明、源码行为与实际运行；证据足够即停止 |
| 教学内容作者 | 将证据组织成讲解、完整示例、失败例和设计对照 | 对读者怎样理解负责；与阅读体验设计者双向提出需求 |
| 练习与评价设计者 | 练习、提示、评价标准和迁移任务 | 正文写作前参与；不展示最终答案，不把自评当掌握 |
| 阅读体验设计者 | 信息层次、图形、导航、交互与可访问性 | 根据真实内容选择表达，不把界面能力当固定写作限制 |
| 独立 Reviewer | 分别执行事实／工程与教学／评价审查 | 不参与被审内容创作，不把作者说明当证明 |
| 确定性脚本／Executor | 链接、Schema、渲染、回归、受控交付与恢复 | 不另设自由判断的执行 Agent，不以结构通过代替语义审查 |

协作分三组：规划阶段由课程设计与练习设计协作，研究者补关键证据；制作阶段由内容作者与阅读体验设计协作，研究者按缺口补证；验收阶段冻结候选，再进行独立事实审查、教学审查和确定性检查。小任务允许兼任，但被审作者不能兼任独立验收者。润色、总结和修订属于现有角色步骤，不新增固定角色。

### 9.2 冻结候选身份

每次集成后生成一份普通文件候选清单，至少记录：

- `candidateId`、学习约定、课程蓝图、评价依据、G0 资源约定与固定来源版本；
- 课文、练习、阅读体验文件、证据和检查规则的路径与 SHA-256；
- 实际验证级别、生成时间、当前状态和审查结果链接。

每份审查结果必须引用 `candidateId` 与清单摘要。学习目标、先备关系、时间安排、评价标准、正文、练习、来源、界面、资源约定或检查规则变化后形成新候选，旧审查结论保留但不自动适用于新候选；按变化重验受影响门禁。修复不得覆盖旧候选及其审查历史。文件清单即可，不新增数据库或工作流系统。

### 9.3 候选与门禁顺序

```text
学习约定与固定来源
→ G0 输入、范围、版本、预算与资源边界检查
→ 候选课程蓝图
→ G1 结构检查＋课程设计／教学审查
→ 资料研究／内容示例／练习评价／阅读体验协同
→ 主 Agent 集成并冻结带摘要的候选
→ G2 链接、Schema、源码探针、组件与渲染检查
→ G3 独立事实／工程审查＋教学／评价审查
→ 有界修复，形成新候选并复验受影响门禁
→ G4 实际浏览器与操作检查
→ 用户试学、练习产物与反馈
→ 获得具体授权后受控交付
```

- G0 与 G2 主要由确定性工具完成；来源是否支持论断仍需 G3 判断；
- G1 的时长求和、字段完整和引用存在可机械检查，能力覆盖、先备顺序、练习与目标是否匹配必须经课程设计／教学判断；
- 事实错误、目标遗漏、先备缺失和评价失配属于阻断；风格偏好只列改进建议，不引发无限修复；
- G3 的完整课程分别审查事实／工程与教学／评价，小幅修订按影响选择；未通过时生成者不得放宽标准；
- G4 证明实际渲染和操作，不证明内容正确或学习有效；
- 用户试学不能由无上下文 Agent 读者测试替代；界面与课文变更分别记录学习记录影响。

### 9.4 有界修复、预算与交付

每次任务在 G0 写明并持久保存：

- 最大修复轮数与并行任务数；样课默认最多 2 轮修复、最多 3 个并行任务，需要变化时先修订任务约定；
- 本轮模型调用／token 预算、暂停线、计量来源和覆盖范围；
- 课程内容生产调用与 DeepTutor 运行调用分别计量，不默认旧账本覆盖新增角色；
- 宿主主／子 Agent 等不可计量部分标为 `unknown`，可给定性工作量说明，不伪造精确 token；
- 到限后保留的候选、审查证据、未完成项和恢复入口。

角色之间优先交付证据卡、源码定位和差异，减少重复传递全文。每个修复任务绑定原问题、责任角色、受影响产物、新候选身份和需重跑门禁。达到上限仍不通过时停止，不以主 Agent 总结替代未通过项。停止后保留最后候选、审查证据和未通过项，由用户选择缩小范围、转人工处理或追加预算；只续作受影响部分，不要求为了继续而重新生成整课。

现有 Wiki 维护 Coordinator／Reviewer／Executor 可复用职责与机制，但课程生产的宿主角色、候选契约和门禁接线必须另行验证；不能因为聊天宿主支持 SubAgent 就声称自动课程管线已经实现。

### E0：能力目标与基线

- 确认最终学习目标和用户先备知识；
- 盘点现有课程的章节、来源、示例和练习；
- 保存现有课程基线，不做覆盖。

### E1：覆盖审计与候选蓝图

- 建立第 4 节覆盖矩阵；
- 标出缺失、重复、顺序错误和证据不足；
- 形成候选目录、最终任务草案及每项目标的资料需求；
- 此时目录是可修订假设，不要求资料尚未核查就先定稿。

### E2：定点资料研究

- 按能力域读取本地项目证据和必要外部资料；
- 建立单一来源清单与证据表；
- 选择适合完整讲解的真实项目案例；

### E3：制作一门完整样课


样课提供已准备好的小型模板、能力契约和输入，明确先备条件，聚焦建议如何成为合法执行。恢复机制只展示一个必要反例，并标出留给后续模块的细节。样课包含：

- 一个从需求到证据的完整正例；
- 一个校验失败与修复示例；
- 一个权限或设计选择对照；
- 一项未展示答案的独立练习；
- 完整来源和必要的图；
- 阅读、练习和反馈时间估计。


分别记录：

- 用户在哪一步卡顿；
- 错误属于概念、步骤、证据还是迁移；
- 需要什么提示才能继续；
- 是否主动使用来源；
- 能否完成独立练习；
- 哪些内容多余或仍然缺失。

先修订样课，不因为篇幅增加或视觉变好就扩写全书。

### E5：决定是否推广

只有样课显示明确学习价值，才决定：

- 是否重排或扩展整门课程；
- 是否生成独立新 Book；
- 是否需要多类型 Block、Markdown 小节目录或结构化来源；
- 是否调整现有作者交付接口；
- 是否进入单独的实施、测试和部署方案。


## 10. 与未来实现方式的关系

### 10.1 内容原型阶段

先使用接近真实阅读器的样稿或独立草稿验证内容，不修改产品。此阶段重点回答“教什么、怎样讲、怎样练”，而不是急于恢复原生自动生成。

### 10.2 若样课成立后的交付选择

| 选择 | 优点 | 代价与适用条件 |
| --- | --- | --- |
| 保留受管作者交付，交付更完整的 Markdown | 改动较小，继续使用已有保护与恢复 | 单块目录、图形和交互表达受限 |
| 受控支持多类型 Block | 接近 DeepTutor 原生丰富阅读体验 | 需要逐类型生成、校验、扩展和恢复测试 |
| 使用原生完整生成链 | 复用 Spine、Page Planner 与内容块规划 | 内容质量、预算、既有保护及恢复需要重新验证 |
| 引入 OpenMAIC 课堂 | 场景、互动和 PBL 表现较强 | 新系统与存储成本高，Slide 默认形式也不等于深度教材 |

当前不预先选择实现。内容样课未证明价值前，不推荐因为原生规划“看起来丰富”就直接切换生产链。


## 11. 质量门禁

任何未来完整课程交付至少检查：

### 覆盖

- 每项最终能力都有章节、来源、示例和练习承接；
- 不存在只有标题或摘要而没有教学内容的必要能力；
- 综合项目使用新任务，不重复展示答案。

### 事实与来源

- 项目事实可回到固定提交；
- 通用知识有合适来源；
- 迁移推演显式标注；
- 链接已实际打开，来源支持对应论断；
- 冲突与未知不被静默抹平。

### 教学

- 重要机制有完整过程，而非只有定义；
- 示例展示输入、决策、输出与证据；
- 练习能暴露具体误解，并有补学与复验；
- 用户试学证据与 Agent 内容审查分别记录。

### 工程与学习证据

- 不覆盖原课程，不删除用户数据；
- 新课不继承旧课掌握结论；
- 保留 release-21 的内容保护、扩展链和恢复规则；
- 实施前另行明确文件范围、模型预算、测试、回滚与部署授权。


## 12. 风险与限制

2. **完整示例可能变成照抄**：必须保留不同场景和未展示答案的考核。
3. **外部课程扩大范围**：只学习与最终能力有关的内容，扩展知识标为辅助。
4. **原生多 Block 增加复杂度**：内容价值成立后再评估，不把块数当质量。
5. **一次用户反馈不是严格实验**：用于诊断，不声称统计有效。
6. **模型生成仍需审查**：格式正确、链接存在和内容忠实是不同检查。
