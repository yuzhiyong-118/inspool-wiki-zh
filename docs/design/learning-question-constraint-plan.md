# 课程题目生产、约束绑定与审查方案

> 公开版本：保留通用契约与方案；历史验收、用户反馈、运行记录及本地素材不随仓库发布。文中状态与验收计数对应原文写作时点的环境，不代表当前部署或验收完成。

## 2. 目标与范围

本次解决：

1. 外部 Agent 已审完整题可原样发布，减少无必要的再次生成。
2. 变式题在真实模型输入中明确学习目标、来源与允许变化的边界。
3. 生成／发布前后都绑定同一规格及实际题目版本，区分结构检查和语义审查。
4. 复用现有生产请求、准备门禁、预算、I4 基线和 I5 交接，不旁路写入。
5. 用可复现的离线反例及后续受控验证，证明实现边界。

首轮仅支持现有单答案选择题，沿用每批 1–8 题及 A–D 选项。随堂预测、自由回答与提示策略保留扩展位置；首轮不新增讲评 Agent、开放短答批改、启用 L0–L3、判断权威掌握度或改造知识准入。

固定上游版本是可复现依据，允许小范围受管补丁。补丁可维护并经真实路径验证，不引入新的通用生成引擎或插件平台。


## 3. 参考机制与取舍

| 来源 | 本次吸收 | 限制 |
| --- | --- | --- |
| rederive | 问题地图、约束排除误解、递进提示、接受满足条件的替代设计 | 不要求所有题只有一个生效规则；不照搬绝不解释 |
| audit-and-rederive | 整理前澄清实质缺口；区分意图、正确性和解释质量；教学与审计材料分层 | 不把已有明确目标的生成偏移当成需求歧义；不要求每题再次确认 |
| admit-only-what-rederives | 消费者固定校验标准、有限返工、最终整体验收、预先定义指标 | 作者代码实验不是教学验证；源码耗尽后继续，不等于我们的阶段硬放行 |
| DeepTutor | 有界参考题生成与修复；复用现有题块和原始学习状态 | mimic 仍会改写；结构通过不代表内容通过 |
| OpenMAIC | 结构化题目、局部编辑、答案与反馈分离、本地选择题判分 | 不复制整套课堂框架；不采用评分故障给半分 |
| Lattice | 先答后评、简短反馈回主线、例题渐退、按表现提示 | 对话讲评是教学观察，不自动形成正式掌握或准入证据 |
| open-notebook／kotaemon | 完整产物才保存、有限上下文引导 | 文本 insight／后续问题建议不是已审测验 |

项目版本、精确源码与复核限制见两份研究报告及其源码清单。PIPE 冻结统计仅核对作者结果，未独立重跑，不据此预期本项目提升率。


## 4. 职责与使用流程


准备者交付讲义、题目规格、完整定稿题或变式参考材料及审查依据。内部消费者呈现题目、收集作答、按已审答案判分和提供反馈，维护既有课程状态；开放式资料整理仍由外部 Agent 负责。

两条生产路径共用内容版本和 I4／I5：

```text
有效学习意图／已有约定 + 来源 + 讲义
                    ↓
        规格与准备材料审校
          ↙                 ↘
定稿题：原样发布         变式题：有界生成
          ↘                 ↙
        实际题目读取 + 结构／字面检查
                    ↓
      最终内容审查 + 整书就绪 + 首次 I4
                    ↓
        网页学习 → I5 只读结果交接
```

发布回执成功、块 ready 和生成结束都不能替代整书就绪或内容审查。未通过的候选不得据此宣称可开始正式学习。


## 5. 最小题目规格

新增项目侧独立、封闭协议 `learning-question-spec/1`，使用 UTF-8 JSON 与现有 canonical/digest 规则。文件作为准备附件保存，不向旧 prepare.json／KnowledgePackage 顶层塞未校验字段。新增接口或描述符必须明确升级并拒绝未知字段，旧版本按原规则读取。

| 字段 | 含义 |
| --- | --- |
| schema、specId、lessonRef、lessonSha256 | 协议、稳定规格身份、讲义／版本引用及实际讲义字节摘要 |
| learningAgreementRef | 已接知识准备链时引用有效约定；独立纯 L 可不依赖 K，但仍明确目标 |
| sources[] | sourceId、sourceVersionId、sha256、locator、excerpt；核对实际冻结来源与原字节连续摘录 |
| objectives[] | id、description、evidenceRequired：目标描述及可观察的答题要求 |
| items[] | questionId、mode（authored／variant）、targetObjectiveId、sourceRefs |
| items[].criteria | requiredLiterals、forbiddenLiterals、scenarioConditions、allowedChanges；前两项机器检查，后两项还须语义审查 |
| items[].misconceptions | 可选：典型误解、错误原因、规则／来源定位；不要求各误解违反不同规则 |
| items[].hints | 可选：提示阶梯／反例／例题渐退材料，不作为全局必填课件 |
| items[].authoredItem | 定稿模式必填：question_id、question_type、question、options、correct_answer、explanation |
| items[].referenceTemplate | 变式模式必填：现有六字段模板；与 authoredItem 互斥 |

Q1 已交付[JSON Schema](../../tools/learning_book/schemas/question-spec.schema.json)、[样例与使用说明](../../tools/learning_book/examples/questions/README.md)、[独立模块](../../tools/learning_book/question_spec.py)。目标与来源引用闭合、跨记录 ID 唯一、总字节与实际输入核验由应用补充检查；不能声称普通 Schema 单独证明这些性质。定稿模式互斥、选项 A–D 非空且答案键唯一、解释非空。

默认上限：1–8 题、最多 16 个直接来源，单字符串不超过 32,768 字符，规范 JSON 总长不超过 256 KiB；这是本次规格的设计限额，不表示当前上游已有相同限额。超过时先拆包／缩小范围，不静默截断或只看前半段。具体输入若受更严格的现有请求上限约束，先给诊断，不偷改预算。

来源与讲义不必在每次请求中全量重复；允许经核验的定位和有界摘录。生成模型必须得到足够的规则、例外与否定条件，不能仅传摘要、关键词或无法访问的本地路径。

### 5.1 两个不同的摘要

- `specDigest`：冻结规格及所引用来源身份，并显式附 authoredOptionOrders，避免 canonical 排序对象键后丢失显示顺序；同 specId 不同内容必须形成新版本／冲突，不能覆盖。
- `questionDigest`：实际题目的 ID、题型、题干、选项键及内容、答案、解释，加 optionOrder；不把运行时间等观察字段混入。已知 difficulty／concentration 标签不参与此摘要，未知其他字段拒绝。

选项顺序同时按现有投影留存，变化须重审。两个摘要 envelope 及确切算法见Q1 接口核对（未随公开仓库附带）。模板字母与最终选项内容不等价，不能把旧的“A 对应 C3”直接套到生成结果。


## 6. 两条路径的接口约定

以下名称是拟新增操作，不是当前已可用命令。

### 6.1 定稿发布 publish-quiz

由 Production 提供窄业务操作，入参含 activityId、requestId、pageId、blockId、expectedRevision、规格／定稿内容引用及审查引用。只替换当前草稿中的指定 quiz 块；不提供任意 HTTP、路径写入或任意块类型编辑能力。

已选窄端点 `POST /api/books/publish-quiz` 与 `PublishQuizRequest`，并配只读 publication 状态查询，详见Q1 接口记录（未随公开仓库附带）。Q2 通过受管 API／Engine 补丁写入，复用锁、revision、取消／并发控制和事件，**不调用模型**；单文件存储不足以构成多文件事务，须补最小写 journal 并验收后才能开放。不能只在 QuizGenerator 中加分支却漏掉原生入口与授权保护。

应用前重验实际来源、规格、目标块及审查绑定；应用后重新读取并逐字段核对定稿内容、题目摘要和 revision。仅允许协议中显式说明的无损规范化，不修改题干或选项措辞。失败不得假报原样发布成功。

定稿审查针对完整题目；发布后实际内容与已审内容完全相同才能复用其题目审查部分，首次 I4 仍负责整门课程的审校与接受。若有任何实质差异，返回待重审。

### 6.2 变式生成 prepare-quiz

兼容旧六字段模板路径；新规格绑定的调用在发出请求前生成**可审阅的实际请求体**，把目标、适用条件、来源摘录、例外、允许改写边界传入真实模型提示。复用 QuestionPipeline 与有界修复，不另造循环。

Q1 已选并实现确定性编入 reference_question，保留原六字段与 reference_answer；先校验实际讲义、来源及摘录字节，包含目标、场景条件、例外所在摘录、改写范围与规格摘要。超过现有 32,768 字符限制即拒绝，不截断。Q2 才留存并发送该实际请求，检查标准与模型输入必须来自同一规格；不再同时维护另一个含义不同的上游输入字段。

生成后读取最终题目，执行确定性检查，形成最终题目的误解／选项解释并审校。生成者自报“通过”不等于可信内容审查。沿用现有允许的审阅角色与凭据；不要求为了形式增加第二个 Agent。

每题沿用当前最多两轮 quiz 生成迭代及至多一次格式修复；具体模型调用数还受工具／提供方实现影响，必须按实际调用和总 token 记录。默认不自动进行语义返工：语义偏离退回，只有明确的后续修订请求才重试。


## 7. 校验与审查边界

| 层 | 可确认的内容 | 不可据此确认的内容 |
| --- | --- | --- |
| 规格与引用 | 字段合法、引用闭合、来源字节和版本匹配、摘要有效 | 来源的事实正确性与教学质量 |
| 题目结构 | 题型、ID、题干／解析非空、选项与答案键合法 | 答案受来源支持、只有一个语义正确选项 |
| 字面条件 | 强制保留编号确实出现、明确禁用词不存在 | 条件实际成立、否定／例外被正确理解 |
| I4／I5 | 已审课程版本、实际学习观察及其交接范围 | 另造知识权威或绕过现有准入 |

例：“BY-042 核验 F-017 与 F-071，不存在编号不一致”能命中全部编号及“不一致”，却不是编号冲突场景。机器只能报字面条件通过；内容审查必须拒绝偏离目标的产物。未完成审查的状态用 pending_review，不用机器“通过”冒充语义通过。

删除旧稿以下规则：所有干扰项必须映射不同约束；字符串能判断理由不违反约束；每题其他约束都不生效。来源原文之外的新案例是否允许由题目的改写边界决定，不以“出现新编号”一概拒绝。

本项目不为一般课程构建规则求解器；未来只有具备完整领域规则且值得维护时，才另行讨论执行语义判定。


## 8. 版本、门禁与恢复

- 绑定含 scope／activity／book／page／block、生产请求、规格摘要、来源／讲义版本、实际题目摘要、内容审查引用。请求同 ID 不同语义拒绝；unknown 不自动换 ID 重发。
- 准备附件进入请求证据、准备 provenance 和后续回读。接入 K 的 publish-quiz 必须同步扩展显式操作白名单、步骤审阅、continuation／提交前重验，不能只扩 Production 忘记 guard。
- 已带绑定的 activity 不得通过省略规格、关闭检查器、原生再生成或旧接口静默降级。原生内容改变后必须检测漂移并阻断现有绑定的继续接受；不承诺当前所有入口已经被保护。
- 尚未绑定的旧活动保留原读取与原流程，不伪造规格；未升级的软件看到必需的新绑定应明确拒绝继续受控接受，不能静默忽略。
- 新摘要不能改变旧快照／包的摘要算法。附件协议与消费者能力显式标识；I4 采集、接受、当前内容检查、I5 打包和离线校验均检查并携带必需绑定。
- Q1 已选独立 learning-question-preparation/1 附件；有新绑定的 I4 快照与 I5 包用显式 /2 协议及 learning-question-evidence/1，旧 /1 保持原字节与边界。Q2 未交付相应 Schema、安装和校验前不得产出 /2；不往封闭旧 prepare.json／知识包塞字段。
- Q2 使用更窄的首次绑定规则：未绑定 quiz 可在首次 I4／学习前逐块发布；题块绑定后，修订先创建替代 activity/book，保存旧快照与作答，不原地重绑旧答案。原生内容编辑／删除不能覆盖绑定；聊天映射和原进度维护仍允许。这样不另建草稿题目版本库，代价是纠错需要替代活动；本轮不把草稿原地修订算作已实现功能。
- 新补丁与原生入口守护必须进入本地安装、版本核对、离线／恢复安装清单。旧安装缺少能力时提前诊断，不以应用端成功发请求代替服务端可用。
- 多文件写入、断电与未知响应只按现有已证明的事务能力处理；若所选上游入口不能保证所需原子性，Q1 接口核对提出具体缺口，Q2 修复后才开放，不能假设具备。
- 未通过的草稿只存在生产状态；不增加第二套用户学习进度库。正式知识候选、G3、Executor、raw approve 保持原职责。


## 9. 与整体工作包的依赖

| 工作 | 关系 |
| --- | --- |
| Q1 离线契约与接口核对 | 可独立开始，不等待 W1／M1，不访问真实运行配置 |
| W1 导航与诊断 | 复用其应用操作／CLI 风格；Q2 只补本专题所需入口，不顺便实施完整 W1 |
| E1 受管编辑与整书完成 | 共用 Production、revision、审阅及完成交付契约；Q2 不另建编辑系统。新编正文课程到首次 I4 须具备 E1；可用独立就绪夹具验证 quiz 操作本身 |
| M1 成本归因 | 实际 token 对照须具备本次调用归因；Q1／Q2 的零模型检查不等待全量 M1 |
| W2／C2、S1 来源影响 | 消费已审冻结版与来源有效性，不能借出题绕开；不将它们整体实现塞进本专题 |
| W3／W5 | 复用定稿不再生成、局部修改与同任务对照结论；无测量不宣称节省率 |

新题目能力若影响 E1 的共享接口，应在该工作包同步说明。当前整体路线仍是 W1 为总修订入口；本专题 Q1 是可先独立完成的离线任务，不把全系统重新排成必须先跑出题。


## 10. 实施顺序与验收

本节是**重整后的 Q1–Q3**，旧稿将真实模型对照放在接入前的顺序不再执行。

| 阶段 | 交付与通过条件 | 不在通过范围 |
| --- | --- | --- |
| Q1：契约及离线验证 | Schema、样例、纯函数校验／摘要、生成输入渲染、当前接口核对与负例；证实不会把字面通过当场景通过 | 生产接线、真实 API、教学效果 |
| Q2：受管接线与独立实例验证 | 定稿发布＋变式绑定进入真实应用路径；临时状态／本机隔离实例验证，无模型；版本、门禁、未知恢复、I4/I5 与安装链兼容 | 真实生成质量、正式库／旧课迁移、净 token 收益 |
| Q3：受控试用与成本对照 | 在数据外发及预算授权有效时，验证定稿／变式的实际课程、重启、作答、导出；报告内容质量与成本 | 普遍因果结论、教学效果提升、自动掌握认证 |

离线验收包含：真实失败产物原字节回归、编号齐但场景否定、同义改写、同规则不同误解、选项重排、来源／讲义／题目变化、绑定缺失或关闭、请求重放、unknown 不重发，以及老包可读而不伪造新绑定。详细用例与停止点见任务书。
