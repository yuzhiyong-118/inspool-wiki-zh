> 状态：E1／E2 首轮工作稿已形成；G-01～G-03 与完整样课 run-02（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-course-authoring/run-02/README.md）已完成，等待用户试学与独立内容审查。

## 1. 审计范围与口径

审计对象是当前五章课程（未随本仓库发布：docs/learning/geo-flow-agent/README.md）、现有学习约定（未随本仓库发布：docs/learning/geo-flow-agent/active-brief.json）及 `docs/learning/geo-flow-agent/sources/` 的 8 份本地资料。

两个系统严格分开：

- **教学系统**：DeepTutor 与作者交付，负责承载课程内容；
- **被学习对象**：目标课程项目 固定提交中的 Flow、Capability、Agent 与 Engine。

“现有覆盖”只表示课文中出现相关内容，不表示已经形成完整教学或用户已经掌握。示例验证分为源码追踪、离线校验和真实运行，三者不互相冒充。

## 2. 交付物一：能力覆盖矩阵

| 能力域 | 先备能力 | 达成标准 | 当前覆盖 | 主要缺口 | 验证方式与学习负担 |
| --- | --- | --- | --- | --- | --- |
| 任务与领域对象 | 能区分文件、配置和一次执行 | 为新场景定义领域对象、Flow 与 Run，并说明各自拥有的事实 | 第 1、3 章有定义和一句话职责 | 没有从真实需求逐步推出对象；DataSet 的真实字段与状态实例不足 | 源码追踪＋对象设计；约 15 分钟 |
| Capability 设计 | 领域对象与输入／产物概念 | 写出含参数、产物、错误、幂等和状态副作用的最小契约 | 第 2 章列出契约字段；`vector-flow.json` 提供使用位置 | 缺一份真实 CapabilitySpec 全字段解读；缺非法输入的实际校验输出 | 源码追踪＋离线校验；约 15 分钟 |
| Flow 编排 | Capability 契约 | 接出合法生产者—消费者关系，并判断改参数／扩能力／新增模板 | 第 2 章有原则和虚构文档片段；本地有完整 Vector Flow | 真实模板没有逐环讲解；产物登记、环序和引用错误只有结论 | 真实模板源码追踪＋断线离线校验；约 20 分钟 |
| Agent 权限与建议 | Flow 模板与 Capability | 分清模型原始输出、服务端实例化、校验、确认和执行 | 第 4 章职责描述准确；`advisor.py` 已证明模板选择＋参数边界 | 缺原始 `template_pick` 到实例化 Flow 的逐对象示例；run-01 B 不可复用为项目事实 | 源码追踪＋实际 sanitize／校验结果；约 20 分钟 |
| 执行与失败恢复 | FlowRun、Capability 幂等 | 区分未执行、失败和结果未知，设计不盲目重发的恢复 | 第 3 章有规则和两个练习；`runner.py` 有调度、重试和状态实现 | 缺真实步骤记录、失败输入与恢复时序；外部发布“结果未知”的证据来源未讲清 | 源码追踪＋离线故障测试；约 15 分钟 |
| 验证与目标证据 | 执行状态与产物 | 区分 Run 成功、Goal 达成、验证豁免和用户确认 | 第 4 章有结论；Vector Flow 保存认证摘要 | 缺真实 Goal／Run／Probe 对照；“成功但未达标”没有完整案例 | 文档／证据源码追踪；真实运行仅作可选展示；约 15 分钟 |
| 独立综合设计 | 上述六项 | 面对新任务提交自洽设计，解释关键取舍 | 第 5 章要求完整设计 | 最终任务与全书贯穿示例同为 Markdown，迁移证据不足；提示与评价层级未定义 | 新任务＋人工评价；约 25 分钟 |
| 扩展知识迁移 | 核心设计已经完成 | 识别其他 Agent 模式中哪些适用于自己的系统 | 当前只有“不必使用重型框架”的结论 | Reflection、Planning、Evaluation 等只有外部参考，尚未按需选择；不应挤压核心课时 | 选读，不计入 125 分钟核心预算 |

### 审计结论

当前课程不是“没有内容”，而是**定义、原则和练习要求较多，完整教学过程较少**。优先补齐真实 Capability、真实 Flow、Agent 实例化和故障证据，不需要先增加新框架或更多抽象概念。

## 3. 交付物二：候选课程目录

总预算暂沿用 125 分钟，包括阅读、练习和反馈。以下是待试学校准的估计，不是已测耗时。扩展阅读另列，不挤占核心时间。

### 模块 1：从任务到对象与权限边界（15 分钟）

- **先备**：无；只需基本 JSON 和程序输入／输出概念。
- **核心**：DataSet、Flow、FlowRun、DraftFlow；Agent 建议与真实写入的区别。
- **完整案例**：从一个 GIS 任务识别领域对象、执行定义、运行实例和外部动作。
- **练习**：为本地文档任务划分对象与职责。
- **证据方式**：源码追踪；不要求运行 GIS。
- **时间**：阅读 10 分钟、练习 4 分钟、反馈 1 分钟。
- **选读**：Agent 自主性分级，不作为 目标课程项目 事实。

### 模块 2：Capability 是契约，不是函数名（15 分钟）

- **先备**：模块 1 的对象与产物。
- **核心**：ID、参数 Schema、产物 spec、确定性执行体、错误、幂等与 `state_effect`。
- **完整案例**：逐项阅读 `vector.prepare` 的真实能力定义，再观察一份非法参数如何被拒绝。
- **失败例**：缺必需参数、非法 `$work` 路径各选其一，避免一次堆叠全部错误。
- **练习**：为文档扫描能力写最小契约。
- **证据方式**：源码追踪＋离线校验。
- **时间**：阅读 9 分钟、练习 5 分钟、反馈 1 分钟。

### 模块 3：把真实 Capability 接成 Flow（20 分钟）

- **先备**：模块 2 的产物与参数。
- **核心**：环、步骤、快照、引用、ArtifactRegistry、生产者—消费者校验。
- **完整案例**：沿 `flows/vector/flow.json` 追踪 `prepare → publish → enable_mvt／metadata → render-verify`，说明每个引用的来源。
- **失败例**：把一个 `$artifacts` 引用改成未登记产物，记录实际校验错误。
- **对照**：修改路径／阈值、增加产物形态、新增场景模板分别属于什么变化。
- **练习**：修复一份断线的文档 Flow。
- **证据方式**：真实模板源码追踪＋离线校验。
- **时间**：阅读 10 分钟、练习 8 分钟、反馈 2 分钟。

### 模块 4：Agent 建议怎样成为合法执行（核心 20 分钟，选读另计）

- **先备**：已提供并读懂模块 2～3 的小型能力契约和模板，不要求现场设计整套系统；样课内直接给出三种建议类型和同案状态表，不假设学习者已掌握 `clarify` 或确认环判断规则。
- **核心**：模型只输出 `template_pick / clarify / message` 等受限建议；服务端确定性实例化整份 Flow；校验、确认与执行是后续不同事实。
- **完整正例**：用户意图 → 模型格式 `template_pick`（run-02／run-03 为手工构造）→ `_instantiate_template` 结果 → `validate_draft` → 创建 draft Run → 按环确认 → REST → Engine；逐步列出对象、触发者、可声称事实和证据级别。
- **失败例**：模型直接输出 `draft_flow`，展示被拒绝及修复重试的边界。
- **对照**：提示词写“不要执行”与架构上不提供执行句柄。
- **必要恢复反例**：确认后外部写入结果未知，不得换 Run 盲目重发；详细恢复留到模块 5。
- **独立练习**：为新的本地任务写模板匹配、澄清和能力缺口响应；分别评价建议类型、字段边界、状态触发者、权限和恢复，并用短变式复验。
- **证据方式**：源码追踪＋实际 sanitize／离线校验；不把示意响应当真实执行，不把 Engine 启动当成完成或目标达成。
- **时间**：核心阅读 8 分钟、首次练习 7 分钟、反馈与短变式 5 分钟；`vector.prepare` 产物细节和外部源码深读为选读。该分配仍需用户试学实测。

### 模块 5：失败、恢复与重复写入（15 分钟）

- **先备**：FlowRun、确认与幂等。
- **核心**：步骤 attempts、失败状态、当前环恢复、幂等跳过、状态不回摆。
- **完整案例**：同一 Run 从失败环恢复，已成功幂等步骤跳过。
- **失败例**：发布已发出但响应丢失，先核对执行记录与外部状态，不直接重发。
- **练习**：为文档发布写两条恢复规则。
- **证据方式**：Runner 源码追踪＋已有或新增离线故障测试；不要求真实外部发布。
- **时间**：阅读 8 分钟、练习 6 分钟、反馈 1 分钟。

### 模块 6：执行成功不等于目标达成（15 分钟）

- **先备**：执行、产物和恢复。
- **核心**：GoalContract、Probe、RingDecisionEvidence、显式豁免和认证摘要。
- **完整案例**：把 Vector Flow 的认证摘要与对应 Run／环／渲染目标证据关联，同时说明摘要不是完整证据。
- **反例**：Run 完成但渲染验证被跳过，只能形成带豁免的结果。
- **练习**：为文档任务写四条状态声明及各自证据。
- **证据方式**：文档与固定模板源码追踪；如引用真实 Run，必须保留实际证据，不能用模板中的摘要冒充本次运行。
- **时间**：阅读 8 分钟、练习 5 分钟、反馈 2 分钟。

### 综合项目：新场景独立设计（25 分钟）

使用第 4 节的新任务，不重复 Markdown 示例。时间暂估为独立设计 18 分钟、评价与补学计划 7 分钟。若真实试学显示 25 分钟不足，应减少前置内容或由用户调整预算，不把未完成产物标为已掌握。

### 选读扩展

Reflection、Planning、Multi-Agent、MCP、Skills 和 Hooks 只在用户需要时进入，不作为核心前置。每项必须说明它解决什么新问题，以及为什么 目标课程项目 当前薄 Agent 不必然需要它。

## 4. 交付物三：最终任务及评价标准

### 4.1 学习者任务：本地借阅记录汇总与摘要发布

现有一批本地图书借阅记录 `borrowings.csv` 和一个输出目录。系统需要：

1. 检查文件存在、UTF-8 可读、必需字段齐全、日期格式合法；
2. 按图书类别生成借阅次数摘要和一份 HTML 报告；
3. 用户确认后，才把报告写入输出目录；
4. 回读实际文件，核对内容摘要；
5. Agent 可以推荐模板、提取路径和回答疑问，但不能直接读写文件。

明确排除联网、真实个人数据、自动修改原始 CSV、自由执行 Shell 和真实外部平台发布。课程没有展示这个任务的答案。

### 4.2 需要提交的设计物

1. **领域对象**：定义批次对象与 Run 的边界，列出来源摘要、剖析、产物、状态和错误；
2. **Capability 契约**：设计 3～5 个能力，写参数、产物、错误、幂等和状态副作用；
3. **Flow 配置**：用显式引用连接检查、汇总、发布和回验，标出确认环；
4. **Agent 建议**：给出模板匹配、模板不唯一和能力不支持三种原始输出，并注明服务端何时实例化 Flow；
5. **故障恢复**：分别处理“输入校验失败”和“发布结果未知”；
6. **验收证据**：区分草案校验、用户确认、执行完成、实际回验和显式豁免；
7. **设计说明**：解释至少两项可选设计及自己的选择。

### 4.3 作答条件与提示记录

- 可以查课程、固定源码、官方文档和接口参考；
- 可以用 Agent 询问概念或解释错误，但不能让 Agent 代做核心对象、Capability、Flow 和恢复设计；
- 分别记录无提示、概念提示、结构提示或部分答案；
- 当前默认目标是“能设计”，不是实现或运行完整软件；
- 若项目已有适用校验器，可追加“经校验”；没有时不得把人工检查写成通过确定性校验。

### 4.4 人工评价表

| 维度 | 达成标准 | 必须修正的错误 |
| --- | --- | --- |
| 对象与状态 | 业务事实、执行定义和运行实例分开；每个状态有明确写入者 | 把所有内容塞进一个 `success`；Run 与领域对象混写 |
| Capability | 输入、产物、错误、幂等和副作用可检查 | 只有函数名；产物未声明；用模型代替确定性规则 |
| Flow 接线 | 每个引用有唯一、前序、已登记来源；确认位于发布前 | 引用未来产物、未声明产物或隐式共享文件 |
| Agent 权限 | 原始输出是受限建议；实例化、校验、确认和执行职责清楚 | Agent 直接读写、返回执行句柄或自由生成未校验 Flow |
| 恢复 | 区分未执行、失败和结果未知；重试有幂等或核查依据 | 响应丢失后换 Run 直接重发 |
| 验收证据 | Run 完成、Goal 达成、回验和豁免分别有证据 | 把 Run 成功当成全部目标满足 |
| 解释与迁移 | 能解释取舍，并适应 CSV／汇总场景 | 只替换示例名词，结构问题仍未处理 |

所有关键错误修正后才能记为“能设计”。满足相同约束的不同对象命名、能力拆分、环划分和验证方式可以接受，不要求与参考解逐字一致。

评价者应在开考前另备参考解与可接受替代，不随学习材料展示。评价结果分别记录当前层级、提示程度、关键错误、补学位置和变式复验结果；Agent 建议不是正式掌握认证。
