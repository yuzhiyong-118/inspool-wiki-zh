# 学习驱动入库的分阶段调研与实施路线图

> 2026-11-11 续接：知识准备业务按[知识准备链方案与任务书](knowledge-preparation-plan.md)细化。它衔接已实现的 DeepTutor 消费链，保留旧来源与证据要求；K0–K4 是待实施工作项，不扩大 S0／S1 的验收范围，不自动激活旧 S3 的独立理解门禁。本轮仅完成设计，尚待独立复审与实施。

> 配套[总体方案](learning-gated-ingest-plan.md)及[持久循环与受控扩展设计](learning-ingest-runtime-loop.md)。S0 与 S1 已完成验收；S1 后续审查发现的恢复、执行资格和结果完整性缺陷已修复，并经独立复审及最新完整历史回归重新通过，证据见[审查记录](learning-ingest-review.md) §34–35。S2–S5 尚未实施或通过阶段验收。历史 passed 只覆盖其记录范围，每阶段只验收实际完成能力，完整业务要求持续保留到依赖齐备时验收。

## 分期原则

- S0–S5 是本次改造的阶段，区别于上一轮已归档 T00–T11；Executor、CandidateView 和契约保留职责，Coordinator 按有界 Step Driver 重构，不为复用旧实现保留第二套循环。
- 每阶段只处理 1–3 个决定性问题；已有出处和代码证据直接复用，不为完成调研重复搜索。
- 每阶段形成“问题—证据—选项—取舍—实现—验收—遗留项”记录，使用固定样例比较效果和成本。
- 用户已授权按阶段推进；现行规则变更、未授权服务接入或超预算扩展仍按具体范围处理。不得凭路线图跳过前置门禁。
- 开发只用临时库和合成／明确允许的样本，不使用真实 raw、正式索引或既有学习资产做破坏性测试。
- 每个阶段必须新增一段可运行能力或可执行协议验证，不能只以文档数量宣称完成。

## 跨阶段执行约定（每阶段开始与交接时必读）

以下为 2026-11-02 用户明确要求的工作方式，适用于 S0–S5，不替代 [AGENTS.md](../../AGENTS.md) 的现行知识库维护规则。

1. **尽量使用多 SubAgent 协同**。独立调研、接口核对和验收审查可并行；主 Agent 负责依赖、预算、冲突和汇总。子任务使用独立最小上下文，明确目标、输入、允许范围、交付和停止条件；存在依赖的工作按序执行。
2. **渐进式披露上下文**。先读交接摘要、当前阶段和任务书，再按文件／章节定位必要材料；不默认传整段会话、全库或全部历史任务。
3. **按需使用 Skill**。复用现有 teach、检索和资料提取机制，区分实际调用、设计参考和候选未接入；不自动安装第三方技能。
4. **重复确定性工作优先沉淀脚本**。优先复用 Health、契约、候选与 Executor；不能脚本化的语义判断保留人工／独立模型审查。
5. **每阶段有可复验门禁**。开始时明确输入基线、产物、通过条件、失败样例和检查方法；交付时运行确定性检查，并由独立 SubAgent 审查实质设计／语义。不得以文档齐全、模型自报或测试替身代替实际验收。
6. **失败形成有界修复循环**。定位具体缺口，只重做受影响产物并复验；生成者不得放宽标准。共享预算跨 SubAgent、重试与恢复持续计数，预算耗尽或证据不足则暂停。
7. **交接必须落盘**。每阶段结束或压缩上下文前更新当前阶段、已完成／未完成、产物路径、证据绑定、实际命令与结果、失败、预算和下一步。无可信 token 统计记 unknown。

**阶段放行清单**：范围与基线明确→必要任务产物汇总→确定性检查通过→独立语义审查通过→修复后复验通过→交接落盘。未完成项不得作为下一阶段已有依赖。

## S0：实体、模块接口与贯穿场景

**目标**：把 v0.7 转换为可执行协议和固定合成样例，不提前实现后续业务。

**交付**：

- 核心实体、生命周期、唯一写入方和目录边界。
- Task Runtime、KnowledgePackage、Knowledge Output、Learning & Assessment、Knowledge Persistence、Executor 的接口。
- 单条 Invocation 的原子预算、重放、发送与结算协议。
- ReviewCredential 的可信复用条件。
- Readiness、授权、完整 WAL 和恢复归并协议。
- 正常文本、外部纠错、跨会话恢复三个场景的步骤、预期状态、所需证据和阶段归属。
- 可执行的协议校验与负向合成样例。

**S0 验收**：已通过。59 项目标测试、451 项完整回归及独立审查通过；公共契约保持兼容。通过仅限协议字段、引用、版本、状态、负向样例和阶段归属，真实锁、Executor 恢复和完整业务链路仍未验证。证据见[审查记录](learning-ingest-review.md) 第 15–16 节。

**2026-11-07 循环协议增量**：RuntimeTask／LearningState 分离、Event／Step／Wait／WorkItem／StepResult／WorkflowRef、版本绑定及负向样例已作为 S1 Task 0 完成实施与独立审查。该结果不回写或扩大历史 S0 的通过范围，证据见审查记录 §23。

**停止条件**：仍保留双层权威预算、Host 成为另一套业务总控、知识包不能承载证据与冲突，或 S0 验收要求依赖尚未实现的后续业务。

详细入口：[S0 详细任务书](learning-ingest-s0-plan.md)。

## S1：统一任务运行时与文件事务基础

**前置**：既有 S0 与本次循环协议增量通过；修订后的运行时设计和 S1 任务书独立复审通过。

**交付**：

- SQLite Task Runtime 统一 Event、Task、Run、Step、Invocation、Wait、WorkItem、预算、授权和结果登记；学习阶段作为领域状态分离。
- 单次原子预留同时检查 Task、Run、并发和最终验证留额。
- 统一 Agent 调用与可信 ReviewCredential 记录；条件不满足时保留独立重审。
- Host 仅作为交互、工具和身份入口。
- Coordinator 重构为 Step Driver，Host／CLI derived、`refresh_index` 及 `run_heal`／`heal_missing_pages`／`heal_broken_links`／`heal_index_sync` 全部业务写入口统一适配；只读预览保留，不保留第二权威账本或执行循环。
- 不可变 PolicyRevision、submission_epoch、完整 Event 业务信封和静态可信 registry；仅用合成工作流证明事件与恢复机制，不建设通用插件平台或 schema 迁移框架。
- Executor 沿用现有 journal_root，提供终态查询、最终准入、完整 WAL、文件应用和独立恢复；T1 先交付最小 freeze／inventory／runner／重启检查及五个写分支的 freeze 拒绝。
- 旧 pre-WAL pending 的 drain／supersede 与全部 Python API 写入口切变。
- 应用前撤销、应用后补偿和归档后修正的完整路径。

**最低真实验证**：

1. 审查期间完成撤销、Readiness 失效或执行所有权换代，不能接受旧操作。
2. 接受点附近崩溃能由完整 WAL 唯一判断接受状态，包括 acceptance_check 成功后、WAL 前崩溃。
3. 同一 invocation 重放不重复调用、扣费或结算；未知结果不自动退款；Worker、Reviewer、RuleAuditor 和 Executor G3 共用同一 InvocationPort。
4. Executor 回滚不归并为 applied；已接受事务恢复不依赖旧租约。
5. 已 applied／recovered 操作在 Run 过期或库变化后仍直接返回历史结果。
6. 同 Host 双线程和不同进程撤销均不被长审查阻挡。
7. 真实宿主身份绑定、生成者自签、缺角色、跨任务／跨候选重放均被拒绝；探针不可用时禁用凭据复用，并验证 Executor 确实独立重审。
8. Host 不能独立修改任务、预算或审查状态，Coordinator 原计数只作非权威执行历史。
9. [L1–L9 与 C1–C5 故障矩阵](learning-ingest-runtime-loop.md#8-单路径与阶段验收)：事件／结果原子化、Step 接管归并、旧 WAL／pending、pause→resume、derived 与 Python API 入口、离线 cutover 重入及 SQLite busy／备份。

**停止条件**：仍有两个权威预算或接受记录，Host 与 Runtime 状态相互复制，Executor 恢复依赖学习任务租约，或旧 WAL／pending 和任一清单内入口未完成切变。

详细入口：[S1 详细任务书](learning-ingest-s1-plan.md)及[运行时协议](learning-ingest-runtime-loop.md)。S1 按 T0–T7 实施：先固定协议和旧 WAL 兼容，再建设 SQLite／Invocation、持久循环、最终接受、学习入口及全局切变。完整文件 WAL 仍是唯一接受事实，现有 journal_root 不改变；财务与资源分离、Task／Run 双留额、ingest／approve 两类授权均保留，S1 不激活 capture/import 授权。

**S1 验收：已于 2026-11-09 通过，并在后续缺陷修复后重新验收。** T0–T7 全部完成；修复版 T1–T6 合并 135 项、最新完整历史中的 X／L／C 26 项通过；全部历史共 38 个测试文件、612 项完成，所有分片退出码为 0，Executor 独立恢复 28 项通过、1 项权限跳过。§34–35 的后续审查及复审追加问题全部关闭，独立复审为 overall passed。通过仅限持久运行时、文件事务、恢复与切变基础设施，证据见[审查记录](learning-ingest-review.md) §33–35；真实宿主、真实 L3、教学质量、真实 scoped 状态及 S2–S5 不在通过范围。

## S2：最小知识证据链与 Wiki 候选

**前置**：S1 能提供可信调用、授权、接受和恢复基础。

**交付**：

- Source、Evidence、Claim、Evidence–Claim Relation 和冲突记录。
- 包含适用条件、证据、原文定位、版本、可读范围、冲突和既有知识关系的 KnowledgePackage。
- 临时补证到持久原文、本地 sources 和最终 G3 input_refs 的映射。
- 主张核验、冲突处理、来源去重和依赖传播。
- Knowledge Persistence 将指定知识包映射为 Wiki 候选，生成四种教学处置和图谱关系覆盖记录。

**最低验证**：正常文本与外部证据纠正两个临时库场景；Evidence metadata 不代替 G3 原文；同一证据可支持一个 Claim、反驳另一个；未决冲突不强行选赢家；新增输出语义返回知识修订。

**停止条件**：知识包缺少关键证据或版本，普通 ingest 偷增 raw，或候选覆盖存在未登记语义。

## S3：课程、学习反馈与独立理解验收

**前置**：S2 能提供已核验知识包和候选预览。

**交付**：

- `output/` 的课程适配器生成 Lesson；Learning & Assessment 管理 Objective、Tutor、Rubric、Assessment 和补讲。
- 概念、机制、程序性、迁移和综合推理目标使用匹配证据。
- 提示辅助与独立作答分开，核心目标不被总分抵消。
- 可复用 rubric_template 与本课 rubric 分离；本课答案仍须独立证据审查。
- 固定案例、holdout、重复判分、不一致裁决和 L2 阻断。
- 学习记录局部失效、跨会话恢复和用户纠错。

**最低验证**：用户先获得讲解再作答；提示复述不算独立掌握；核心误放行或校准不适用阻断 L2；候选只教 A 却含 B 时拒绝；可选和非教学不伪造 Assessment。

**停止条件**：需要把核心目标降为可选消除失败，或校准只记录而不阻断。

## S4：来源演进、扩展校准与其他输出

**前置**：S3 已形成可用学习闭环。

**交付**：

- 来源 discovered／trial／active／restricted／retired 生命周期、审计、降级和回退。
- 博主、社区、学术平台及研究中发现来源的主题适配和复核。
- 扩展判分校准的适用领域与成本记录。
- Article、VideoScript 等其他 Knowledge Output 适配器及输出专属质量标准。
- 输出新增事实、结论变化或范围扩大时的知识修订请求。

**最低验证**：新来源主要增加注册与适配数据；来源热度不替代证据；新增输出类型不修改 Task Runtime、证据链、学习门禁或知识沉淀接口；公开发布仍需具体授权。

**停止条件**：需要为新输出类型复制证据或事务系统，或来源／输出可以自行提升信任与授权。

## S5：真实小批次知识沉淀与效果验证

**前置**：S0–S4 的能力均有各自验收，现行规则变更形成具体 diff 并按授权批准。

**交付**：

- 真实小批次的正常文本、外部纠错和跨会话恢复验证。
- Readiness、ingest 授权、Executor ingest、pending_review、approve 授权、Executor approve 和 processed。
- 中断恢复、重放、用户后续编辑、撤销、补偿和伪造凭据的失败用例。
- 用户学习时间、重复追问／确认、迁移应用、恢复负担、模型与工具成本记录。
- 面向用户的使用入口、实际能力边界和剩余风险。

**最低验证**：未理解、未确认或未解决冲突时不应用；写入内容与学习和审查版本一致；raw 与 Wiki 同批受控；历史批次不回退、不补造学习记录。

**停止条件**：需要绕过 Executor、跳过业务批准、篡改审查结果或把测试替身当真实宿主证据。

## 每阶段统一交付格式

1. 本阶段决定性问题及复用材料。
2. 实际新增来源、版本／日期、可见范围和未验证内容。
3. 选择与放弃的方案、成本依据、规则和接口差异。
4. 可运行产物、可复现命令、实测结果和失败样例。
5. 遗留问题、下一阶段允许依赖的最小接口和运行边界。

阶段产物只在需要时创建，不提前生成六套冗长任务书。跨阶段共享同一知识包、证据摘要、协议和运行时；研究发现不会未经审查自动升级为规则或正式知识。
