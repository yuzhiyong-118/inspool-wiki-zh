# 本地学习系统收尾计划

> 本文为历史设计记录，随设计迁移整理发布。文中状态与验收计数对应原文写作时点的环境，不代表当前部署或验收完成。私人证据未随本仓库发布，引用处以「证据未公开，无法由本仓库独立复核」标注；本机路径已抽象为占位符，执行时替换为实际路径。

状态：工程收尾已交付，整体尚待用户亲自试学及原生追问验证。T4 的真实六章架构课与首题已发布，质量审查和学习前基线通过，准备新增用量（见本机账本） tokens（正文直写 0），累计业务用量（见本机账本）。此前白榆预审题的失败审查保留；新课冷索引发现的 uv 硬链接已按原字节实体化，并增加安装预检及回归，未重置预算。T5 可从第一章开始，当前作答为空。历史 I6 证据保持原字节。详见 本轮验收与继续入口（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-book-closeout/README.md）、课程入口（未随本仓库发布：docs/learning/system-architecture/README.md）、[本机使用手册](../../tools/learning_book/LOCAL_USE.md)及 [课程准备工作单](../../tools/learning_book/PREPARATION.md)。

目标是把已经验收的学习闭环整理成可日常使用的本地系统。完成后，用户能够启动网页，学习外部 Agent 准备并审校的课程，保存进度与追问，通过现有接口交接结果，并查看累计用量和恢复状态。

## 现有基础与问题

I6 已完成一份 361 字验收资料的真实生产、外部审校、网页答题与追问、同实例重启、独立备份恢复和交接消费。最终 67 次调用／原始 tokens 见本机账本，其中实报与估算同账本。预审模板路径实际完成一道题及过渡文，为 2 次（用量见本机账本）。I6 验收（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-book-i6/acceptance.md） · token 审计（证据未公开，无法由本仓库独立复核：docs/design/evidence/learning-book-i6/token-audit.md）

当前影响日常使用的主要问题如下。

| 问题 | 已有依据 | 收尾结果 |
| --- | --- | --- |
| 启动及监控依赖验证脚本 | 实例与控制器保存在 Git 忽略区；控制器仅在 armed 文件存在时进入预算 watch | 提供正式运行入口，网页操作获得持续监督和调用前检查 |
| 闲置与模型工作超时混用 | 现有 Budget.watch 会按账本长期无变化触发 usage_stale | 阅读闲置保持可用，实际在途任务超时得到处理 |
| 中断重生成的状态不准确 | revision 已推进，旧题仍标 READY，新题未保存 | 清楚区分当前生成任务和上次完整内容，重启后可恢复观察 |
| 普通操作需要手工组合探针参数 | I6 的预审题、编辑、监督和备份通过专用脚本串接 | 外部 Agent 和用户使用有文档的普通函数／CLI 与原生网页 |
| 初始生成质量与呈现仍需审校 | 首轮出现编号、处置和来源外扩展错误，页面目标含生成指令，回复字数失准 | 明确准备与审查步骤，修正文案和可确定性处理的显示问题 |

实现基础沿用 [应用模块](../../tools/learning_book/README.md)、[Budget／ProcessStop](../../tools/learning_book/budget.py)、[I4 基线](../../tools/learning_book/BASELINE.md)、[I5 交接](../../tools/learning_book/HANDOFF.md)及 [I6 上游补丁](../../patches/deeptutor/i6/README.md)。

## 任务顺序与依赖

| 任务 | 交付 | 依赖 |
| --- | --- | --- |
| T1 运行与预算监督 | 正式启动／状态／停止入口，覆盖网页与 CLI 的预算检查，累计用量展示 | 现有 I6 环境与预算模块 |
| T2 生成中断与恢复状态 | 持久生成状态、旧内容标识、重启识别、显式恢复操作 | 复用 T1 的任务生命周期与停止信号 |
| T3 安装、备份和恢复 | 可复现的本机安装清单，普通备份／恢复入口，使用手册 | T1、T2 的接口稳定 |
| T4 课程准备与学习入口 | 可复制的外部 Agent 工作单、预审题调用入口、必要文案修订 | T1、T2；复用 I3～I5 |
| T5 用户真实试用 | 一份真实资料的准备、审校、亲自学习、恢复及交接记录 | T1～T4 |

先完成 T1 与 T2，再将其固化到 T3／T4。T5 的资料选择和主观体验需要用户参与，前面的工程工作可以独立完成。

## T1 运行与预算监督

### 实施

1. 将验证控制器中已实测的进程启动、健康检查、身份绑定和停止逻辑整理进普通应用入口。沿用 ProcessStop 对 PID、创建时间、可执行文件和监听归属的核对，明确本次拥有的 API／Web 进程。
2. 服务运行期间持续观察累计账本。网页的 HTTP、WebSocket 和后台任务，以及 CLI 发起的当前受支持文本模型操作，都接入同一份调用前预算检查。覆盖编译、单块重生成、页边追问及其中的子调用。
3. 复用上游公共模型调用入口接入检查，并核对后台工作是否继承正确作用域。监督器失联、账本不可读、计量缺失或额度触线时，拒绝新增模型调用，持久记录实际停止结果。
4. 区分健康但闲置的阅读会话与正在执行的模型任务。账本在阅读期间保持不变属于正常状态；在途任务使用实际开始时间、活动状态和可观察进展判断超时。
5. 提供可读状态，至少包含服务状态、累计实报／估算用量、暂停线／总额、当前模型任务、最近停止原因。启动和重启沿用原账本及预算基线。
6. 优先补齐现有 source／session_id／turn_id 或已有调用上下文的归属。并发时按实际 call_id 关联操作；无法归属的调用保留到全局累计，并明确单操作归因未知。前后账本差值只用于已证明独占的操作窗口。

现有授权记录为累计 1,000,000、800,000 暂停，已记账量（见本机账本）。执行前重读实际账本。暂停线、缺失计量及在途调用可能晚到的情况继续明确记录，本地监督无法承诺供应商硬封顶。本地 embedding 单独记录运行情况，其 token 计量仍按实际可用能力表达。

### 验收

- 从原生网页分别触发一次模拟编译、重生成和追问，三条入口及其子调用均被观察。
- 模拟阈值到达、账本损坏、监督器退出和实际在途超时，确认门禁、停止与持久原因；实际进程停止仅针对受管实例。
- 用可控时钟验证长时间阅读闲置，期间服务正常，账本不变。
- 重启前后累计值相同；两个并发操作的归因不会重复计算同一 call_id。
- 确定性验收使用本地替身和故障注入，真实模型只用于最后必要的连通性与使用验证。

## T2 生成中断与恢复状态

### 实施

1. 先核对上游既有请求、stream 和生成状态标识，在 DeepTutor 的现有存储与元数据中持久记录生成任务。项目证据层继续保存观察和回执。
2. 开始生成时保存目标 book／page／block、操作身份、输入摘要、开始时间及正在生成的状态，同时保留上次完整 payload。
3. 新 payload 与完成状态按一致的提交规则发布。失败、取消、断连和进程退出分别保存实际可知事实，传输结果未知时保留未知状态。
4. 重启后识别失去执行者的任务。页面展示“上次完整内容”和本次中断状态，提供显式继续或重新生成入口。普通状态查询能够直接读回事实。
5. 同一目标的并发生成使用已有写者锁与 revision 冲突规则处理。请求结果未知时，先读回核对，再决定后续操作。
6. 保留既有 progress、submission 和首次基线。内容改变后，I4／I5 继续显示实际漂移与关联限制。

### 验收

- 在请求接收后、生成中、结果提交前和提交后分别终止独立测试进程，重启核对任务与内容。
- 页面能识别“旧内容仍可读，本次生成中断”，并清楚展示操作结果。
- 相同请求核对和重复查询保持结果一致，实际恢复动作具有可追溯身份。
- 修复前的旧数据和缺少新增状态字段的数据仍能读取。
- 回归既有首次答题、旧 submission、基线、历史交接包和未知结果语义。

## T3 安装、备份与恢复

### 实施

- 固化 Windows／Python 3.12／Node 22、SQLite 单 worker 和本机 loopback 的已验证组合。安装清单记录固定源码、补丁顺序、完整 Python 依赖、实际 wheel 和 Web 产物摘要。
- 正常启动使用已构建的生产 Web 资产。重新构建时记录字体等外部构建依赖和获取方式。
- 在配置中显式区分 runtime、项目 state、资料包、发行物和日志。首次初始化使用实际运行账号，并检查目录读写权限。
- 已有实例通过明确的迁移／升级操作接入。新构建保留独立清单和回退依据，历史 I5／I6 证据包保留原字节。
- 封装已验证的停服或一致性快照、复制、逐文件 hash 校验、隔离恢复及读回检查，覆盖 Book、progress、会话、KB、账本和项目 state。
- 编写从安装到停止的本机使用手册，说明查看已有课程、准备资料、学习前审查、导出结果、备份恢复与常见错误处理。

### 验收

- 使用一个新的本机安装／数据目录启动，核对实际安装文件和生产页面。
- 重复启动返回可理解的已运行状态或端口冲突，停止操作准确识别受管进程。
- 使用已有 I6 数据做一次升级／回退兼容核对，记录过程中的文件变化。
- 将备份恢复到独立目录，在原目录不可用的条件下读取相同课程、作答、会话和累计用量，导出包仍能离线验证。
- 运行、只读恢复及查看已有内容的验收新增模型调用为 0。

## T4 课程准备与学习入口

### 实施

1. 整理一份外部 Agent 操作工作单，覆盖资料暂存、用户明确整理意图、来源与版本、学习目标、有限语料包、参考题、审查和结果读取。沿用现有 ingest／approve 流程衔接知识库。
2. 为已验证的预审题路径提供普通函数／CLI 调用示例或薄包装，按原生接口传递 prepared_templates 和显式生成参数，复用 T1 的预算控制和 T2 的操作身份。正常使用不需要读取验证脚本。
3. 短课示例显式限定内容范围、题目数量和题型，使用已核对的有限原文与模板。保留普通生成路径，分别记录两种路径的输入、调用次数、token 和审查结果。
4. 把学习目标改为面向学习者的文案，生成约束放入准备参数。保留原始教学答复，显示程序实计的字数，记录短答要求的实际遵循情况。
5. 核对课件聊天的上下文及工具清单，利用现有配置减少无关工具与重复来源文本。现有用户显式选择继续生效，优化后复验必要工具和来源读取。
6. 将学习前审查、网页学习、结果导出和外部消费的命令与页面动作写成连续操作说明，输出能够定位到已有资料和证据。

### 验收

- 另一位执行者仅依据公开工作单和普通入口，能够完成资料准备与一次预审题生成。
- 无效模板在发模型请求前给出明确错误，原资料包和正常调用保持可用。
- 正文、学习目标、题目及解释对照原文完成审查。学习和结果交接延用既有未知值、覆盖限制及证据引用。
- 给出同一有限资料上的调用次数、输入／输出／缓存及实报／估算用量。I6 的用量（见本机账本） 是单次实测参考，后续差异需要结合实际工作量解释。

## T5 用户真实试用

由用户选择一份实际想学习的资料，外部 Agent 按工作单整理。完成审校后，用户亲自在网页阅读、答一道题、追问一次，关闭再打开继续，随后由外部 Agent 读取交接结果并提交候选。

记录以下结果。

| 观察项 | 记录内容 |
| --- | --- |
| 内容质量 | 来源偏离、错误答案、审校改动及准备者工作量 |
| 学习体验 | 是否容易找到课程、读懂目标、作答、追问及恢复位置 |
| 稳定性 | 实际错误、中断状态、恢复结果及重复提交情况 |
| 用量 | 准备、生成、追问、重试分别消耗多少，是否出现重复探索 |
| 外部消费 | 能否定位原始作答、教学消息及来源，是否正确保留 unknown／partial |

试用中发现的问题按影响范围登记，修复具体阻断后再核对受影响流程。形成一份用户体验与工程验收记录，列清通过、限制和后续改进。

## 工程管理与完成条件

每项任务更新状态、改动文件、实际构建、验证命令、结果和未覆盖项。实现复用现有应用操作及上游能力；课程与可写学习状态继续由 DeepTutor 管理，项目负责输入契约、调用、证据和交接。源码核对、确定性修复与真实模型验证分别记账。

新增测试针对本次实际缺陷，覆盖正常入口、旧数据、重试、中断和并发的一致性。现有回归通过后，仅在新增改动或未解决问题需要时扩大测试。耗费真实模型的验证优先复用有限资料与预审模板，保留每次失败和重试的实际用量。

以下条件全部满足后，将本地日常使用收尾标记完成。

- 正式运行入口覆盖启动、状态、停止、备份和恢复，操作手册可由用户独立执行。
- 网页和 CLI 的受支持模型调用获得持续预算监督，阅读闲置与真实工作超时有准确区分。
- 中断生成状态可读、恢复可追溯，旧内容、作答和历史证据兼容。
- 外部 Agent 依据公开工作单能够交付课程输入并消费学习结果。
- 用户完成一次真实资料试用，具体问题及适用范围有记录。

后续课程类型、资料规模、MCP 包装和知识库可视化的排序，依据真实使用记录确定。
