# 知识准备与学习系统端到端设计复核

> 本文为上游选型与原始研究记录。上游源码副本与研究过程记录未随本仓库发布；引用上游源码时绑定[上游来源清单](upstream-sources.md)的固定提交与文件路径，结论与分析随正文发布。文中状态与结论对应原文写作时点，不代表当前部署或验收完成。

日期：2026-11-11。范围：设计拉通与文档修订，非实施验收、非独立 Reviewer 通过凭据。以[知识准备任务书](knowledge-preparation-plan.md)、现有 learning_book、知识维护规则及 DeepTutor 消费边界为依据。本轮未更改业务代码、正式 raw／wiki、现有课程或运行配置。

## 1. 总体判断

整体方向可行：外部 Agent 做开放式研究和整理；知识准备形成可复用、可核对的内容；DeepTutor 做教学；原始学习记录为下次规划提供依据；正式知识接受沿用维护流程。主要风险在这些环节的连接和语义，尚无依据要求重写 DeepTutor 或再开发通用 Agent。

这套架构包含两个可独立推进的目标：知识质量与学习适切性。二者在课程准备处汇合；正式知识维护可以独立进行，用户学习也不以正式 wiki 先写入为前提。目标、证据、课件和学习记录分别有版本及状态，用引用连接，不压成一个“任务已完成”。

## 2. 贯穿场景

用户白天交给 Agent 三篇文章，晚上说“整理今天的资料，重点学会部署，我大约有四十分钟”。

1. 先前材料仅暂存。此次从相关 wiki 与可用学习记录判断已有背景，向用户简述建议方向、略过内容和未知前置；明确要求可以直接复用，无需逐项再问。
2. 知识路线核对文章与已有结论，发现两篇转载同一来源、第三篇属于新版行为。它们不能变成“三票赞成”；保留共同来源和版本条件。
3. 学习路线形成“能完成最小部署、知道如何核查运行状态”的约定。其他主题留作参考，不把整个检索结果变成课程。
4. 从核验范围抽取适合目标的材料，形成学习投影和覆盖说明。若已有审校讲义，直接复用；需要 DeepTutor 生成时，检查实际输出是否扩展事实或偏离目标。
5. 完成实际课件审校、基线及发布，交给用户在原生网页学习。外部 Agent 不必常驻。
6. 用户说“回顾本课”后，Agent 显式导出所选活动与公开会话，核对包并汇总表现、疑问及证据不足处。当前没有自动触发器，不能说课程完成后一定会后台整理。
7. 学习表现影响下次规划；新事实或错题回到知识核验。知识候选走既有审查与应用；用户明确 approve 后才归档 raw。用户若指定“学完再入库”，保留这次顺序要求。

## 4. 门禁与交互合并

| 检查 | 真正检查什么 | 谁处理失败 |
| --- | --- | --- |
| 学习约定 | 方向、已有基础、范围和量级是否明确，真实认可／委托是否覆盖 | 关键缺口交用户澄清；已有答案直接复用 |
| 知识核验 | 关键结论、条件、来源及冲突是否足以支撑本次用途 | 准备者补证／修订，证据不足则明确排除或待定 |
| 课件审校 | 实际正文／题目是否忠实、覆盖目标且不过量 | 准备者修订；实质扩大范围才返回用户 |
| 内容基线 | 实际发布内容、资源与来源映射是否稳定可追溯 | 项目采集／核对；不得把基线一致当语义正确 |
| 正式维护 | 候选、依赖、独立审查及具体操作授权是否有效 | 既有维护 Runtime／Executor；归档单独消费用户 approve |

前四项不要求用户各点一次“通过”。能后台完成的检查后台完成；方向选择和归档批准保留真实用户意思，必要的例外请求合并展示其具体差异。模型判定、字段合法和原生提案按钮都不能代替这两个业务意思。

用户可中断、暂缓、不成课、只读参考或只导出未完成记录；这些是正常出口，不构造失败循环。约定、事实、课件和学习记录各自变化时，只重做受影响检查。

## 5. 工程规模与实施顺序

继续采用本机普通模块、现有维护能力、既有 learning_book 和一个 DeepTutor 服务。新增范围是应用操作、最小关联封装及工作单，不加消息总线、动态插件平台、常驻规划 Agent 或全量用户画像服务。

K0 优先固定三个实际接口问题：

1. 什么输入能形成有依据的背景观察和有效学习约定，什么变化使其需重确认？
2. 知识包、核验结果、投影及目标覆盖怎样绑定，如何避免复制事实与循环依赖？
3. 发布前检查、显式回顾、纠错与正式维护分别通过哪个现有入口，缺能力时停在哪里？

随后按 K1–K3 完成临时库中的最小实际能力，再由 K4 分列本地、真实语义、外发及正式应用证据。验收扩为 A01–A33，其中 A28–A33 直接覆盖本次跨环节问题。验收项数量不是测试通过数量，当前均为待实施要求。

## 6. 当前可以怎样推进

本轮设计已足以进入 K0 接口细化与可执行协议验证；不是整条知识链的实施放行或最终通过。K0 完成后应独立审查字段、依赖和失败路径，再推进依赖它的业务实现。用户此前选择先完成方案与任务书，本轮遵守这一范围。

仍未解决且不能靠本次文档宣称完成的事项：真实语义核验质量、目标对齐与课时估计效果、目标宿主的实际接入、自动门禁、学习结果回顾触发界面，以及完整来源治理。当前六章课程仍可使用，个人试学继续提供这些产品假设的实际反馈。
