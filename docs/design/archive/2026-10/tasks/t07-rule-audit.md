# T07 规则申诉与审查协议

## 状态与目标

已验收；阶段 P2。仅对有证据的规则争议提出裁决建议，分离规则缺陷与检查器缺陷。 实际产物与验收记录见任务总表；执行中任务不视为已完成。

## 依赖与最小上下文

- 先读工作区 `AGENTS.md` 与 [agent-development-tasks](../development-tasks.md#%E7%8B%AC%E7%AB%8B%E4%B8%8A%E4%B8%8B%E6%96%87%E4%B8%8E%E4%BA%A4%E4%BB%98%E8%A7%84%E5%88%99)，规则以 AGENTS 为准。
- 前置任务：[T04](t04-p1-pilot.md)，均须验收并交付接口摘要。
- 必读：契约、规则 ID 映射、总方案第六、九节；ADR-0001 争议。
- 只加载本任务必要章节、发布的契约及依赖交付摘要，无需继承全部聊天。接口缺口提交协调者，不自行修改公共契约。

## 修改范围与产物

允许修改：`tools/wiki_runtime/rule_audit/`、`tools/tests/test_rule_audit.py`。这些是拟定路径，当前可能尚不存在。共享初始化、注册及导航由协调者处理；任何范围移交必须先记录。

交付：申诉请求校验、四类裁决响应、中文提示模板、去重键与规则修订提案模板。

不做：不自动修检查器、不修改 AGENTS、不授予当前任务豁免、不重置全局预算。

## 验收条件

1. 缺规则 ID、失败轨迹或最小反例的空泛申诉被拒；相同证据不重复唤醒。
2. 四类结果覆盖规则有效、验证器有误、规则需变更、证据不足；均不直接应用规则或内容。
3. AGENTS 修改必须转用户决定；用户未回复不算批准；规则/验证器变更要求重验。
4. 用 ADR 分歧作模拟审查，不改旧 ADR 来制造已解决结论。
5. 测试只使用临时库或专属夹具，不改真实 raw 正文、业务状态、AGENTS 或 ADR，不覆盖已有未提交改动。

验收命令：`-B -m unittest discover -s tools/tests -p test_rule_audit.py -v`。 使用 [agent-development-tasks](../development-tasks.md#%E9%AA%8C%E6%94%B6%E4%B8%8E%E7%8A%B6%E6%80%81) 中的可用 Python 解释器；新增命令必须在交付时给出完整可复现形式。

## 交付与停止条件

返回任务 ID、契约版本和摘要、修改文件、验证命令与结果、剩余风险和接口建议；完整日志留在专属运行记录。依赖缺失、跨文件所有权冲突、契约变更或需要真实环境授权时，停止相应步骤并报告；可继续不依赖它的本任务工作。开发者不得自行将任务标为最终已验收。
